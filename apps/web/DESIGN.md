# zm-baton 웹 화면 디자인 기준

**목적**: zm-baton 웹 화면을 만들고 고치고 검토할 때 따를 기준을 한곳에 둔다. 화면이 AI의 기본값처럼 보이지 않고, 1인 조직에서 팀·조직으로 넓혀도 구조가 그대로이게 한다.
**읽는 사람**: 웹 화면을 만드는 사람과 AI 에이전트, 화면 PR을 검토하는 세션.
**소유자·마지막 검토**: hanumoka · 2026-10-13
**정본 관계**: 값의 정본은 [`src/tokens.css`](src/tokens.css)다. 이 문서는 그 값을 어떻게 쓰는지 정한다. 화면의 정보 구조와 동작은 설계 허브의 화면 초안이 정본이다(저장소 `AGENTS.md` 2절).

## 디자인 판단

IT 조직과 1인 개발자가 매일 쓰는 업무 도구다. 지금 무엇을 움직여야 하는지 빨리 알 수 있어야 한다. 차분하고 정보가 촘촘하며, 키보드로 일할 수 있고, 한국어가 먼저다.

## 정한 것 넷 (2026-10-13 소유자)

1. **화면 부품의 기반**: 손으로 쓴 CSS와 토큰(CSS 변수)을 쓴다. 대화상자·드롭다운 메뉴·콤보박스·툴팁처럼 키보드·포커스 처리가 어려운 부품에만 Radix Primitives를 쓰고, 그 부품이 처음 필요한 PR에서 이유와 함께 더한다.
2. **아이콘**: 16px 격자, 선 굵기 1.5px, 둥근 선 끝으로 통일한 자체 SVG만 쓴다(`src/icons/`, 필요한 것만). 30개를 넘으면 아이콘 세트 하나로 옮기는 것을 다시 본다.
3. **방향**: 명령 중심 두 칸에 왼쪽 사이드바를 붙인 배치다. 아래 「화면 배치」에 있다.
4. **서체**: 본문은 Pretendard, 번호·경로·키는 고정폭(`--font-mono`)이다. Pretendard는 고정한 판의 CDN에서 받고, 받지 못하면 시스템 한국어 서체로 넘어간다.

## 설계 원칙 여섯

각 원칙은 옆의 방법으로 확인한다.

| 원칙 | 뜻 | 확인 방법 |
|---|---|---|
| 확장성 | 항목·사람·작업 수가 늘어도 화면 구조가 바뀌지 않는다 | 「1인 조직」과 「팀 조직(사람 여럿, 작업 수백 건)」 두 장면을 함께 본다 |
| 유연성 | 조직이 바꾸는 값(단계 이름과 건너뛰기, 팀·프로젝트 이름, 글 길이)이 바뀌어도 화면 코드를 고치지 않는다 | 긴 제목, 0건, 많은 건수, 긴 이름을 넣어 깨지지 않는지 본다 |
| 가시성 | 지금 위치, 멈춘 것, 다음 동작이 첫 화면 높이 안에 보인다 | 1440px·390px 첫 화면 스크린샷에서 셋을 짚는다 |
| 가독성 | 본문 14~16px, 줄 길이 80자 이하, 대비 4.5:1 이상, 한국어는 낱말 사이에서만 줄을 바꾼다 | 아래 「글자」 |
| 사용성 | 주 작업을 키보드만으로 끝낸다. 누를 대상은 32px 이상(터치 폭 44px) | 키보드만으로 주 동작을 끝까지 해 본다 |
| 직관성 | 아이콘에 글자를 붙이고, 같은 것은 같은 이름·같은 자리에 둔다. 단추 이름이 결과를 말한다 | 스크린샷만 새 세션에 보여 주고 주 동작이 무엇으로 보이는지 묻는다 |

## 화면 배치

1. **왼쪽 사이드바**: 콘텐츠보다 한 단계 낮은 중립색 바탕(`--c-side`), 강조색 없음. 현재 화면은 밝은 바탕과 굵은 글자로만 표시한다. 맨 위에 조직·팀 전환, 그 아래 「나 / 팀 / AI / 저장한 보기 / 설정」 묶음으로 항목이 늘어난다. 1인 조직은 아이콘만 보이게 접는다(`--w-rail`), 팀은 펼친다(`--w-side`).
2. **찾기·명령 입력줄**: 콘텐츠 맨 위. `Ctrl+K`로 연다. 그 아래 한 줄에 거르기 칩(프로젝트·단계·막힘, 팀이면 담당자·팀). 찾을 것이 있는 화면에서는 입력줄이 그 화면의 찾기를 겸하고, 화면 이동은 `>`로 시작하거나 화면 이름을 그대로 쓴다.
3. **목록과 상세**: 왼쪽 목록(`--w-list`)과 오른쪽 상세를 늘 함께 둔다. 목록 머리에 보기 전환 자리(목록·보드·타임라인, 아직 없는 보기는 잠그고 이유를 보인다).
4. **목록 묶기**: 「지금 누가 들고 있나」로 묶는다. 1인 조직은 기다림 / AI 세션 / 사람 / 끝남, 팀은 기다림 / AI 세션 / 나 / 팀원 이름별 / 끝남. 결정처럼 들고 있는 쪽이 없는 기록은 상태로 묶는다(정할 것 / 지금 유효 / 지난 것). 비어 있는 묶음도 보이고 빈 상태 문구를 단다.
5. **단계 기호**: 단계가 나아갈수록 원 안이 아래부터 찬다(16px에서 채움 높이 2.75·5.5·8.25·11px). 막히면 같은 높이로 찬 네모로 바뀐다. 기호 옆에는 늘 단계 이름을 쓴다. 결정의 상태는 마름모로 보여 작업 단계와 섞이지 않는다. 제안은 가운데 점, 채택은 채움, 대체됨은 가로줄, 기각은 점선이고 옆에 늘 상태 이름을 쓴다.
6. **좁은 폭(390px)**: 사이드바는 아래 탭 줄(4~5칸)이 되고, 상세는 목록을 덮는 시트로 연다. 가로 스크롤이 없다.

## 색

- 중립은 흑연 회색 세 층이다: 사이드바(`--c-side`) < 목록·도구줄(`--c-canvas`) < 상세·입력(`--c-paper`).
- 강조색(`--c-accent`, 석유청록)은 주 동작, 현재 선택, 포커스에만 쓴다.
- 상태색은 강조색과 따로다: 막힘 `--c-block`, 기한 지남 `--c-warn`. 상태는 색만으로 전달하지 않고 모양과 글자를 함께 쓴다.

## 글자

- 크기는 `--fs-xs`(12) · `--fs-sm`(13) · `--fs-md`(14, 본문) · `--fs-lg`(16) · `--fs-xl`(18) · `--fs-2xl`(21)만 쓴다.
- 한국어는 `word-break: keep-all`(기본값으로 걸려 있다). 숫자 열은 `.num`(`tabular-nums`).
- 대문자 라벨, 한 낱말만 다른 색·이탤릭으로 강조하는 제목을 쓰지 않는다.

## 상태와 문구

- 부품마다 일곱 상태: 기본·hover·focus·active·disabled·loading·error. 누를 수 없는 단추는 이유를 보인다.
- 빈 화면 세 유형: 아직 안 씀(무엇인지와 만드는 동작 하나), 지금 비어 있음(왜 비었는지), 오류(무엇이 문제이고 어떻게 고치는지).
- 불러오는 중은 실제 행 모양과 같은 자리 표시로 보인다. 가운데 회전 표시는 쓰지 않는다.
- 움직임은 상태가 바뀔 때만 쓴다(`--dur-fast`, `transform`·`opacity`). `prefers-reduced-motion`이면 움직임을 끈다(`src/base.css`).
- 화면 글은 쉬운 한국어로, 단추는 일어나는 일을 말한다. 오류는 사과하지 않는다.

## 하지 않는 것

- 지표 카드 줄이나 같은 크기 카드 그리드로 화면 짜기, 카드 안의 카드
- 모든 덩어리에 같은 테두리·모서리·그림자
- 그라디언트, 글로우, 장식용 유리 효과
- 1px보다 굵은 색 왼쪽 테두리로 강조하기
- 이모지나 유니코드 기호를 아이콘 대신 쓰기
- 제목 위 대문자 머리표, 「A · B · C」식 가운뎃점 문자열, 단추 끝의 「→」
- 페이지를 열 때의 등장 애니메이션, 모든 행의 hover 연출
- 화면 머리의 긴 설명 문단

## 기계로 막는 것

`src/designRules.test.ts`가 웹 시험(`npm test`)에서 확인한다. `src` 아래 하위 폴더(`icons/`, `shell/`, `ui/`, `kit/`, `work/`, `decisions/`, `inbox/`)의 파일도 본다.

1. 색 값은 `tokens.css`에만 있다.
2. px 글자 크기는 `tokens.css`에만 있다.
3. 그라디언트가 없다.
4. 1px보다 굵은 왼쪽 테두리가 없다.
5. 대문자 변환과 `transition: all`이 없다.
6. 화면 코드에 이모지가 없다.

간격·모서리 값이 토큰인지는 아직 기계로 보지 않는다. 검토에서 본다.

## 검토

화면 PR은 1440px·390px 스크린샷(바꾸기 전과 후)을 붙인다. 작성 세션이 아닌 세션이 위 원칙 여섯과 「하지 않는 것」으로 검토한다.

## 지은 것과 아직 짓지 않은 것

- **지었다**: 사이드바(`src/shell/`), 찾기·명령 입력줄, 좁은 폭의 아래 탭 줄과 시트, 아이콘(`src/icons/`), 단계 기호(`StageGlyph`), 결정 상태 기호(`DecisionMark`), 공용 부품(`src/ui/`, 기록의 Markdown을 그리는 `Prose` 포함), 디자인 키트 화면(`#kit`, 사이드바에는 없고 주소로만 연다). 새 토큰과 부품은 키트 화면에 먼저 보인다. 키트는 `tokens.css`를 직접 읽으므로 토큰을 더하면 견본이 저절로 생긴다.
- **목록과 상세 화면의 공용 부품**(`src/ui/`): 작업과 결정 화면이 같은 것을 쓴다. 배치와 행·상세 머리 모양(`panes.css`), 목록 머리·키 안내·행의 키보드 이동(`ListPane`, `rowKeys`), 거르기 칩(`Chip`), 「읽기만 한다」 줄(`ReadOnly`), 주소에 남기기(`useAddress`), 시트의 포커스 되돌리기(`useSheet`), 넓은 폭에서 첫 행 보이기(`useShownRow`)다. 나를 기다리는 것 화면부터는 넓은 폭의 상세 칸과 좁은 폭의 시트를 한 부품(`DetailPane`)으로 두고, 처리하면 목록에서 빠지는 항목은 빠진 자리의 다음 항목을 고른다(`useNextWhenGone`). 다음 화면도 이것으로 짓는다.
- **작업 화면**(`src/work/`): 목록(`--w-list`, 1180px 이하 `--w-list-mid`)과 상세를 늘 함께 두고, 목록은 머리줄 아래에 붙어 있고 페이지는 상세를 민다. 목록은 「지금 누가 들고 있나」(기다림 / AI 세션 / 사람 / 끝남)로 묶는다. 거르기 칩(프로젝트·단계·막힘·완료·취소 보기)과 검토 단계 설정은 입력줄 아래 `#screen-chips`에 있다. 작업 화면에서는 입력줄이 제목·번호·다음 행동 찾기를 겸하고, 화면 이동은 `>`로 시작하거나 화면 이름을 그대로 쓴다. 거르기와 고른 작업은 주소(`#work?stage=…&item=…`)에 남는다. 빈 상태 세 유형(아직 가져온 작업 없음·거른 결과 없음·읽기 실패)과 390px 시트가 있다. Git 정본 작업은 상세 머리에 「읽기만 한다」를 보이고 바꾸는 단추를 잠근 채 서버가 준 이유를 단추 옆에 보인다.
- **접힌 사이드바의 툴팁**: 접힌 사이드바의 항목은 머리줄(입력줄과 칩 줄) 아래에서 시작한다. 셸이 머리줄 높이를 `--h-tool`로 재서 쓰므로, 항목 이름 툴팁이 칩을 가리지 않는다.
- **결정 화면**(`src/decisions/`): 작업 화면과 같은 문법이다. 목록과 상세를 늘 함께 두고, 목록은 상태로 묶는다(정할 것 / 지금 유효 / 지난 것). 지난 것(대체됨·기각)은 머리와 건수만 보이게 접어 두고, 그 줄의 단추나 「지난 것 보기」 칩으로 편다. 묶음 안은 결정일 최신순이다. 행 첫 줄은 상태 기호와 이름·번호·질문, 둘째 줄은 결정일·프로젝트(1180px 이하에서 뺌)·고른 안의 첫 문단이다. 거르기 칩은 프로젝트·상태(건수 포함)·지난 것 보기이고, 입력줄이 번호·질문·결정 찾기를 겸한다. 거르기와 고른 결정은 주소(`#decisions?project=…&status=…&past=1&item=…`)에 남는다. 상세 머리에 「읽기만 한다」와 정본 Git 파일을 한 줄로 보이고, 고른 안 → 대체 관계 → 나머지 절 순서로 읽는다. 대체 관계를 누르면 그 결정으로 가고(브라우저 뒤로 가기로 돌아온다) 목록에서도 그 행이 보이게 한다. 서버에 결정과 작업을 잇는 기록이 없어서, 작업의 제목·번호·다음 행동에 그 결정 번호가 나오면 「이 번호를 적은 작업」으로 옆 칸에 보이고 작업 화면으로 잇는다. 빈 상태 세 유형(아직 가져온 결정 없음·거른 결과 없음·읽기 실패)과 390px 시트가 있다.
- **나를 기다리는 것 화면**(`src/inbox/`, 첫 화면): 작업·결정 화면과 같은 문법이다. 목록과 상세를 늘 함께 두고 화면 머리의 설명 문단은 없다. 목록은 계약의 다섯 묶음(권한 요청 / 멈춘 AI의 질문 / 내 작업과 겹친 충돌 / 위험 목록 검토 / 표본 검토와 나머지 알림)을 그 순서대로 두고, 묶음 안은 오래 기다린 것부터다. 서버가 아직 만들지 않는 묶음(1·4·5)은 빈 상자 대신 머리 한 줄에 「아직 중계하지 않는다」·「서버가 아직 만들지 않는다」를 보인다. 행 첫 줄은 종류(아이콘과 글자)와 요약(충돌은 그 파일, 기다리는 세션은 실행기가 보낸 문구나 그 세션의 하는 일), 둘째 줄은 기다린 시간·바로 알림/묶어 알림·반복·관련 세션의 짧은 번호와 브랜치다. 상세는 무엇이 기다리는지, 겹친 파일(고정폭), 왜 나를 기다리는지, 할 수 있는 일, 옆 칸의 관련 세션(누르면 세션 현황에서 연다) 순서다. 충돌은 상세에서 확인 / 충돌 아님(이유를 적어야 보낸다) / 해결로 판정하고, 판정하면 목록을 바로 다시 읽고 다음 항목을 연다. 기다리는 세션은 「그 세션의 터미널에서 이어 입력하면 저절로 닫힌다」를 행동 자리에 보인다. 고른 항목은 주소(`#inbox?item=…`)에 남는다. 빈 상태는 기다리는 것 없음(무엇이 오면 쌓이는지)과 읽기 실패 둘이고, 390px에서는 목록만 보이고 행을 누르면 시트로 연다. 충돌 표시는 겹친 두 원(`conflict` 아이콘)이다.
- **아직**: 세션 현황의 안 배치를 다시 짓는다. 결정 목록은 고른 행을 목록 안에서 보이게 옮기지만, 작업 목록은 아직 그렇게 하지 않는다. 작업 목록 머리의 보기 전환(목록·보드·타임라인) 자리는 아직 없다. 팀 조직의 묶기(나 / 팀원 이름별)와 담당자·팀 칩은 서버에 팀과 담당자가 생길 때 넣는다. 사람 이름은 서버에 없어 책임자를 사용자 ID(`usr_owner`)로 보인다. 작업 수백 건을 위한 가상 스크롤은 없다(서버가 한 번에 500건까지 준다).
