# zm-baton 웹 화면 디자인 기준

**목적**: zm-baton 웹 화면을 만들고 고치고 검토할 때 따를 기준을 한곳에 둔다. 화면이 AI의 기본값처럼 보이지 않고, 1인 조직에서 팀·조직으로 넓혀도 구조가 그대로이게 한다.
**읽는 사람**: 웹 화면을 만드는 사람과 AI 에이전트, 화면 PR을 검토하는 세션.
**소유자·마지막 검토**: hanumoka · 2026-10-18
**정본 관계**: 값의 정본은 [`src/tokens.css`](src/tokens.css)다. 이 문서는 그 값을 어떻게 쓰는지 정한다. 화면의 정보 구조와 동작은 설계 허브의 화면 초안이 정본이다(저장소 `AGENTS.md` 2절).

## 디자인 판단

IT 조직과 1인 개발자가 매일 쓰는 업무 도구다. 지금 무엇을 움직여야 하는지 빨리 알 수 있어야 한다. 차분하고 정보가 촘촘하며, 키보드로 일할 수 있고, 한국어가 먼저다.

## 정한 것 넷 (2026-10-13 소유자)

1. **화면 부품의 기반**: 손으로 쓴 CSS와 토큰(CSS 변수)을 쓴다. 대화상자·드롭다운 메뉴·콤보박스·툴팁처럼 키보드·포커스 처리가 어려운 부품에만 Radix Primitives를 쓰고, 그 부품이 처음 필요한 PR에서 이유와 함께 더한다.
2. **아이콘**: 16px 격자, 선 굵기 1.5px, 둥근 선 끝으로 통일한 자체 SVG만 쓴다(`src/icons/`, 필요한 것만). 30개를 넘으면 아이콘 세트 하나로 옮기는 것을 다시 본다.
3. **방향**: 명령 중심 두 칸에 왼쪽 사이드바를 붙인 배치다. 아래 「화면 배치」에 있다.
4. **서체**: 본문은 Pretendard, 번호·경로·키는 고정폭(`--font-mono`)이다. Pretendard는 고정한 판의 CDN에서 받고, 받지 못하면 시스템 한국어 서체로 넘어간다.

## 설계 원칙 여섯

각 원칙은 옆의 방법으로 확인한다.

| 원칙 | 뜻 | 확인 방법 |
|---|---|---|
| 확장성 | 항목·사람·작업 수가 늘어도 화면 구조가 바뀌지 않는다 | 「1인 조직」과 「팀 조직(사람 여럿, 작업 수백 건)」 두 장면을 함께 본다 |
| 유연성 | 조직이 바꾸는 값(단계 이름과 건너뛰기, 팀·프로젝트 이름, 글 길이)이 바뀌어도 화면 코드를 고치지 않는다 | 긴 제목, 0건, 많은 건수, 긴 이름을 넣어 깨지지 않는지 본다 |
| 가시성 | 지금 위치, 멈춘 것, 다음 동작이 첫 화면 높이 안에 보인다 | 1440px·390px 첫 화면 스크린샷에서 셋을 짚는다 |
| 가독성 | 본문 14~16px, 줄 길이 80자 이하, 대비 4.5:1 이상, 한국어는 낱말 사이에서만 줄을 바꾼다 | 아래 「글자」 |
| 사용성 | 주 작업을 키보드만으로 끝낸다. 누를 대상은 32px 이상(터치 폭 44px) | 키보드만으로 주 동작을 끝까지 해 본다 |
| 직관성 | 아이콘에 글자를 붙이고, 같은 것은 같은 이름·같은 자리에 둔다. 단추 이름이 결과를 말한다 | 스크린샷만 새 세션에 보여 주고 주 동작이 무엇으로 보이는지 묻는다 |

## 화면 배치

1. **왼쪽 사이드바**: 콘텐츠보다 한 단계 낮은 중립색 바탕(`--c-side`), 강조색 없음. 현재 화면은 밝은 바탕과 굵은 글자로만 표시한다. 맨 위에 조직·팀 전환, 그 아래 「나 / 팀 / AI / 저장한 보기 / 설정」 묶음으로 항목이 늘어난다. 설정 자리는 사이드바 아래(`FOOT_ITEMS`)이고, 「나」·「조직」·「AI 계정」·「감사 기록」이 그 순서로 있다. 설정 화면이 생기면 「조직」·「AI 계정」·「감사 기록」은 그 안의 부분이 된다. 1인 조직은 아이콘만 보이게 접는다(`--w-rail`), 팀은 펼친다(`--w-side`).
2. **찾기·명령 입력줄**: 콘텐츠 맨 위. `Ctrl+K`로 연다. 그 아래 한 줄에 거르기 칩(프로젝트·단계·막힘, 팀이면 담당자·팀). 찾을 것이 있는 화면에서는 입력줄이 그 화면의 찾기를 겸하고, 화면 이동은 `>`로 시작하거나 화면 이름을 그대로 쓴다.
3. **목록과 상세**: 왼쪽 목록(`--w-list`)과 오른쪽 상세를 늘 함께 둔다. 목록 머리에 보기 전환 자리(목록·보드·타임라인, 아직 없는 보기는 잠그고 이유를 보인다).
4. **목록 묶기**: 「지금 누가 들고 있나」로 묶는다. 1인 조직은 기다림 / AI 세션 / 사람 / 끝남, 팀은 기다림 / AI 세션 / 나 / 팀원 이름별 / 끝남. 결정처럼 들고 있는 쪽이 없는 기록은 상태로 묶는다(정할 것 / 지금 유효 / 지난 것). 비어 있는 묶음도 보이고 빈 상태 문구를 단다.
5. **단계 기호**: 단계가 나아갈수록 원 안이 아래부터 찬다(16px에서 채움 높이 2.75·5.5·8.25·11px). 막히면 같은 높이로 찬 네모로 바뀐다. 기호 옆에는 늘 단계 이름을 쓴다. 결정의 상태는 마름모로 보여 작업 단계와 섞이지 않는다. 제안은 가운데 점, 채택은 채움, 대체됨은 가로줄, 기각은 점선이고 옆에 늘 상태 이름을 쓴다.
6. **좁은 폭(390px)**: 사이드바는 아래 탭 줄(4~5칸)이 되고, 상세는 목록을 덮는 시트로 연다. 가로 스크롤이 없다.

## 색

- 중립은 흑연 회색 세 층이다: 사이드바(`--c-side`) < 목록·도구줄(`--c-canvas`) < 상세·입력(`--c-paper`).
- 강조색(`--c-accent`, 석유청록)은 주 동작, 현재 선택, 포커스에만 쓴다.
- 상태색은 강조색과 따로다: 막힘 `--c-block`, 기한 지남 `--c-warn`. 상태는 색만으로 전달하지 않고 모양과 글자를 함께 쓴다.

## 글자

- 크기는 `--fs-xs`(12) · `--fs-sm`(13) · `--fs-md`(14, 본문) · `--fs-lg`(16) · `--fs-xl`(18) · `--fs-2xl`(21)만 쓴다.
- 한국어는 `word-break: keep-all`(기본값으로 걸려 있다). 숫자 열은 `.num`(`tabular-nums`).
- 대문자 라벨, 한 낱말만 다른 색·이탤릭으로 강조하는 제목을 쓰지 않는다.

## 상태와 문구

- 부품마다 일곱 상태: 기본·hover·focus·active·disabled·loading·error. 누를 수 없는 단추는 이유를 보인다.
- 빈 화면 세 유형: 아직 안 씀(무엇인지와 만드는 동작 하나), 지금 비어 있음(왜 비었는지), 오류(무엇이 문제이고 어떻게 고치는지).
- 불러오는 중은 실제 행 모양과 같은 자리 표시로 보인다. 가운데 회전 표시는 쓰지 않는다.
- 움직임은 상태가 바뀔 때만 쓴다(`--dur-fast`, `transform`·`opacity`). `prefers-reduced-motion`이면 움직임을 끈다(`src/base.css`).
- 화면 글은 쉬운 한국어로, 단추는 일어나는 일을 말한다. 오류는 사과하지 않는다.

## 하지 않는 것

- 지표 카드 줄이나 같은 크기 카드 그리드로 화면 짜기, 카드 안의 카드
- 모든 덩어리에 같은 테두리·모서리·그림자
- 그라디언트, 글로우, 장식용 유리 효과
- 1px보다 굵은 색 왼쪽 테두리로 강조하기
- 이모지나 유니코드 기호를 아이콘 대신 쓰기
- 제목 위 대문자 머리표, 「A · B · C」식 가운뎃점 문자열, 단추 끝의 「→」
- 페이지를 열 때의 등장 애니메이션, 모든 행의 hover 연출
- 화면 머리의 긴 설명 문단

## 기계로 막는 것

`src/designRules.test.ts`가 웹 시험(`npm test`)에서 확인한다. `src` 아래 하위 폴더(`icons/`, `shell/`, `ui/`, `kit/`, `work/`, `decisions/`, `documents/`, `inbox/`, `sessions/`, `review/`, `question/`, `accounts/`, `org/`, `me/`, `audit/`, `auth/`)의 파일도 본다.

1. 색 값은 `tokens.css`에만 있다.
2. px 글자 크기는 `tokens.css`에만 있다.
3. 그라디언트가 없다.
4. 1px보다 굵은 왼쪽 테두리가 없다.
5. 대문자 변환과 `transition: all`이 없다.
6. 화면 코드에 이모지가 없다.

간격·모서리 값이 토큰인지는 아직 기계로 보지 않는다. 검토에서 본다.

## 검토

화면 PR은 1440px·390px 스크린샷(바꾸기 전과 후)을 붙인다. 작성 세션이 아닌 세션이 위 원칙 여섯과 「하지 않는 것」으로 검토한다.

## 지은 것과 아직 짓지 않은 것

- **서버 초기 설정**(`src/server/ServerSetup.tsx`): 인증을 마친 서버 관리자가 이름을 확인하는 한 칸 양식이다. 기존 조직·관리자 이름을 불러와 업그레이드 때 빈칸으로 덮어쓰지 않으며, 필요한 이름만 수정한다. 불러오는 중은 행 자리 표시, 실패는 이유와 「설정 다시 읽기」를 보인다. 주 동작은 「조직 설정 마치기」이고 로그아웃은 보조 동작이다. 초기화 충돌·권한 변경 응답은 로그인 상태를 다시 읽어 현재 화면으로 이동한다. 기존 A 배치를 국소 보완했다. 1440px·390px, 긴 이름, 키보드 완료·재시도는 합성 응답 브라우저 시험으로 확인한다. 실제 서버 통합 증거와는 구별한다.
- **지었다**: 사이드바(`src/shell/`), 찾기·명령 입력줄, 좁은 폭의 아래 탭 줄과 시트, 아이콘(`src/icons/`), 단계 기호(`StageGlyph`), 결정 상태 기호(`DecisionMark`), 공용 부품(`src/ui/`, 기록의 Markdown을 그리는 `Prose` 포함), 디자인 키트 화면(`#kit`, 사이드바에는 없고 주소로만 연다). 새 토큰과 부품은 키트 화면에 먼저 보인다. 키트는 `tokens.css`를 직접 읽으므로 토큰을 더하면 견본이 저절로 생긴다.
- **목록과 상세 화면의 공용 부품**(`src/ui/`): 작업과 결정 화면이 같은 것을 쓴다. 배치와 행·상세 머리 모양(`panes.css`), 목록 머리·키 안내·행의 키보드 이동(`ListPane`, `rowKeys`), 거르기 칩(`Chip`), 「읽기만 한다」 줄(`ReadOnly`), 주소에 남기기(`useAddress`), 시트의 주소 복원과 포커스 되돌리기(`useSheet`), 넓은 폭에서 첫 행 보이기(`useShownRow`)다. `useAddress`의 `navigation`은 외부 주소 이동과 명시적인 주소 점프 때만 바뀐다. `useSheet`는 이 값과 선택 번호로 직접 링크·새로고침·뒤/앞 이동의 상세를 열고, 목록의 방향키·첫 행 자동 선택·자동 조회에 따른 선택 변경으로는 닫힌 시트를 열지 않는다. 탭이나 Enter는 `show()`로 연다. 나를 기다리는 것 화면부터는 넓은 폭의 상세 칸과 좁은 폭의 시트를 한 부품(`DetailPane`)으로 두고, 처리하면 목록에서 빠지는 항목은 빠진 자리의 다음 항목을 고른다(`useNextWhenGone`). 좁은 칸의 긴 저장소 경로는 `/` 뒤에서 먼저 꺾는다(`Path`). 다음 화면도 이것으로 짓는다.
- **작업 화면**(`src/work/`): 목록(`--w-list`, 1180px 이하 `--w-list-mid`)과 상세를 늘 함께 두고, 목록은 머리줄 아래에 붙어 있고 페이지는 상세를 민다. 목록은 「지금 누가 들고 있나」(기다림 / AI 세션 / 사람 / 끝남)로 묶는다. 거르기 칩(프로젝트·단계·막힘·완료·취소 보기)과 검토 단계 설정은 입력줄 아래 `#screen-chips`에 있다. 작업 화면에서는 입력줄이 제목·번호·다음 행동 찾기를 겸하고, 화면 이동은 `>`로 시작하거나 화면 이름을 그대로 쓴다. 거르기와 고른 작업은 주소(`#work?stage=…&item=…`)에 남는다. 빈 상태 세 유형(아직 가져온 작업 없음·거른 결과 없음·읽기 실패)과 390px 시트가 있다. Git 정본 작업은 상세 머리에 「읽기만 한다」를 보이고 바꾸는 단추를 잠근 채 서버가 준 이유를 단추 옆에 보인다. 상세의 「다음 단계」 아래에 「AI에게 맡기기」(맡길 수 없으면 잠그고 서버가 준 이유를 옆에 보인다)와 「실행 기록」(실행마다 보고 상태, 진행 중이면 최근 활동, 실행 브랜치와 바뀐 파일, 끝나면 zm-baton이 합치지 않는다는 안내)이 있다(`work/Handoff.tsx`). 진행 중인 실행에는 「실행 취소」(한 번 더 확인)와 「실행 중인 AI에게 지시」가 늘 보이고, 할 수 없으면 잠근 채 서버가 준 이유를 옆에 보인다. 보낸 지시는 전달 상태와 함께, 연결이 끊긴 실행·준비 검사에서 멈춘 실행은 경고 띠로 보인다(`work/RunRow.tsx`). 맡기기 단추는 서버가 정한 대로 「이어서 맡기기」·「돌려보내고 이어서 맡기기」가 된다.
- **접힌 사이드바의 툴팁**: 접힌 사이드바의 항목은 머리줄(입력줄과 칩 줄) 아래에서 시작한다. 셸이 머리줄 높이를 `--h-tool`로 재서 쓰므로, 항목 이름 툴팁이 칩을 가리지 않는다.
- **결정 화면**(`src/decisions/`): 작업 화면과 같은 문법이다. 목록과 상세를 늘 함께 두고, 목록은 상태로 묶는다(정할 것 / 지금 유효 / 지난 것). 지난 것(대체됨·기각)은 머리와 건수만 보이게 접어 두고, 그 줄의 단추나 「지난 것 보기」 칩으로 편다. 묶음 안은 결정일 최신순이다. 행 첫 줄은 상태 기호와 이름·번호·질문, 둘째 줄은 결정일·프로젝트(1180px 이하에서 뺌)·고른 안의 첫 문단이다. 거르기 칩은 프로젝트·상태(건수 포함)·지난 것 보기이고, 입력줄이 번호·질문·결정 찾기를 겸한다. 거르기와 고른 결정은 주소(`#decisions?project=…&status=…&past=1&item=…`)에 남는다. 행의 번호는 가져온 결정이 `DEC-`, 여기서 만든 결정이 `DCS-`이고, 여기서 만든 제안은 결정일 자리에 「정하기 전」을 쓴다. 가져온 결정은 상세 머리에 「읽기만 한다」와 정본 Git 파일을 한 줄로 보이고, 고른 안 → 대체 관계 → 나머지 절 순서로 읽는다. 작업의 제목·번호·다음 행동에 그 결정 번호가 나오면 「이 번호를 적은 작업」으로 옆 칸에 보이고 작업 화면으로 잇는다. 대체 관계를 누르면 그 결정으로 가고(브라우저 뒤로 가기로 돌아온다) 목록에서도 그 행이 보이게 한다. 빈 상태 세 유형(아직 결정 없음·거른 결과 없음·읽기 실패)과 390px 시트가 있다.
- **여기서 만든 결정**(`src/decisions/`의 `DecisionForm`·`decisionDraft`): 「새 작업」과 같은 자리(목록 머리 오른쪽)에 「새 결정」 주 동작 단추가 있다. 누르면 상세 칸(좁은 폭은 시트)에 양식이 열린다. 양식은 질문 → 맥락 → 선택지(글자 앞 동그라미로 고른 안 표시, 「선택지 더하기」) → 결정 → 근거 → 재검토 조건 → 결정 역할(승인은 칸이 아니라 사실로 보인다: 1단계는 소유자) → 프로젝트(체크) → 관련 작업(고르고 잇기) 순서이고, 질문이 없으면 보내는 단추가 잠기고 이유를 보인다. 상세는 사실 줄에 「정본 여기서 만든 결정」을 더하고, 머리 바로 아래 「할 수 있는 일」에 제안이면 채택하기(주 동작) / 기각하기(이유는 적지 않아도 된다) / 내용 고치기와 승인하는 사람을, 채택이면 「새 결정으로 대체하기」를 둔다. 서버가 허락하지 않는 단추는 잠그고 서버가 준 이유를 자물쇠와 함께 보인다(작업 화면의 다음 단계와 같다). 그 아래 고른 안 → 대체 관계(제안이면 「채택하면 대체할 결정」) → 선택지(상자 없이 목록으로, 고른 안은 굵게와 「고른 안」 표시) → 맥락 → 근거 → 결정 역할 → 재검토 조건 순서로 읽고, 옆 칸에 관련 작업 / 승인 기록 / 이력을 둔다. Markdown 칸은 `Prose`로 그린다. 작업 상세 옆 칸 맨 위에는 그 작업을 이은 결정이 「이어진 결정」으로 보인다(`LinkedDecisions`, 없으면 아무것도 그리지 않는다).
- **나를 기다리는 것 화면**(`src/inbox/`, 첫 화면): 작업·결정 화면과 같은 문법이다. 목록과 상세를 늘 함께 두고 화면 머리의 설명 문단은 없다. 목록은 계약의 다섯 묶음(권한 요청 / 멈춘 AI의 질문 / 내 작업과 겹친 충돌 / 위험 목록 검토 / 표본 검토와 나머지 알림)을 그 순서대로 두고, 묶음 안은 오래 기다린 것부터다. 24시간 넘게 기다린 검토는 1번 묶음 자리로 올라오고 행 둘째 줄에 「오래 기다려 위로 올림」을 쓴다. 행 첫 줄은 종류(아이콘과 글자)와 요약(충돌은 그 파일, 기다리는 세션은 실행기가 보낸 문구나 그 세션의 하는 일), 둘째 줄은 기다린 시간·바로 알림/묶어 알림·반복·관련 세션의 짧은 번호와 브랜치다. 상세는 무엇이 기다리는지, 겹친 파일(고정폭), 왜 나를 기다리는지, 할 수 있는 일, 옆 칸의 관련 세션(누르면 세션 현황에서 연다) 순서다. 충돌은 상세에서 확인 / 충돌 아님(이유를 적어야 보낸다) / 해결로 판정하고, 판정하면 목록을 바로 다시 읽고 다음 항목을 연다. 기다리는 세션은 「그 세션의 터미널에서 이어 입력하면 저절로 닫힌다」를 행동 자리에 보인다. 위험·표본 검토(`src/review/ReviewDetail.tsx`)는 행 첫 줄이 종류와 그 작업의 제목, 둘째 줄 끝이 걸린(표본이면 바뀐) 첫 파일과 나머지 수(고정폭)다. 상세는 사실 줄(종류·기다린 시간·「사람 기다림(…), 자동 검사 안 함」처럼 사람 검토와 자동 검사를 따로·작업 단계) → 왜 나에게 왔나(패턴마다 걸린 파일) → 할 수 있는 일 → 검토할 결과(실행 브랜치·기준·스냅샷 커밋, 고정하지 못했으면 경고 표시와 「대상을 고정할 수 없음」, 바뀐 파일과 「위험 경로」 표시, 변경을 보는 `git diff` 명령) 순서이고 옆 칸에 그 작업(누르면 작업 화면)이 있다. 「승인하기」(주 동작)와 「반려하기」 단추 안에 그 판정이 무엇을 하는지 서버가 준 글이 작게 들어가고, 긴 글은 단추 안에서 꺾는다. 반려는 이유 칸을 먼저 열고 이유가 없으면 보내는 단추가 잠긴다. 표본 반려에는 위험 목록 후보 칸(서버의 제안이 미리 들어 있음)이 있다. 판정하면 목록 위에 결과 한 줄과 「작업 열기」가 다음 판정까지 남는다. 질문(`src/question/QuestionDetail.tsx`)은 2번 묶음에서 행 첫 줄이 종류(「질문」·「실행의 질문」)와 질문 글이다. 상세는 사실 줄(종류·막는지·기다린 시간·기한, 지났으면 「기한 지남, 다시 알림 N회」) → 질문(멈춘 단계·선택지) → 왜 나에게 왔나(종류와 받는 역할, 질문한 쪽, 무응답은 승인이 아님) → 할 수 있는 일(답 칸, 「문서를 바꿔야 한다」 확인란, 이어진 기록 번호 셋, 「답 보내기」 주 동작과 「질문 거두기」) 순서이고 옆 칸에 작업과 전달 이력이 있다. 답하면 위험·표본 검토와 같은 결과 한 줄이 남는다. 고른 항목은 주소(`#inbox?item=…`)에 남는다. 빈 상태는 기다리는 것 없음(무엇이 오면 쌓이는지)과 읽기 실패 둘이고, 390px에서는 목록만 보이고 행을 누르면 시트로 연다. 충돌 표시는 겹친 두 원(`conflict` 아이콘)이다. 권한 요청(1번 묶음)과 선택형 질문(2번 묶음) 중계(`inbox/RelayDetail.tsx`, `inbox/relayView.ts`)는 행 둘째 줄과 상세 사실 줄에 상태를 모양과 글자로 보인다(남은 초, 전달하는 중, 전달됨: 허용, 전달 안 됨, 이미 터미널로 넘어감). 상세는 실행할 명령 전문(고정폭 상자)이나 대상 파일과 도구 입력 전체 → 실행기가 붙인 설명 → 할 수 있는 일 → 작업 위치 → 왜 나를 기다리나 순서라, 390px에서도 답하는 단추가 첫 화면 높이 안에 든다. 권한 요청은 허용(주 동작) / 거절(이유는 적지 않아도 된다) / 터미널에서 답하기, 선택형 질문은 질문마다 선택지 행(하나 고르기는 동그라미, 여러 개는 네모)과 답 보내기(모두 고르기 전에는 잠기고 이유를 보인다) / 터미널로 넘기기다. 답한 뒤에도 항목은 남아 전달 여부를 보이고, 전달됨에는 「터미널에서 먼저 답했으면 쓰이지 않았을 수 있다」를 늘 붙인다. 끝난 중계는 10분 동안 묶음 안 「방금 끝난 중계」 줄 아래에 흐리게 남고 건수에서 빠진다. 중계 중인 권한 요청과 같은 세션의 「권한 확인」 기다림은 같은 말이라 목록에서 뺀다. 사이드바 아래(좁은 폭은 「더 보기」)에 집중 모드 단추(`focus` 아이콘, 켜지면 현재 화면처럼 밝은 바탕과 굵은 글자)가 있고, 켜진 동안 1·2번 묶음 머리에 「집중 모드: 새 요청은 터미널에서」를 보인다. 서버가 중계를 켜지 않았으면(기본) 1번 묶음 머리에 「꺼져 있다(사람 인증이 생기기 전에는 기본 꺼짐)」를 보인다. 켜는 단추는 두지 않는다(서버 설정 `ZM_BATON_RELAY`). 첫 화면은 브라우저 탭이 보이고 이 화면이 열려 있는 동안 15초마다 서버에 알린다(선택형 질문은 그때만 중계된다).
- **세션 현황 화면**(`src/sessions/`): 같은 문법이다. 지금까지의 표를 목록과 상세로 바꿨다. 거르기 칩은 저장소(목록에 있는 것만, 건수 포함)와 끝난 세션 보기이고, 입력줄이 세션 번호·하는 일·브랜치 찾기를 겸한다(서버에 세션 찾기가 없어 화면에서 거른다). 목록은 살아 있음 / 그 밖(끝남·등록 끔·만료, 끝난 세션 보기를 켰을 때만)으로 묶고, 묶음 안은 마지막 신호 최신순이다. 행 첫 줄은 실행기와 하는 일(공유하지 않거나 아직 올리지 않았으면 그렇다고 쓴다), 다른 세션과 겹친 파일이 있으면 겹침 표시(아이콘과 글자, 수)다. 둘째 줄은 살아 있지 않을 때의 상태, 저장소(1180px 이하에서 뺌), 브랜치, 마지막 신호, 장치다. 상세는 하는 일을 제목으로, 상태·실행기와 판·장치를 한 줄로 보이고, 세션 번호 전체(고정폭)·저장소와 위치·브랜치·하는 일 올린 때·등록·마지막 신호, 겹친 파일(아직 판정을 기다리면 나를 기다리는 것의 그 항목으로 잇고, 확인함으로 남은 충돌이면 그렇다고 쓴다), 옆 칸의 최근 고친 파일(겹친 파일 표시) 순서다. 등록하지 않았거나 등록을 끈 세션이 빠진다는 것과 셸 명령으로 바꾼 파일이 보고되지 않는다는 것은 상세의 작은 안내로 둔다. 거르기와 고른 세션은 주소(`#sessions?repo=…&ended=1&item=…`)에 남는다. 빈 상태는 등록된 세션 없음(시작 훅이 `zm-baton session register`로 등록한다)·살아 있는 세션 없음(끝난 세션 보기)·거른 결과 없음·읽기 실패이고 390px 시트가 있다. 사이드바의 세션 수는 셸이 살아 있는 세션만 따로 읽어 센다.
- **문서 화면**(`src/documents/`): 같은 문법이다. 사이드바의 「결정」 아래에 있고(아이콘 `doc`), 좁은 폭에서는 아래 탭 줄의 「더 보기」 안에 있다. 목록은 들고 있는 쪽이 없는 기록이라 최신 판의 승인 상태로 묶는다(승인 기다림 / 승인됨 / 판 없음, 묶음 안은 최근에 바뀐 것부터). 행 첫 줄은 정본 위치 아이콘(제품 안 `doc`, Git `git-file`)과 「판 2 초안」 같은 판 상태, 제목이고, 둘째 줄은 정본 위치 글자·프로젝트(1180px 이하에서 뺌)·Git 경로(고정폭)다. 거르기 칩은 프로젝트와 정본 위치(건수 포함), 입력줄이 제목·Git 경로 찾기를 겸한다. 거르기와 고른 문서·판은 주소(`#documents?project=…&source=…&item=…&ver=…`)에 남는다. 상세 사실 줄은 정본(아이콘과 글자)·현재 판·승인된 판·프로젝트·소유자이고, Git 문서는 그 아래 「읽기만 한다」와 경로·저장소·브랜치를 한 줄로 보인다. 「할 수 있는 일」의 주 동작은 다음 판이다: 제품 안은 「새 판 쓰기」, Git은 「새 커밋 기록」(커밋과 메모를 그 자리에서 받는다). 옆에 보고 있는 판의 「판 N 승인하기」(승인할 수 없으면 잠그고 서버가 준 이유), 마지막에 「문서 정보 고치기」. 그 아래 고른 판의 본문(제품 안은 `Prose`, Git은 경로와 커밋 안내), 판 목록(가장 새 판부터, 보는 판은 바탕과 「보는 판」 글자로 표시, 판마다 보기·승인하기), 옆 칸에 영향 받는 작업 / 관련 결정 / 이력이다. 판 상태는 「초안」·「승인됨」 글자를 가는 테두리 안에 쓰고 색만으로 나누지 않는다. 새 판은 상세 칸(좁은 폭은 시트)의 쓰기 양식에서 최신 본문으로 시작하고, Markdown 칸(`ui/MarkdownField`)에는 쓰기 / 미리보기 두 단추가 있다. 본문이 그대로면 저장 단추가 잠기고 이유를 보인다. 새 문서 양식은 제목 → 정본 위치(제품 안 / Git, 등록할 때만) → 프로젝트 → Git 위치 또는 첫 판 본문 → 영향 받는 작업 → 관련 결정 순서이고, 잇기는 `ui/LinkPicker`(이은 것 목록과 브라우저 기본 고르기 상자)로 한다. Git 경로가 절대 경로처럼 보이면 보내기 전에 막고 이유를 보인다. 빈 상태 세 유형(아직 등록한 문서 없음·거른 결과 없음·읽기 실패)과 390px 시트가 있다.
- **AI 계정 화면**(`src/accounts/`): 사이드바 아래의 설정 자리(「화면 배치」 1의 「설정」)에 둔다. 사용량 상한은 조직 설정(기준 G39.4)이라 설정 화면이 생기면 그 안의 한 부분이 되고, 그 전까지는 그 자리가 이 화면을 연다(아이콘 `key`, 좁은 폭은 「더 보기」 안). 같은 문법이다. 목록은 들고 있는 쪽이 없는 기록이라 지금 일을 맡을 수 있는지로 묶는다(쓸 수 있음 / 멈춤 / 비활성, 묶음 안은 오래된 것부터). 행 첫 줄은 종류(개인 구독·조직 계정·API 키)와 이름, 둘째 줄은 멈춘 이유(멈췄을 때)·오늘 사용량과 하루 상한에 대한 비율·오늘 실행 수다. 상세는 종류·인증 방식·소속·자격 위치를 사실 줄로, 멈췄으면 그 아래 경고 띠(비활성은 조용한 줄), 할 수 있는 일(고치기·비활성화하기 또는 다시 쓰기·추가 과금 멈춤 풀기, 비활성화와 멈춤 풀기는 한 번 더 확인), 오늘 사용량, 상한과 그것이 어떻게 지켜지는지, 최근 7일, 최근 실행(작업으로 잇는다), 목적과 자료 처리 조건, 옆 칸의 이력 순서다. 비용은 늘 「가격표 환산」이라 적고 청구액이 아니라고 말한다. 양식은 키 값을 묻지 않는다. 자격 위치는 종류가 정하는 사실로 보이고, 키처럼 보이는 글은 보내기 전에 막고 이유를 보인다. 고른 계정은 주소(`#accounts?item=…`)에 남는다. 작업 화면의 「AI에게 맡기기」 양식에 「AI 계정」 칸(멈춘 계정은 잠그고 이유를 붙인다, 칸 아래에 이 실행의 상한과 오늘 사용량)이, 실행 기록의 칸에 계정·인증 방식·상한·사용량·과금 위치와 멈춘 이유의 경고 띠가 있다.
- **문서 모순 후보**(`inbox/ContradictionDetail.tsx`, `ui/OpenContradictions.tsx`, `ui/contradictionView.ts`, `ui/contradictions.css`): 마스터가 찾은 후보는 첫 화면 5번 묶음에 종류 「모순 후보」(`doc` 아이콘)로 놓이고, 행 제목은 두 기록의 이름이다. 상세는 어긋나 보이는 두 문장(각 문장 위에 그 문서판·결정으로 가는 링크, 문장은 조용한 바탕의 인용 상자) → 마스터가 본 이유와 찾은 경로·실행 기록 링크 → 왜 나를 기다리나 → 판정 단추 셋(확인 / 모순 아님, 이유를 적어야 보낸다 / 해결) 순서다. 문서·결정 상세에는 「할 수 있는 일」 아래에 「열린 모순 후보」가 보인다. 그 기록의 문장을 먼저(「이 문서」·「이 결정」), 상대 기록을 링크로 두고, 판정 전이면 「나를 기다리는 것에서 판정」, 확인함이면 「고쳤으니 해결로 남기기」를 둔다. 그 기록으로 시작한 마지막 모순 찾기의 결과를 한 줄로 보인다. 후보도 찾기 기록도 없으면 아무것도 그리지 않는다.
- **작업 상세의 질문**(`src/question/Questions.tsx`): 「다음 단계」 아래, 「AI에게 맡기기」 위에 「질문」 칸이 있다. 질문마다 첫 줄에 상태(답변 대기는 경고색 글자)·종류·막힘·묻는 쪽과 답하는 쪽·기한, 그 아래 질문 글, 답과 이어진 기록 번호, 답이 다음 실행에 들어간 방식, 열린 질문은 「나를 기다리는 것에서 답하기」 링크, 문서 반영 대기는 문서판 번호 칸과 「문서 반영 기록」이 온다. 맨 아래 「질문 남기기」(서버가 허락하지 않으면 잠그고 이유)는 누르면 질문 칸·종류(받는 사람 안내)·막힘 확인란 폼으로 열린다. 실행 기록의 끝난 실행에는 「질문으로 남기기」가 있고, 누르면 그 실행의 마지막 답으로 시작하는 폼이 그 자리에 열린다. 답이 온 질문이 있으면 맡기기 단추가 「답을 넣어 이어서 맡기기」가 되고 폼에 몇 개가 들어가는지 쓴다.
- **위험 목록 화면**(`src/review/RiskRules.tsx`, 주소 `#risk?item=…`): 사이드바의 「문서」 아래(아이콘 `alert`), 좁은 폭에서는 「더 보기」 안이다. 같은 문법으로 목록은 조직(「조직 기본」 한 행)과 프로젝트로 묶고, 행 둘째 줄에 목록의 출처(처음 목록·조직이 고친 목록·조직 기본 목록을 쓴다·이 프로젝트가 고친 목록), 패턴 수, 후보가 있으면 후보 수를 쓴다. 상세는 사실 줄(목록·패턴 수·표본 비율과 하루 상한) → 표본 반려에서 올라온 후보(패턴·작업·반려 이유, 「목록에 더하기」 주 동작과 「후보에서 빼기」) → 위험 경로 패턴(패턴 문법 안내, 한 줄에 하나씩 쓰는 고정폭 입력 칸, 조직이면 표본 비율(%)·하루 상한 칸, 저장 단추와 되돌리기) 순서다. 바꾼 것이 없으면 저장 단추가 잠기고 「바꾼 것이 없다」를 보인다. 3~4안을 따로 만들지 않고 목록과 상세의 공용 문법을 그대로 썼다.
- **조직 화면**(`src/org/`, 주소 `#org?item=…`): 사이드바 아래 설정 자리의 「조직」(아이콘 `team`, 좁은 폭은 「더 보기」 안)이다. 같은 문법으로 목록을 종류로 묶는다(조직 / 사람 / 팀 / 제품 / 프로젝트 / 저장소 / 환경). 1인 조직(활동 중인 사람이 한 명이고 팀·제품·환경이 없을 때)은 조직·사람·프로젝트·저장소만 보이고, 나머지는 묶음 자리 대신 「팀·제품·환경: 아직 없음. 사람을 더하면 팀을 나눈다」 한 줄과 「팀 더하기」로 접는다. 사람이 둘이 되거나 팀·제품·환경이 하나라도 생기면 모든 묶음이 보이고 빈 묶음은 빈 상태 문구를 단다. 행 첫 줄은 아이콘과 이름(종류는 묶음 머리가 말하므로 행에 다시 쓰지 않는다. 조직 행만 「조직」을 쓴다), 둘째 줄은 역할(소유자는 「모든 역할」)·사람 수·이어진 수·짧은 저장소 키다. 보관한 항목과 비활성 사람은 「보관됨」·「비활성」 글자와 흐린 제목으로 보인다. 상세는 사실 줄(사람이면 상태·역할·매니저 번호·사람 번호, 저장소면 저장소 키·원격·PC 수) 아래에 운영자만 보는 조작(이름 바꾸기, 역할 확인란과 역할이 하는 일, 활동 상태, 사람 고르기, 이을 항목 고르기와 끊기, 종류, 원격 주소, 보관·되살리기)을 두고, 서버의 거절 이유를 그 조작 바로 아래에 보인다. 조직 소유자의 역할은 모두 체크된 채 잠기고 「조직 소유자는 늘 모든 역할을 갖는다」를 자물쇠와 함께 보인다. Git에서 가져온 프로젝트는 이름 칸 대신 이유를 보인다. 운영자가 아니면 「조직 구조는 운영자 역할만 바꾼다」 한 줄과 읽기만 보인다. 조직 행의 상세는 역할 여섯과 공유 범위 다섯을 뜻과 함께 풀어 둔다. 목록 머리의 「더하기」(운영자만)는 종류를 고르는 양식을 상세 칸(좁은 폭은 시트)에 연다.
- **나 화면**(`src/me/`, 주소 `#me`): 설정 자리 맨 위의 「나」(아이콘 `person`)다. 목록과 상세가 아닌 한 장이다. 머리에 이름과 조직·역할·팀·매니저 번호(고정폭), 그 아래 상태 카드 미리보기(세션이 받는 글 그대로 고정폭 상자, 「저장소에서 열면 그 저장소의 최근 결정과 다른 세션이 붙는다」) → 내 열린 작업(단계 기호와 단계 이름, 제목, 두 줄까지의 다음 행동, 작업 화면으로 잇기. 끝내거나 취소한 작업은 「끝내거나 취소한 작업 N건」 아래에 접는다) → 연결된 세션(공유하지 않은 내 「지금 하는 일」도 보이고 「공유 안 함(나만 봄)」 표시, 세션 현황으로 잇기) 순서이고, 넓은 폭은 옆 칸에 개인 메모(「나만 본다. 조직 운영자도 못 보고, 내보내기에도 들어가지 않는다」를 자물쇠와 함께, 쓰기·고치기·지우기, 지우기는 한 번 더 묻는다)와 작업 기록(내가 하거나 내 세션이 한 일, 기록으로 잇기)이 있다. 1180px 이하는 한 줄로 내려온다.
- **구성원 로그인 계정**: 조직 소유자만 사람 상세에서 로그인 상태와 일회용 설정 코드 발급을 본다. 일반 운영자에게는 이 조작이 없다. 코드 원문은 화면 메모리에만 두고 새로고침·사람 전환·상세 닫기 때 지운다. 로그인 필수 모드에서만 발급한다.
- **로그인 화면**(`src/auth/`, 서버가 `required`일 때만): 사이드바 없이 캔버스 바탕 가운데 좁은 한 칸(`--w-form`)에 종이 바탕 양식 하나다. 위에 자물쇠와 「zm-baton」 한 줄, 양식은 새 항목 양식(`.wn`)의 칸·단추·거절 줄을 그대로 쓴다. 「로그인」(아이디·비밀번호)과 「처음 비밀번호 정하기」(설정 토큰·아이디·새 비밀번호 두 번, 설정 코드를 구성원은 조직 소유자에게, 최초 소유자는 서버 시작 기록에서 받는다는 안내) 둘이고, 아직 비밀번호가 없는 서버면 뒤쪽으로 연다. 양식 아래 조용한 단추 하나로 서로 오간다. 보낼 수 없으면 단추를 잠그고 이유를 옆에 쓴다. 주소는 바꾸지 않아 로그인 뒤 원래 화면(예: `#me?device_login=…`)으로 간다. `local` 모드에서는 이 화면이 없다(`AuthGate`). 3~4안은 만들지 않았다(공용 부품만 쓴 한 장).
- **나 화면의 로그인과 기기**(`src/me/MyAccess.tsx`): 연결된 세션 아래에 「로그인」(`required`만: 로그인한 아이디, 로그아웃, 접어 둔 「비밀번호 바꾸기」 양식)과 「내 기기」(두 모드: 이름 옆 작은 테두리 표시로 「기기 토큰 있음 / 없음(경고색) / 폐기함」, 둘째 줄에 OS·등록·마지막 신호·기기 번호, 토큰이 없으면 할 일 한 줄, 「폐기하기」는 한 번 더 묻는다. `required`면 `zm-baton login`이 보여 준 코드를 넣는 칸)이 있다. 주소가 `#me?device_login=코드`면 본문 맨 위에 「기기 연결 요청」(큰 고정폭 코드, 새 기기인지 내 기존 기기인지, 기한, 「연결 허락」 주 동작과 「거절」)이 먼저 보인다.
- **공유 범위 표시**: 작업·결정·문서 상세의 사실 줄에 「공유 범위」(개인·제한·팀·조직·공개)를 글자로 보인다. 이름표는 한 곳(`ui/visibility.ts`)에 있고, 서버가 모르는 값을 보내면 그대로 보인다. 바꾸는 양식은 아직 없다(서버는 기록의 주인에게만 받는다).
- **감사 기록 화면**(`src/audit/`): 사이드바 아래 설정 자리, 「AI 계정」 다음(좁은 폭은 「더 보기」 안). 아이콘은 30개 상한(「정한 것 넷」 2)에 닿아 자리의 `settings`를 빌려 쓴다. 같은 문법이다. 목록은 날짜로 묶고(오늘·어제·날짜, 묶음 머리에 표시 없음) 새것부터다. 행 첫 줄은 행위자 종류(사람 `person`·세션 `session`·실행 `run`·시스템 `settings` 아이콘과 글자)와 동작의 이름, 둘째 줄은 시각(고정폭 숫자)·대상 종류와 짧은 번호·행위자 번호(이름을 모르는 동작이면 동작 코드)다. 거르기 칩은 행위자·대상(서버가 센 종류와 건수)·기간과, 상세에서 고른 「대상 번호」(누르면 풀린다)다. 상세는 동작 이름을 제목으로 시각·행위자·부른 사람(다를 때만)·동작 코드를 사실 줄로 두고, 대상(그 화면으로 가는 단추와 「이 대상의 기록만 보기」) → 남긴 내용(키는 고정폭, 값은 글, 묶음 값은 조용한 바탕의 들여 쓴 JSON, 좁은 폭에서는 키 아래에 값) → 행위자 종류의 뜻 순서다. 목록 머리 오른쪽의 「보존 규칙과 내보내기」(누른 동안 눌린 상태)는 상세 자리에 내보내기(주 동작 「내보내기 파일 받기」, 내려받기 링크)와 보존 규칙 표(종류·보존·서버 설정 이름)를 연다. 보존 기간은 바꾸는 칸 없이 자물쇠와 「서버 설정으로만 바꾼다」를 보인다. 거르기·고른 줄·열린 칸은 주소(`#audit?…`)에 남는다. 빈 상태 세 유형(아직 기록 없음·거른 결과 없음·읽기 실패)과 390px 시트가 있다. 한 번에 100건, 「더 보기」로 500건까지이고, 넘으면 기간이나 대상으로 좁히라고 말한다.
- **아직**: 위험 목록의 저장소별 목록과 패턴 시험 칸(경로를 넣어 걸리는지 보기)은 없다. 문서 판끼리의 차이 보기, 승인 철회, 정본 위치 옮기기는 없다. Git 문서의 본문은 화면에 그리지 않는다. 결정 양식의 Markdown 칸에는 미리보기가 없다(저장한 뒤 상세에서 그려 본다). 채택한 결정 쪽에는 그것을 대체하자는 제안(아직 채택 전)을 보이는 자리가 없다. 제안 쪽에서만 「채택하면 대체할 결정」으로 보인다. 세션 현황의 「공유 끄기」·「실행 중단 요청」(화면 초안의 행동)은 서버 API가 없어 넣지 않았다. 선택형 질문의 「직접 쓰기」(터미널의 Other)는 없다. 묶어 알리는 때(하루 두 번)의 알림은 없다. 결정 목록은 고른 행을 목록 안에서 보이게 옮기지만, 작업 목록은 아직 그렇게 하지 않는다. 작업 목록 머리의 보기 전환(목록·보드·타임라인) 자리는 아직 없다. 서버에 사람과 팀이 생겼지만 작업 목록의 팀 묶기(나 / 팀원 이름별)와 담당자·팀 칩은 아직 없고, 작업·결정·문서 화면은 책임자를 사용자 ID(`usr_owner`)로 보인다(이름은 조직 화면만 쓴다). 공유 범위를 바꾸는 양식과 조직 화면의 사람 인증(누가 요청했는지)은 다음 단계다. 작업 수백 건을 위한 가상 스크롤은 없다(서버가 한 번에 500건까지 준다).
