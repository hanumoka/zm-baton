### 검토 절차와 v0.2 예외

`AGENTS.md:39`의 새 절차는 검토 기준과 충돌하지 않는다.
확신은 높음이다.
기준의 「작성자와 검토자를 나눈다」 절은 판단하는 역할과 세션을 나눈다.
검토 기록을 Git에 넣는 주체가 반드시 검토자여야 한다는 규칙은 없다.
작성 세션이 별도 검토자의 기록을 고치지 않고 커밋해도 검토 판정의 주체는 바뀌지 않는다.
검토자의 신원과 검토 대상 커밋은 기록 안에 남아야 한다.
Git 커밋의 작성자 정보만으로 검토자의 신원을 대체할 수는 없다.

v0.2는 검토 뒤 변경이 `docs/reviews/`의 검토 기록 파일뿐일 때 기존 검토를 현재 커밋에도 적용한다.
이 예외는 기록을 커밋하는 실행기를 제한하지 않는다.
따라서 작성 세션의 원문 그대로인 기록 커밋에도 적용할 수 있다.
구현이나 정책 문서를 함께 바꾸면 이 예외를 적용할 수 없다.
이번 `4e21213`에는 정책 문서와 계획 변경이 있으므로 새 검토가 필요했다.
이 기록이 그 변경을 검토한다.

「검토자가 직접 고치면 다시 검토한다」는 규칙도 유지된다.
새 문장은 검토자에게 구현 수정을 허용하지 않는다.
검토 기록만 추가하는 경우에는 v0.2의 구체적인 예외를 적용한다.

`codex exec`는 검토 실행 방법을 정한다.
별도 역할·세션과 소유자의 검토 세션 실행 원칙을 없애는 문장은 아니다.
작성 대화를 이어받지 않는다는 정본의 요구도 그대로 적용된다.
병렬 Claude 작업자에게 서로 다른 worktree를 주는 규칙은 작업 파일을 분리한다.
worktree가 다르다는 사실만으로 독립 검토 세션이 되는 것은 아니다.
AGENTS는 별도 세션 요구를 유지하므로 이 규칙과도 충돌하지 않는다.

### 시험 계획과 협업 계약

추가된 조회 API는 계약의 「실행 권리 청구」와 「전송 경로」에 맞는다.
API 다섯은 최소 시험의 기능 목록이다.
계약 전체의 API 수를 다섯으로 제한한 것으로 읽지 않았다.
폴링으로 할 일을 조회하는 경로는 계약에 있다.
계약의 주기 값은 시험 결과로 조정할 수 있는 시작값이다.
WebSocket 생략은 이번 시험의 제외 범위로 명시됐다.

`kind` 설명은 계약의 「보고 한 건의 모양」과 일치한다.
활동 일곱 가지와 시작·종료의 `lifecycle`을 구분했다.
계약의 보고 형식도 직접 참조한다.

새 제외 항목은 계약 요구를 삭제한 것이 아니라 최소 시험 뒤로 구현을 미룬 것이다.
문서는 후속 1단계 작업이라고 명시한다.
요청 중복·작업 버전·연결 단절 처리 등을 생략한 시험만으로 계약 전체 준수나 1단계 완료를 선언할 수는 없다.
현재 변경에는 그런 선언이나 실행 코드가 없다.
제외 목록 전체가 계약의 단계 구분과 완전히 같은 것은 아니다.
기억 등 기존 항목의 단계 표현은 이번 커밋에서 바뀌지 않았다.
이번 검토에서는 추가된 제외 항목의 계약상 의무가 유지되는지 확인했다.

## 비차단 지적

### C3-R. 작업 순서 표에 API 넷이 남아 있다

- 위치: `docs/stage1/compat-test.md:45`. 대조 위치는 같은 파일 13행이다.
- 검토 항목: 1. 수락 조건, 12. 문서.
- 근거: 본문은 조회를 포함한 API 다섯으로 바뀌었다. `work/compat-server` 행은 여전히 API 넷이라고 적는다.
- 확신: 높음.
- 병합 막음: 아니오.
- 영향: 서버 작업 범위를 표만 보고 읽으면 조회 API를 빠뜨릴 수 있다.
- 비차단 이유: 본문은 필요한 API 다섯을 명확히 열거한다. 실행 구현이 없는 계획 문서의 잔여 불일치다.
- 고칠 방향: 작성 세션이 45행의 API 넷을 API 다섯으로 맞춘다. 수정 커밋은 다시 검토받는다.

## 검토 항목의 적용과 부채 후보

수락 조건·계약·비밀값·문서 항목은 위에 기록했다.
중복 방지와 실행 보고는 계획의 변경만 대조했다.
권한 코드·런타임 시험·의존성은 실행 코드 변경이 없어 해당 없음이다.
파일 책임과 크기는 세 파일의 작은 문서 수정 범위에서 확인했다.
새 제삼자 코드나 재배포 의존성은 없다.
핵심 모듈의 첫 코드 병합은 이번 변경에 해당하지 않는다.
API 수를 본문과 표에 반복한 것이 인지부채 후보다.
C3-R이 그 불일치의 근거다.
부채의 판정과 대응 시점은 소유자가 정한다.

## 확인하지 않은 것

- PR 본문의 일곱 항목, 소유자 승인, 사람 필수 변경의 판단 이유를 확인하지 않았다.
- CI 결과와 원격 브랜치 상태를 확인하지 않았다.
- 앞선 검토 범위 전체를 다시 검토하지 않았다.
- `zm-docs`의 Git HEAD와 미커밋 상태는 확인하지 않았다.
- 계약이 참조하는 모든 결정 기록과 관련 설계 파일은 열지 않았다.
- 실제 `codex exec` 실행 절차나 병렬 worktree 운용은 시험하지 않았다.
- 작성 세션의 실행 로그와 실제 시작 명령은 확인하지 않았다.
- 서버·연결 프로그램·Claude Code의 실행 시험은 하지 않았다.
- 전용 비밀값 탐지기는 돌리지 않았다. 수동 점검이 모든 비밀값의 부재를 보장하지 않는다.
- LICENSE를 외부 원문과 다시 비교하지 않았다.

AGENTS와 LICENSE는 정책 문서다.
실제 병합에는 소유자의 판단 이유와 병합 승인이 필요하다.
