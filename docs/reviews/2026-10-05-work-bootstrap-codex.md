# work/bootstrap Codex 독립 검토 기록

## 판정: 「병합 가능」

검토한 변경의 병합 막음 지적은 0개다.
비차단 지적은 4개다.
이 판정은 로컬 변경에 대한 AI 검토 승인이다.
소유자의 병합 승인과 사람 필수 변경의 판단 이유를 대신하지 않는다.
PR 본문과 원격 검사는 확인하지 않았으므로 병합 직전에 별도로 확인해야 한다.

### 검토 기준의 허브 판 대비 차이

`git diff --no-index -- ../zm-docs/docs/research/2026-10-04-ai-team-collaboration/review-standard.md docs/review-standard.md`로 전체 차이를 확인했다.
현재 허브 파일에는 옮기기 전 판이라는 안내가 있다.
확인한 차이는 사용자가 지정한 범주 안에 있다.

1. 허브의 YAML 앞머리를 제거했다.
2. 제목과 두 양식의 기준 버전을 v0.2로 바꿨다.
3. 정본 이동 안내를 저장소 관점의 정본 관계로 바꿨다.
4. 소유자·마지막 검토 줄과 근거 번호 설명을 넣었다.
5. 결정·기준·조사·계약의 링크를 번호 또는 이름으로 바꿨다.
6. 작업 번호를 정하기 전에는 브랜치 이름을 쓰도록 했다.
7. 결론 4번과 병합 직전 절에 검토 기록 예외를 넣었다.
8. 변경 이력을 넣었다.

다른 규칙 본문의 삭제나 변경은 찾지 못했다.
예외는 일반적인 현재 커밋 일치 문장보다 구체적인 규칙으로 읽었다.
검토 결과 항목 3과 병합 직전 목록 2에도 예외 절을 참조하면 오독을 줄일 수 있다.
이는 추가 병합 막음 지적이 아니다.

### 공개 범위

다섯 커밋의 파일 내용과 커밋 설명을 확인했다.
절대 경로·대표적인 토큰 형식·개인키 머리말·허브에서 확인한 회사 및 별도 프로젝트 식별자를 검색했다.
실제 비밀값·로그인 정보·소유자 PC 절대 경로·회사 자료는 찾지 못했다.
절대 경로 검색의 일치 결과는 LICENSE 3·195행의 공개 HTTP 주소였다.
커밋 작성자의 개인 메일 주소는 Git 작성자 메타데이터에 있다.
이를 로그인 정보로 분류하지 않았다.

공개가 허용되지 않은 허브 문서의 통째 복사는 찾지 못했다.
검토 기준의 이전은 DEC-0087이 허용한다.
나머지는 작업에 필요한 결정 요약과 상대 참조다.
검토 근거로 요구된 설계 요약과 비공개 문서 자체의 복사를 구분했다.

### 무시 규칙과 줄바꿈

`git check-ignore -v --no-index --non-matching`으로 다음 경로를 확인했다.

`git check-attr text eol diff -- gradlew gradlew.bat setup.cmd setup.ps1 init.sh gradle/wrapper/gradle-wrapper.jar image.png image.gif`도 실행했다.
셸 파일은 LF다.
bat·cmd·ps1은 CRLF다.
jar·png·gif는 `text`와 `diff`가 unset인 이진 파일이다.
현재 후보 구조에서 소스가 무시되는 회귀는 찾지 못했다.
모든 가능한 소스 경로를 보장하는 시험은 아니다.

### 시험 계획과 계약

통과 기준 1~3은 계약의 청구·세대 번호·사건 중복 처리와 맞는다.

## 비차단 지적

### C1. AGENTS의 검토 기록 요약에는 일부 항목이 빠져 있다

- 위치: `AGENTS.md:40`, `AGENTS.md:52`.
- 검토 항목: 12. 문서. 앞선 지적 6의 잔여다.
- 확신: 높음. 병합 막음: 아니오.
- 근거: 기준 321행은 모델·역할과 작성 세션과의 구별을 요구한다. AGENTS 40행은 실행기·버전·세션 번호만 열거한다. 기준 결론 10번의 PR 본문도 AGENTS 52행의 요약에는 없다.
- 영향: 요약만 읽으면 기록 항목이나 비밀값 점검 범위를 빠뜨릴 수 있다.
- 비차단 이유: AGENTS 46행이 정본의 15개 조건을 따르도록 한다. 요약을 예시로 소개하므로 정본 의무를 없애지는 않는다.
- 고칠 방향: 신원 목록을 완성하거나 정본의 검토 결과 절을 직접 가리킨다. 비밀값 목록에 PR 본문을 명시한다.

### C2. 시험 계획의 제외 범위가 앞선 지적을 모두 반영하지 않았다

- 위치: `docs/stage1/compat-test.md:19`, `docs/stage1/compat-test.md:33`.
- 검토 항목: 1·2·12. 앞선 지적 12의 잔여다.
- 확신: 높음. 병합 막음: 아니오.
- 근거: 계약은 사건의 `kind`를 활동 일곱 가지 또는 `lifecycle`로 정한다. 계획의 출력 변환에는 이 구분이 없다. 앞선 지적이 든 `request_id` 중복 처리, 작업 `version` 검사, WebSocket 깨우기의 포함 여부도 명시하지 않았다.
- 영향: 작성자가 무엇을 시험하고 무엇을 후속 작업으로 남길지 다르게 해석할 수 있다.
- 비차단 이유: 최소 시험 계획이다. 현재 변경에 계약을 어기는 실행 코드가 없다. 앞선 지적도 비차단이었다.
- 고칠 방향: 세 항목의 포함 여부를 적는다. 사건 변환은 계약의 보고 형식을 가리킨다. 구현 전에 종료 사건 없는 출력 종료의 처리도 시험 범위에 명시한다.

### C3. 조회 흐름에 대응하는 API가 목록에 없다

- 위치: `docs/stage1/compat-test.md:13`, `docs/stage1/compat-test.md:17`.
- 검토 항목: 1·2·12.
- 확신: 높음. 병합 막음: 아니오.
- 근거: 서버 API 넷은 작업 만들기·실행 시도 만들기·청구·사건 받기다. 연결 프로그램의 첫 단계는 할 일 조회다. 계약의 전송 경로도 HTTPS 조회를 요구한다.
- 영향: 두 작업 브랜치가 연결될 때 조회 경로를 추가하거나 초기 전달 방법을 별도로 정해야 한다.
- 비차단 이유: API 상세 명세나 구현이 아직 없다. 계획 보완으로 해결할 수 있다.
- 고칠 방향: 조회 API를 목록에 넣는다. 시험에서 실행 시도 번호를 직접 전달할 의도라면 그 방식을 명시한다.

### C4. 전체 변경의 공백 검사가 실패한다

- 위치: `LICENSE:202`.
- 검토 항목: 12. 저장소 문서 정리.
- 확신: 높음. 병합 막음: 아니오.
- 근거: `git diff --check main..work/bootstrap`의 종료 코드는 2다. 출력은 `LICENSE:202: new blank line at EOF.`다.
- 영향: 공백 검사를 필수 검사로 쓰면 실패한다.
- 비차단 이유: 조항 내용이나 동작의 결함은 아니다. 현재 필수 CI라는 근거는 없다.
- 고칠 방향: 작성 세션이 마지막 빈 줄을 제거한다. 수정 커밋이 생기면 다시 검토받는다.

| `git diff --stat main..work/bootstrap`, 파일별 변경·본문 읽기 | 대상 10개 파일을 검토했다 |
| 허브 판과 `git diff --no-index` | 차이가 있다. 위의 허용 범주와 일치한다. 차이가 있어 종료 코드 1이다 |
| `git check-ignore`, `git check-attr` | 위 표의 기대와 일치한다 |
| Python으로 PR 양식 블록 비교 | `PR_template_exact_match: True` |
| Python으로 `git rev-list`·`git ls-tree`·`git show` 결과 검색 | 다섯 커밋에서 실제 금지 자료를 찾지 못했다 |
| 추적 파일 줄 수 계산 | 최장 파일은 검토 기준 401줄이다. 1,000줄 초과가 없다 |
| `git diff --check main..work/bootstrap` | 실패. 종료 코드 2. C4에 원문을 기록했다 |
| `git -C ../zm-docs rev-parse HEAD` 및 지정 파일 `status --short` | 실패. `detected dubious ownership` 오류다. 설정은 바꾸지 않았다 |

처음 PowerShell 기본 인코딩으로 읽은 한국어는 깨졌다.
이후 UTF-8을 지정해 다시 읽었다.
허브 비교는 디스크의 현재 파일을 기준으로 했다.
허브의 HEAD와 미커밋 상태는 확인하지 못했다.

## 부채 후보와 확인하지 않은 것

규칙을 AGENTS와 검토 기준에 반복하면 일부만 고쳐질 수 있다.
C1이 그 사례다.
설계 허브를 읽을 수 없는 외부 기여자는 근거 번호를 직접 검증할 수 없다.
이는 DEC-0087이 선택한 제약이다.
부채 여부와 대응 시점은 소유자가 정한다.

- PR 본문, 소유자 승인, 판단 이유, CI 결과, 원격 브랜치 보호를 확인하지 않았다.
- 앞선 기록의 원격 상태와 허브 미커밋 상태를 현재 사실로 재사용하지 않았다.
- JDK·Gradle·Go·Docker·Claude Code의 설치 상태나 버전을 재검증하지 않았다.
- 서버·연결 프로그램 빌드와 실행 시험을 하지 않았다.
- Claude Code 명령의 실제 지원 여부를 실행으로 확인하지 않았다. 계약과 계획의 일치만 확인했다.
- macOS·Linux의 체크아웃과 Gradle wrapper 실행 권한을 시험하지 않았다.
- 모든 실행기가 규칙 파일을 자동으로 읽는지 시험하지 않았다. 이 세션에는 사용자가 AGENTS 내용을 직접 제공했다.
- 허브의 모든 G·R·F·V·FN·S 근거를 전수 검토하지 않았다. 지정 결정·계약·기능 단계와 필요한 데이터 모델 부분을 확인했다.
- 전용 비밀값 탐지기는 돌리지 않았다. 형식 검색이 임의의 비밀값 부재를 보장하지 않는다.
- LICENSE를 외부 공식 원문과 비교하지 않았다.

정책 문서가 포함된 변경이다.
소유자는 PR에 판단 이유를 남겨야 한다.
실제 병합 전에는 검토 기준의 결론 조건 5~8과 병합 직전 확인 목록을 충족해야 한다.
