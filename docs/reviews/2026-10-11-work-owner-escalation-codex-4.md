### PR head와 병합 당시 기준점 검증

환경: Windows `10.0.26300.0`, PowerShell `7.6.6`, Git `2.53.0.windows.2`, Codex CLI `0.162.0`, GitHub CLI `2.93.0`.

`git ls-remote origin 'refs/pull/*/head'`는 종료 코드 1로 실패했다. Git의 `sh.exe`가 `CreateFileMapping ... Win32 error 5`를 내고, 이어 `fatal: Could not read from remote repository.`가 나왔다. 원격 조회가 불가능했고 `.git` 쓰기도 허용되지 않아 fetch는 실행하지 않았다. 대신 이미 존재하는 `refs/remotes/origin/pr/1`~`refs/remotes/origin/pr/8`을 사용했다. 이 참조들이 현재 원격 값과 같은지는 확인하지 못했다.

조건별 pathspec은 `docs/review-standard.md:152`부터 `:163`까지의 표에서 추출했다. 「되돌릴 수 없음」 행은 조건 2, 나머지는 조건 1이며 각 패턴에 `:(top,glob)`를 붙였다. 각 PR에 다음 비교를 실행했다.

```text
git merge-base <병합 커밋>^ refs/remotes/origin/pr/<번호>
git diff --no-renames --name-only <위 공통 조상> refs/remotes/origin/pr/<번호> -- <조건별 pathspec>
git diff --no-renames --name-only <병합 커밋>^ <병합 커밋> -- <조건별 pathspec>
```

새 절차는 첫 diff를 사용하므로 보호 경로를 보존한다. 이 PR 계보에 일반 문서 변경이 더 있고 main을 다시 합치지 않았다면 공통 조상은 그대로여서 같은 결과가 된다. 마지막 설명은 Git 계보에 근거한 추론이며, 추가 커밋이나 시험 PR을 만들지는 않았다.

- 원격 PR 본문의 필수 항목·작성자 검증 결과, 초안 여부, 현재 원격 HEAD, CI, 브랜치 보호, 실제 소유자 호출과 병합 결정. 조회 실패로 확인하지 못했고 통과로 간주하지 않았다. 병합 전 확인 담당에게 남는다.
- 원격 `refs/pull/*/head`와 로컬 PR 참조의 일치, 브랜치 삭제 뒤 GitHub의 실제 참조 보존 동작, PR 본문·댓글의 변경 이력. 로컬 객체 비교만 수행했다.
- 실제 호출 누락 건수와 과거 PR의 승인 경위. 가상의 추가 커밋·브랜치·시험 PR·병합은 만들지 않았다.
- 비공개 `zm-docs` 원문과 관련 계약·결정 전체. 사용자가 제공한 DEC-0096 1항과 저장소의 v0.3을 대조했다.
- Linux·macOS·Bash·cmd.exe의 실행 결과, Go·Kotlin·Web·Electron의 빌드·제품 동작·단위·통합·거부 시험과 전체 코드 보안 감사. 이번 변경은 정책 문서이며 제품 동작 시험을 통과했다고 주장하지 않는다.
- 제품 계약·의존성·라이선스·DB·배포 코드 변경과 핵심 모듈 첫 구현은 이번 수정에 없어 해당 검사는 해당 없음이다.
