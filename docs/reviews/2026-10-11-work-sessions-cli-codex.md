- 변경 파일 10개 전체와 관련 시험을 읽었다. 총 추가 2,104줄이며 가장 긴 파일은 `internal/session/session_test.go`의 516줄이다. 손으로 쓴 1,000줄 초과 파일은 이번 변경에 없다.
- 협업 계약 v1 「직접 연 AI 세션을 서버에 등록한다」를 읽고 등록·해제·사건·상대 경로 요구를 대조했다. 비공개 설계 문서의 내용이나 소유자 PC 경로를 이 기록에 복사하지 않았다.
- Claude Code의 훅 입력, `SessionStart`의 `startup/resume/clear/compact`, 시작 출력의 모델 맥락 전달과 훅 timeout 의미는 [공식 훅 문서](https://code.claude.com/docs/en/hooks)에서 확인했다. 특정 Claude Code 버전의 실제 실행을 재현한 것은 아니다.
- 기존 시험에서 설정 키 순서, 다른 도구의 훅과 `&&` 보존, 반복 설치, 기본 제거, 일부 잘못된 JSON 거부, `n` 취소와 백업 생성을 확인했다. 별도 재현에서는 실제 `y` 입력 뒤 저장되는 것도 확인했다. 이는 동시 수정 보존까지 증명하지 않으며 R1에서 실패했다.
- 일반 등록 요청에서 저장소 절대 경로·원격 주소의 userinfo가 제외되고, `file_touch`에서 `_root`를 제거하는 경로를 확인했다. 기존 상대 경로 시험은 저장소 내부·외부·상대 입력과 Windows 대문자 입력을 다룬다.
- 세션 토큰은 세션 상태 파일에 저장되고 사건 API의 Bearer 헤더에 쓰인다. 새 코드에서 공급자 로그인 정보 파일을 읽는 동작은 발견하지 못했다. Unix의 파일 모드 의도는 0600/0700이며 Windows는 사용자 폴더 ACL 상속에 의존한다.
- Git 실행에 `GIT_OPTIONAL_LOCKS=0`과 `GIT_TERMINAL_PROMPT=0`을 설정하는 것을 확인했다. 이것만으로 외부 필터나 자식 프로세스까지 안전하게 종료된다고 확인한 것은 아니다.
- 의존성 파일 변경이나 새 제삼자 코드 고지는 없고, 새 코드는 표준 라이브러리와 기존 내부 패키지를 사용한다. 제삼자 코드의 독립적인 출처 추적까지 수행하지 않았다.

| 설치 확인 대기 중 설정 변경 후 `y` | **보존 요구 실패**. 종료 0이지만 외부 변경과 그 백업이 유실됨(R1) |
| 삭제 공유 없이 열린 오래된 잠금 / 닫히지 않은 stdin | **시간 상한 요구 실패**. 각각 4초 / 5.5초 뒤에도 훅 실행 중. 핸들·입력을 해제한 뒤 종료 0, stdout·stderr 0바이트(R2) |
| 민감정보 표식을 넣은 notification | **비노출 요구 실패**. message가 HTTP 요청에 그대로 포함(R4) |
| 재등록 응답 지연 중 `session off` | **해제 유지 요구 실패**. off 종료 0 뒤 토큰 복구, 후속 요청 1건(R5) |
| 첫 해제 HTTP 503 후 재시도 | **재시도 요구 실패**. 두 명령 모두 종료 1, 서버 요청은 첫 1건뿐(R6) |
| waiting 뒤 compact 재등록과 Bash 도구 완료 | 마지막 도구의 요청 0건, 로컬 waiting=false(R7) |
| 잘못된 인증 포함 서버 URL | 로그에 합성 비밀값 표식 포함, stdout·stderr는 0바이트(R8) |
| 지연되는 Git clean filter로 종료 상한 재현 시도 | **확인 불가**. Git의 `sh.exe`가 `CreateFileMapping … Win32 error 5`로 실행 실패. 짧은 완료 시간을 시간 상한 통과로 인정하지 않음 |

추가 재현은 `python -` 인라인 시험으로, 임시 프로젝트·임시 `ZM_BATON_HOME`·루프백 모의 HTTP 서버·합성 데이터만 사용했다. 실제 사용자 Claude 설정이나 운영 서버를 변경하지 않았다. 잠금 시험은 해당 임시 잠금의 핸들을 닫아 종료시켰고, stdin 시험은 입력을 닫아 종료시켰다.

### 필요한 부정·동시성 시험과 부채 후보

- R1~R6의 재현을 회귀 시험으로 남겨야 한다. 특히 stale 인계는 별도 프로세스 두 개의 교차 순서, 살아 있는 소유자의 지연, 후속 소유자 획득 뒤 이전 unlock까지 다뤄야 한다. Go의 `-race` 통과는 파일 잠금 프로토콜의 안전성 증명이 아니다.
- Windows의 일시적인 삭제 중 `ErrPermission` 처리 분기는 있지만, 그 상황을 강제로 만든 시험은 없다. 상태 파일 교체 실패, 손상된 상태, 저장 실패 뒤 순번·토큰의 일관성도 추가 확인 대상이다.
- 드라이브가 다른 입력, 드라이브 루트의 저장소, UNC, 링크·junction, 특수문자 실행 파일 경로에 대한 시험이 없다. `HookCommand`는 실행 파일을 큰따옴표로만 감싼다(`settings.go:33`). 셸 확장 문자가 있는 설치 경로와 다른 도구의 유사한 실행 파일 이름에 대한 인용·소유권 판별을 점검할 부채 후보가 있다.
- 백업 이름이 초 단위이고 `os.WriteFile`로 기존 백업을 덮어쓸 수 있으며, 설정 임시 파일 이름도 고정이다(`main.go:220`, `:229`). 연속 설치·제거와 동시 실행에서도 복구본을 보존하도록 보강할 부채 후보가 있다.
- 정상 흐름 시험 외에 재등록 응답 역전, 종료·재등록 경쟁, 재개 전송 실패, 서버 응답 손상·크기 초과·redirect, 로그 민감정보 거부 시험이 필요하다. `auth_success` 등 대기가 아닌 알림까지 모두 waiting으로 바꾸는 분류도 검토할 대상이다.
- 계약의 살아 있는 세션 토큰 갱신과 위험 경로 패치 보관은 이 변경에서 구현되지 않았다. 이번에 요청한 CLI 범위 밖의 후속 작업·수락 조건을 명시할 부채 후보이며, 이번 검토를 계약 전체 구현 완료 승인으로 사용하면 안 된다.
- 2,104줄의 변경 분할 검토와 516줄 시험 파일의 유지 이유는 PR 본문에서 확인하지 못했다. 이 이유를 남길 인지부채 후보가 있다. 부채의 최종 판정은 소유자가 한다.

### 확인하지 않은 것

- PR 본문의 필수 여덟 항목, 작성 실행기 버전·실행 계정 종류, CI 결과, 원격 PR HEAD, 소유자 호출·결정 댓글. 명시적 저장소를 지정한 `gh pr view`도 GitHub 연결이 실패했다. 필수 항목이 비었다고 확인한 것은 아니며, 갖춰졌다고 확인한 것도 아니다.
- Linux·macOS 실행과 Linux `-race`, 작성자가 보고한 Docker 및 `GOOS=darwin/windows go vet` 결과의 원본 로그. 작성자 보고를 검토자가 실행한 통과 결과로 기록하지 않았다.
- 실제 Claude Code 훅 설치·실행, 실제 개인 설정 파일, 공급자 로그인 파일, 네트워크 파일시스템, 다른 Windows 사용자로 토큰 파일을 읽는 ACL 거부 시험.
- 별도 `work/sessions-server` PR의 구현·계약 파일과 실제 서버 연동. 서버의 토큰 회전·만료·재사용·재개 시 기다림 처리·역순 사건 정렬·권한 거부는 모의 서버 시험으로 증명하지 않았다.
- 비공개 위협 모델·데이터 모델·결정 기록 전체. 이번에 읽은 설계 정본은 협업 계약 v1의 관련 절이며, 해당 보안 변경에 대한 위협 모델 추적은 PR 작성자가 보완해야 한다.
- 오래된 잠금의 동시 강탈을 강제하는 실행 시험, 실제 Git 작업과의 동시 인덱스 잠금 시험, 정상 실행되는 외부 Git 필터의 시간 제한·하위 프로세스 종료. 해당 미확인을 통과로 표시하지 않았다.
