1. **JSON 구조와 훅 다섯.** `plugin.go:44`가 만드는 marketplace의 `name`·`owner`·`plugins`, 상대 `source: ./zm-baton`, 플러그인의 이름·버전, 기본 위치 `hooks/hooks.json`을 확인했다. 이벤트·명령 인수·제한 시간은 이전과 같다. 생성물에 대해 Claude Code 2.1.296의 marketplace·plugin 검증이 모두 종료 0이었다. marketplace 설명 누락 경고 1개, plugin 경고 0개였으며 이를 기능 지적으로 올리지 않는다. 구조는 [공식 marketplace 형식](https://code.claude.com/docs/en/plugin-marketplaces#create-a-marketplace)과 [플러그인 기본 배치](https://code.claude.com/docs/en/plugins-reference#standard-layout)에 맞는다.
2. **Windows 경로와 명령.** `plugin.go:37`은 훅의 실행 파일 경로를 `/`로 바꾸고 큰따옴표로 감싼다. 공백이 있는 실행 파일·설정 폴더·프로젝트를 사용해 생성물을 확인했다. 출력된 설치·제거 명령을 PowerShell에서 합성 `claude` 함수로 받아, marketplace 경로가 한 인수로 전달되고 local 설치·제거 전에 해당 프로젝트로 이동하는 것을 확인했다. 실제 Claude 설정은 바꾸지 않았다. 셸 특수문자와 Git Bash 없는 환경의 한계는 아래에 별도로 적었다.

- `plugin.go:37`의 셸 의존성을 지원 환경별로 명시하고 시험할 후보다. 현재 1단계 대상은 `docs/stage1/compat-test.md`의 소유자 Windows PC이며 Git Bash가 있다. Git Bash 없는 Windows까지 넓히면 현재 `"<exe>" hook ...`는 PowerShell에서 `UnexpectedToken`으로 파싱에 실패한다. [공식 훅 문서](https://code.claude.com/docs/en/hooks#exec-form-and-shell-form)는 그 환경에서 PowerShell을 기본으로 쓰며, `command`와 `args`를 분리한 직접 실행도 제공한다. 이번에는 기존 HookCommand를 그대로 옮긴 것이고 현재 수락 환경 밖의 호환성 부채로 분류했다. 특수문자 경로 문제 C2와 함께 해결할 수 있다.
- 손으로 쓴 변경 소스는 모두 500줄 미만이며 1,000줄 제한에 걸리지 않는다. 큰 PR의 분할 검토 이유는 PR 본문을 읽지 못했으므로 누락을 확정하지 않는다. 핵심 모듈 2·3은 기존 확장이며, 기록 현황에서 이미 「기록 미작성」이다. 소유자 설명 기록은 대신 작성하지 않았다.

### 검증 기록

대상 커밋은 `559df1377bbcf92864fe2e4ccd045af2b899829b`다. 환경은 Windows `10.0.26300.0`, PowerShell `7.6.6`, Go `go1.27.2 windows/amd64`, Git `2.53.0.windows.2`, Codex CLI `0.162.0`, Claude Code `2.1.296`이다. Go는 발견한 실행 파일의 절대 경로로 호출했으며 캐시는 별도 임시 폴더로 지정했다. 아래 Go 명령의 작업 폴더는 `apps/agent`다.

Go의 버전 확인·시험·빌드 과정에는 텔레메트리 `upload.token` 생성의 `Access is denied` 경고가 있었지만 시험과 빌드 자체는 종료 0이었다. 초기 PATH와 일반 설치 위치에서는 Go를 찾지 못했으며, 이후 발견한 도구로 위 시험·빌드를 실행했다. Python 인라인 시험은 합성 설정과 임시 폴더만 사용했다. Git Bash 실행에서 멈춘 시험의 미실행 뒷부분은 별도 호출로 실행 파일 이동·제거 검증을 마쳤다.

조건 1·2의 보호 경로는 각각 `git diff --no-renames --name-only c0341ff HEAD -- ':(top,glob)…'`로 기준 표 전체를 대조했고 둘 다 출력 0줄이었다. 소유자 호출은 이 경로 검사와 별개인 보안·시크릿 변경 종류 및 이전 호출 판정에 근거한다. 조건 3의 「판정 불가」나 조건 4·5의 이견·면제 시도는 이번에 확인되지 않았다.

### 확인하지 않은 것

- PR 필수 여덟 항목, 작성 실행기 버전·계정 종류의 PR 기재, 원격 HEAD, CI, 초안 여부, 소유자 질문·병합 결정 댓글. 조회 실패는 이 항목들이 갖춰졌거나 빠졌다는 판정이 아니다. 작성자가 병합 직전 확인해야 한다.
- 실제 사용자 Claude 설정에 대한 marketplace 등록·plugin 설치·제거, 설치된 플러그인의 세션 시작·재로드. 공급자 로그인 파일은 읽지 않았다.
- 작성자가 보고한 실제 `claude -p` 등록·상태 카드·파일 변경·종료와 빈 hook.log의 원본 로그 및 재실행. 이는 **작성자 보고**이며 이번 검토자의 통과 결과가 아니다.
- Linux·macOS 실행, Linux Docker race, 각 OS의 vet. 작성자의 gofmt·세 OS vet·Windows test·Linux race 보고를 이번 독립 검증 결과로 바꾸어 적지 않았다.
- 2차 경합 재현 전체, 디스크 I/O 정지, watchdog 도중 파일 작성 중단, Git 하위 프로세스 잔류. 변경되지 않은 부분의 기존 결과와 미확인 범위를 유지했다.
- 비공개 설계 전체와 서버 #11·다른 PR의 전체 재검토. 협업 계약 v1 「직접 연 AI 세션을 서버에 등록한다」의 관련 부분만 대조했으며 비공개 원문과 소유자 PC의 절대 경로를 이 기록에 복사하지 않았다.
