# 재개·입력 보존·모바일 상세 복원 수정 검증

**목적**: TSK-027의 기능 결함 다섯 건을 어떻게 고쳤고 무엇을 시험했는지 남긴다.
**대상·소유자**: 검토자와 hanumoka. **마지막 확인**: 2026-10-15.
**작성자**: Codex, 세션 `01a13c92-51f2-77d2-9414-39fce9e7aefc`. 작성자의 자체 검증이며 독립 승인 기록은 아니다.
**기준판**: `main@24fca69505e1f9bf4c4b9732be869100c2b66e3c`. 아래 결과는 이 문서와 함께 커밋하는 구현에 대한 것이다.

업무 도구의 작업 화면에서 작성 중인 내용을 지키고 선택한 작업을 다시 열 수 있도록, 기존 목록·상세 배치와 공용 부품을 유지하며 동작을 고쳤다. 큰 개편이 아니므로 시안 선택은 추가하지 않았다.

## 수정 내용

| 결함 | 수정과 확인 |
|---|---|
| 두 번 연속 재개할 때 이전 미커밋 변경이 빠짐 | 재개 직전 실행 번호로 폴더를 찾던 것을, 이전 보고의 검증된 전용 브랜치가 가리키는 작업 트리로 바꿨다. 같은 기기·계정과 이전 프로세스 종료 확인 조건은 유지한다. A→B→C 재개에서 A와 B가 남긴 파일을 C에서도 읽는다 |
| 재개 결과가 이전 실행 스냅샷 참조를 덮어씀 | `Workspace.RunID`로 현재 실행 번호를 따로 보관한다. 폴더·브랜치를 재사용해도 스냅샷은 현재 실행 번호의 참조에 남긴다. 두 참조의 SHA와 실제 파일 내용을 대조했다 |
| 자동 조회 때 편집 초안 소실 | 항목 번호가 같으면 편집 폼을 유지하고, 열 때의 필드·버전을 따로 보관한다. 새 버전이 오면 저장을 잠그고 초안을 유지한다. 사람이 「내 수정과 최신 내용 합치기」를 누르면 고친 필드만 최신 자료에 합쳐 다시 확인하고 저장한다 |
| 질문 전송 실패 때 입력 소실 | 상위 동작의 실패를 폼까지 전달한다. 성공한 경우에만 입력을 비우고 폼을 닫으며, 거절 이유는 기존 위치에 표시한다. 같은 동작 경로를 쓰는 편집·대기 사유·위임 양식도 실패하면 후처리를 하지 않는다 |
| 모바일 항목 주소·새로고침의 상세 미복원 | 공용 `useSheet`에 선택 번호와 `useAddress`의 주소 이동 횟수를 넘긴다. 직접 링크·새로고침·주소 이동은 상세를 열지만, 방향키·첫 행 자동 선택·조회로 다음 행을 고르는 동작은 닫힌 시트를 열지 않는다. 작업 외에 결정·문서·첫 화면·세션·계정·조직·감사·위험 목록 화면에도 연결했다 |

현재 실행 번호를 브랜치 이름으로 계속 추론하는 방법은 재개 시 맞지 않아 쓰지 않았다. 서버 보고 형식과 DB 구조는 바꾸지 않았다. 편집의 최신 버전을 자동 채택하면 다른 세션의 변경을 덮어쓸 수 있어 사람의 합치기 동작을 넣었다. 전송 실패를 성공한 Promise로 바꾸는 대신, 오류는 화면이 표시하고 각 폼이 입력을 유지한다.

브라우저 회귀 시험은 다음을 확인한다.

1. 다른 세션의 버전·제목 갱신 뒤에도 초안이 남고, 합치기 전에는 저장할 수 없다.
2. 내가 고치지 않은 제목은 최신 값을 유지하고 내가 고친 필드만 보낸다. HTTP 409 뒤에도 초안을 유지하며 재시도가 성공하면 닫는다.
3. 질문 전송 HTTP 409 뒤 원문이 남고 같은 원문으로 재시도한다. 성공했을 때만 닫는다.
4. 다른 작업을 선택하면 앞 작업의 초안을 섞지 않는다.
5. 390px 직접 링크와 새로고침에서 상세를 연다.
6. 닫은 뒤 5초 조회가 지나도 다시 열지 않으며, 다시 탭해 열고 Esc로 닫으면 원래 행으로 포커스를 돌려준다.
7. 항목 주소 변경·뒤로 가기·앞으로 가기·선택 해제를 따른다.
8. 390px의 편집 충돌 안내와 단추가 가로로 넘치지 않는다.
9. 좁은 폭의 방향키는 행만 고르고, Enter를 눌러야 상세를 연다.
10. 항목 번호가 없는 주소로 넓은 폭에 처음 진입해 첫 행이 자동 선택된 뒤 폭을 줄여도 시트가 열리지 않는다. 항목 번호가 있는 주소의 새로고침·외부 이동은 상세를 여는 별도 경로다.
11. 좁은 폭의 첫 화면에서 판정하면 시트를 닫고 다음 행으로 포커스를 돌려준다.
12. 닫은 첫 화면 항목이 자동 조회에서 사라져 다음 항목이 선택돼도 시트를 열지 않는다.
13. 위험 목록의 직접 링크와 새로고침에서도 상세를 복원한다.

시험 전제는 `apps/web`의 빌드와 Python Playwright·Chromium 설치다. 결과 위치는 `--output <폴더>`로 고른다. 생략하면 OS 임시 폴더를 쓴다. 모든 API를 합성 자료로 응답하므로 운영 서버는 필요 없고 운영 자료에 쓰지 않는다. 실패하면 프로세스는 0이 아닌 코드로 끝나며, 같은 명령으로 재현한다. 시험 작성 중 textarea 내용·단추 안 설명을 포함한 접근성 이름과 시트 안의 중복 제목 때문에 선택자 오류가 있었고 이를 고친 뒤 통과했다. 이를 제품 실패로 세지 않았다.

첫 독립 검토는 `ecab02f`에서 선택 변경을 모두 주소 이동으로 취급하는 회귀를 발견해 병합을 막았다. 지적에 동의해 주소 이동 횟수를 따로 전달했고, 위 9~13번과 직접 링크 닫기의 행 포커스 검사를 추가했다. 판정 원문은 [첫 독립 검토](2026-10-15-work-review-fixes-claude.md)에 보존한다.

[두 번째 독립 검토](2026-10-15-work-review-fixes-claude-2.md)는 `7250b1d`에 병합 가능을 판정했다. 막지 않는 지적 중 10번 시험의 주소 갱신·새로고침 경합은 바로 보정했다. 새 문서에서 항목 없는 주소로 시작하고, 첫 행 주소까지 기록된 것을 확인한 뒤 폭을 줄인다. 이 보정은 제품 코드를 바꾸지 않는다.

## 범위와 남은 확인

Go의 재개 회귀 시험은 실제 Git과 종료 확인 기록을 쓰며 실제 Claude Code 프로세스는 띄우지 않는다. Linux에서는 Windows 전용 종료 시험 일부를 건너뛴다. Windows Go 시험은 PR CI에서 확인한다. 브라우저는 합성 API이며 실제 서버와 연결한 전체 실행, 실제 휴대전화 입력기, 팀 사용자 수백 명, 모든 화면의 주소 복원, axe 접근성 전수 검사는 하지 않았다. 서버·데스크톱 소스는 이번에 바꾸지 않았다.

기존 H-46 개인 기록 내보내기와 모바일 Ctrl+K의 모달 밖 포커스 이동은 별도 고도화 후보로 남긴다. 1단계 실사용 종료 조건과 소유자의 핵심 모듈 설명 기록을 이 시험으로 대신하지 않는다.
