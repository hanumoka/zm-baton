### 고도화 후보 (막지 않음. 목록에 옮길 때 번호는 작성 AI가 붙인다)

- **A. 교체 확인이 화면에만 있다.** 서버는 확인 여부를 받지 않고 발급한다(`LoginAdministration.kt:49-56`).
  - 문제: 오래된 탭이나 API 직접 호출로, 대기 중인 코드를 교체하거나 재설정 코드를 확인 없이 발급할 수 있다.
  - 정도: 소유자가 한 명뿐이라 드문 경합이다.
  - 고치는 방법: 요청에 「교체를 안다」 표시나 예상 상태를 싣고, 맞지 않으면 409로 거절한다.
- **B. 비활성화했다가 다시 활성화하면 기기 토큰이 다시 쓰인다.**
  - 원인: 비활성화는 `web_logins`와 `setup_tokens`만 끝낸다(`Org.kt:242-245`). `Devices.kt:104-113`은 지금 상태만 본다.
  - 문서: 범위는 「웹 로그인과 미사용 코드」로 정확히 적혀 있다.
  - 남는 위험: 소유자는 비활성화로 모든 접근이 끊긴다고 기대할 수 있다. 비활성 사람의 AI 세션 토큰은 확인하지 못했다.
  - 고치는 방법: 비활성화 때 기기를 폐기할지 정한다.
- **C. 여러 조직으로 넓힐 때의 경계.**
  - 원인: 비밀번호는 사람마다 하나(`person_passwords`)인데, 권한은 행위자의 조직으로 판정한다(`LoginAdministration.kt:58-67`, `PermissionFacts.orgOf`는 첫 소속 조직).
  - 위험: 한 사람이 여러 조직에 들면(H-48과 같은 종류) 조직 A의 소유자가 조직 B에서도 쓰는 로그인 정보를 재설정할 수 있다.
  - 때: 서버 관리자와 조직 관리자를 나누거나 복수 조직을 만들기 전에 다시 본다.
- **D. 보이던 코드가 다시 그려지면서 사라진다.**
  - 경우: 30초 갱신 사이에 다른 운영자가 그 사람의 이름·역할·팀을 바꿔 `stamp`가 바뀔 때(`OrgDetail.tsx:29-32`), 또는 배치가 바뀔 때.
  - 결과: 코드는 아직 유효한데 화면에서 사라진다. 소유자가 다시 발급해야 한다. PR 본문은 배치 전환만 적었다.

### 검토 항목 열두 가지

1. **수락 조건**: 채운다(위 중점 표). 기한 지남, 이미 씀, 교체됨, 비활성, 다른 조직, 없는 사람, `local` 모드, 본인이라는 실패 경로를 모두 다룬다. 지적 1·2는 사용성 문제다.
2. **계약**: 협업 계약 v1 「등록과 세션 토큰」 6·7항(사람이 판단하는 일은 웹 인증으로만, 토큰은 해시만)에 맞다. API는 더하기만 했다. 새 끝점 둘이 생겼고, `can_manage_logins`는 기본값 false이며, 웹 타입에서는 선택 항목이다. 설계 규칙 5를 지킨다.
3. **권한**: 중앙 판정기를 거치고, 허용·거부 시험이 있다. 화면은 서버가 준 값(`can_manage_logins`, `can_issue`, `reason`)만 따른다. 자기 권한을 넓히는 경로는 없다. 소유자가 구성원 계정을 넘겨받을 수 있는 것은 재설정 기능의 본질이다. 감사 기록에 발급자와 대상이 남는다.
4. **중복 방지**: 한 번 쓰기는 조건 갱신 한 번으로, 경합은 사람 행 잠금으로 막는다. 프로세스 종료는 해당 없다.
5. **비밀값**: 차이에 비밀값이 없다. 시험 비밀번호는 기존 시험 상수를 참조한다. 캡처와 탐침의 코드는 이름에 「SYNTHETIC…NOT_A_REAL_CREDENTIAL」이 붙은 합성 값이고 저장소 밖에 있다.
6. **로그·보고**: 웹 발급의 감사 기록 행위자가 「서버」에서 「발급한 사람」으로 바뀌어 실제 수행자가 남는다(`Logins.kt:223`). 서버 시작 때 발급은 그대로 시스템이다. 실패를 성공으로 보고하는 경로는 없다.
7. **시험**: 성공 시험과 거부 시험이 있고, 합성 자료와 Testcontainers를 쓴다. 빈틈은 지적 5다.
8. **파일 책임**: 컨트롤러(78줄)와 화면 부품(98줄)을 따로 뒀다. 1,000줄을 넘는 파일은 없다.
9. **의존성**: 추가 없다. Playwright는 저장소 밖 탐침에서만 썼다.
10. **라이선스**: 제삼자 코드가 없다.
11. **부채 후보**: 위 「부채 후보」 절에 적었다.
12. **문서**: 새 절은 전제조건, 단계, 완료 확인, 실패 대응을 갖췄다. 어긋난 문장은 지적 3이다.

**지금도 지키는 선 셋**

1. 차이와 PR 본문에 비밀값·개인 정보·절대 경로가 없다.

3. 서버가 듣는 주소는 바뀌지 않았다.
