## 실제 실행

합성 조직·계정·저장소와 소유자 본인 Claude 구독으로 확인했다. 조직 API 검증으로 계산하지 않는다.

1. 갱신한 서버에서 기존 비밀번호로 로그인해 최초 설정 유지와 서버 관리자 권한을 확인했다.
2. 관리 화면 1440px·390px에서 현재 위치와 내용을 확인하고 가로 넘침이 없음을 검사했다.
3. 웹에서 준비 상태의 새 작업을 만들고 명시적으로 본인 구독 계정을 선택해 합성 README를 읽도록 맡겼다.
4. 브라우저를 닫은 뒤 독립 실행 중인 최신 Go 작업자가 실제 Claude Code를 실행했다. `run_01a14e62-7fa0-7388-a706-576b826bf099`는 `submitted`로 끝났으며 실제 답변에 `baton-independent-server-verified`가 있었다.
5. 브라우저를 새로 열어 해당 작업이 결과 검토 단계임을 확인했다.
6. 실행 중 작업이 0임을 확인한 뒤, 기록된 PID의 정확한 실행 파일·서버 표식을 확인하고 시험판 서버와 작업자만 중지했다. 전달한 시작 스크립트로 고정 판을 다시 띄워 비밀번호 로그인·초기 설정·같은 제출 실행 1건 보존을 확인했다. 기존 운영 설치는 재시작하지 않았다.

최초 브라우저 재확인에서는 선택 요소의 접근성 이름에 계정 설명도 들어 있어 정확한 이름 일치로 찾던 시험 코드가 시간 초과했다. 부분 이름으로 계정 선택 요소를 찾아 전체 흐름을 다시 통과했다. 제품 코드를 바꾸거나 실패를 성공으로 계산하지 않았다.

검증 후 복원용 보조 Java 프로세스와 DB 컨테이너는 고유 표식·라벨을 확인해 중지했고 볼륨·백업은 보존했다. 기존 설치와 최종 시험판은 `health UP`이다. 원본 데이터·비밀번호·브라우저 세션·공급자 로그인 자료와 전체 로그는 공개 사본에 포함하지 않는다.

## 남은 확인

최종 독립 검토 Z1·Z2 뒤 `./gradlew test --tests '*NoticeRecipientsTests' --tests '*MasterCheckTests'`를 실행해 13건을 통과했다. 사용량 시험은 같은 사람의 실제 로그인·CSRF HTTP 요청이 첫 수신 전 403, 반복 수신 뒤 200인지 검사한다. 모순 시험은 수신자 집합·중복 없음과 `NOTICE_JUDGE` 판정을 서비스 호출 전에 검사한다. 제품 런타임 코드는 바꾸지 않았다. 이 후속은 별도 독립 재검토 대상이다.

Z9의 보강으로 원래 V14 백업에서 업그레이드한 뒤 보존한 복제 DB를 다시 시작해 V16·작업 26건·결정 106건·문서 0건을 읽고 중지했다. [선별 결과](assets/2026-10-18-runtime-proof/results.json)에 추가했다. 재확인은 DB 상태의 증거이며 최초 업그레이드 때 서버 `6b320d4`의 건강 상태 확인을 새로 실행한 것으로 계산하지 않는다. 작업자 강제 종료 시험의 서버는 `6b320d4` 기반 PR #48 작업 중 커밋 전 빌드였으므로 안내도 그 범위로 좁혔다.

조직 API 자격, 대상 OS 상시 서비스, 정책·화면 선택, 병합·운영 적용은 소유자 최종 확인에 남긴다. 현재 Windows 시험을 Linux/macOS 프로세스 종료 보장으로 넓히지 않는다. 실제 AI 취소·재개·API 재시작·작업자 강제 종료 복구와 백업·복원의 앞선 증거 범위는 [최종 안내](../stage1/independent-preview-guide.md)에 있다.
