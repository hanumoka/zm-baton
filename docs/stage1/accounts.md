# AI 계정과 사용량 상한 — 1단계 셋째 묶음 셋째 판

맡긴 실행이 어느 AI 계정으로 도는지 고르고, 그 실행이 얼마나 썼는지 세고, 상한에 닿으면 멈추는 기능이다. 계정 등록은 기능 명세 FN-0501, 사용량 상한은 FN-0409(기준 G39.4), 과금 신호는 G39.5다. 근거는 협업 계약 v1의 「실행할 때 넘기는 것」(인증), 「질문과 과금 신호」, 대기 사유 `waiting_limit_reset`·`billing_stopped`, 과금 표시 문서, DEC-0095 5항이다(설계 허브 zm-docs).

- **대상**: 셋째 묶음 첫 판·둘째 판([handoff.md](handoff.md))을 설치한 소유자 PC 한 대.
- **소유자**: 저장소 소유자. 마지막 확인 2026-10-14.
- **전제**: 서버와 연결 프로그램(`zm-baton agent`)을 이 판으로 같이 바꾼다. 옛 연결 프로그램은 계정과 상한을 모르고 예전처럼 돈다(환경 변수를 빼지 않고, 상한 옵션을 넘기지 않는다).

## 계정은 로그인 정보가 아니다

zm-baton 서버에 두는 것은 다음뿐이다. 키 값이나 로그인 토큰은 받지도, 저장하지도, 보고·로그·내보내기에 싣지도 않는다. API 키처럼 보이는 값을 이름·목적·조건 칸에 쓰면 서버와 화면이 둘 다 거절한다.

| 칸 | 뜻 |
|---|---|
| 이름 | 사람이 읽는 이름. 예: 「내 Max 구독」 |
| 종류 | 개인 구독 / 조직 계정 / API 키 |
| 소속 | 개인 구독은 개인, 조직 계정은 조직. API 키는 고른다 |
| 목적, 자료 처리 조건 | 글로 적는다(DEC-0077 1항, FN-0501) |
| 자격 위치 | 구독은 「그 PC의 Claude Code 로그인」, API 키는 「그 PC의 환경 변수 `ANTHROPIC_API_KEY`」. 이름만 둔다 |
| 기기 | 비우면 맡긴 PC. 정하면 그 PC로 맡긴 일에만 쓴다 |
| 상한 | 아래 「상한」 |

다른 이름의 환경 변수에 둔 키를 `ANTHROPIC_API_KEY`로 옮겨 넣는 것은 실행 주입(핵심 모듈 5, 2단계 금고)이라 이 판에는 없다. 계정을 지우지 않고 비활성화한다. 비활성화한 계정에는 새 일을 맡기지 않고, 이미 도는 실행은 끝까지 돈다.

이 판을 처음 띄우면 계정 하나가 생겨 있다: 「이 PC의 Claude Code 로그인」(`acc_owner_login`, 개인 구독). 지금까지 맡긴 일이 돌던 방식 그대로라, 계정을 따로 만들지 않아도 맡기기가 이어진다.

## 단계

### 1. 서버와 연결 프로그램을 바꾼다

[handoff.md](handoff.md) 1·2단계와 같다. 서버가 뜰 때 `V9`가 한 번 적용된다. 표 둘(`ai_accounts`, `usage_signals`)을 더하고, `runs`에 계정·인증 방식·과금 위치·상한·사용량·멈춘 이유 칸을 더하고, 위임의 계정 칸에 외래 키를 걸고, 알림 종류에 `usage_alert`를 더한다. 지우는 것은 없고 이미 있던 기록은 그대로다.

### 2. 계정을 본다·등록한다

1. 웹의 사이드바 아래(설정 자리) 「AI 계정」을 연다. 좁은 화면에서는 「더 보기」 안에 있다.
2. 목록은 「쓸 수 있음 / 멈춤 / 비활성」으로 묶인다. 고르면 오늘 사용량, 상한, 최근 7일, 최근 실행, 이력이 보인다.
3. 새 계정은 「새 계정」을 누르고 이름·종류·목적·조건·상한을 쓴 뒤 「등록하기」를 누른다.
4. API 키 계정이면 맡길 PC에서 `zm-baton agent`를 띄우는 PowerShell 창에 키를 둔다. 키는 zm-baton으로 보내지 않는다.

```powershell
$env:ANTHROPIC_API_KEY = '<Console에서 만든 키>'   # 그 창에만 남는다
zm-baton agent
```

### 3. 맡길 때 계정을 고른다

작업 상세의 「AI에게 맡기기」 양식에 「AI 계정」 칸이 생겼다. 처음 값은 이어 갈 실행의 계정(그 계정이 지금 쓸 수 있으면), 아니면 쓸 수 있는 첫 계정이다. 멈춘 계정은 잠긴 채 이유와 함께 보인다. 칸 아래에 이 실행의 상한과 그 계정의 오늘 사용량이 보인다.

계정을 고르지 않는 옛 화면이나 명령으로 맡기면 서버가 쓸 수 있는 가장 오래된 구독 로그인 계정을 쓴다. API 키 계정은 쓴 만큼 돈이 나가므로 서버가 스스로 고르지 않는다.

### 4. 실행에서 확인한다

실행 기록의 그 실행 칸에 다음이 보인다.

| 칸 | 내용 |
|---|---|
| 계정 | 계정 이름과 실행기가 실제로 쓴 인증 방식(구독 로그인 / API 키) |
| 상한 | 이 실행이 받은 턴·비용·시간. 비용 옆 「(오늘 남은 만큼)」은 그날 남은 하루 상한이 실행 상한보다 작아 그만큼으로 줄었다는 뜻이다 |
| 사용량 | 가격표 환산 비용, 턴, 시간. 그 아래 줄에 토큰(입력·캐시 읽기·캐시 쓰기·출력) |
| 과금 위치 | 구독 한도(5시간·7일 사용 비율) / 추가 사용 / API 과금 / 알 수 없음(확인 불가) |
| 경고 띠 | 상한이나 신호로 멈췄으면 무엇에 닿았는지와 다음에 할 일 |

## 상한

계정마다 넷을 둔다. 비우면 그 상한이 없다.

| 상한 | 처음 값 | 누가 지키나 | 닿으면 |
|---|---|---|---|
| 실행마다 턴 | 200 | Claude Code `--max-turns` | 그 실행이 `error_max_turns`로 끝난다 |
| 실행마다 비용 | 30달러 | Claude Code `--max-budget-usd` | 그 실행이 `error_max_budget_usd`로 끝난다 |
| 실행마다 시간 | 60분 | 연결 프로그램의 시간 재기 | 연결 프로그램이 실행기를 멈춘다 |
| 계정의 하루 비용 | 200달러 | 서버(맡길 때·청구할 때) | 그날 그 계정으로 새 실행을 시작하지 않고, 돌던 실행을 멈춘다 |

- **비용은 청구액이 아니다.** Claude Code가 토큰에 내장 가격표를 곱한 값(`costBasis: list`)이다. 구독 계정이면 돈이 나가지 않는다. 상한을 재는 데만 쓴다. 2026-10-14 Claude Code 2.1.296으로 구독 로그인에서 `--max-budget-usd`가 지켜지는 것을 확인했다(가격표 환산 0.017달러에서 0.01달러 상한으로 멈춤).
- **하루**는 서울 시각 0시에 바뀐다(서버 설정 `zm-baton.usage.day-zone`, 처음 값 `Asia/Seoul`). 실행의 사용량은 결과가 온 날로 센다.
- **실행의 비용 상한은 그날 남은 하루 상한으로 줄어든다.** 청구할 때 서버가 「실행 상한과 오늘 남은 하루 상한 가운데 작은 것」을 넘긴다. 그래서 실행 하나가 하루 상한을 넘기지 않는다. 남은 것이 없으면 청구할 때 시작하지 않는다.
- **비정상 소비**: 최근 60분에 하루 상한의 절반을 넘게 쓰면 같은 방법으로 멈춘다. 60분이 지나 그 사용량이 창 밖으로 나가면 풀린다.
- **처음 값을 넉넉하게 잡은 이유**: 소유자의 작업을 갑자기 멈추지 않기 위해서다. 1단계에서는 맡긴 일 하나가 길어도 몇 달러(가격표 환산)이고, 하루에 여러 개를 맡겨도 하루 200달러에 닿기 어렵다. 실행 시간 60분은 이전 판의 연결 프로그램 기본값(30분)보다 길다. API 키 계정은 실제로 돈이 나가므로 등록할 때 상한을 줄여 두기를 권한다.
- `zm-baton agent --run-timeout`은 이제 기본이 `0`이고, 0이면 계정의 실행 시간 상한을 쓴다. 값을 주면 그것이 더 짧을 때만 쓴다. 서버가 상한을 보내지 않으면 30분이다.

### 닿으면 일어나는 일

1. 그 실행이 멈추거나(실행 상한), 서버가 실행 취소와 같은 길로 멈춘다(하루 상한·비정상 소비·과금 신호). 서버가 멈출 때는 실행을 「중단 요청됨」으로 두고 위임을 철회한다. 연결 프로그램이 다음 임대 갱신(5초 안)에 알아채고 실행기를 멈춘다.
2. 작업에 대기 사유가 붙는다. 상한이면 「한도 리셋 대기」(`waiting_limit_reset`), 추가 과금 신호면 「추가 과금으로 멈춤」(`billing_stopped`). 실행기가 결과를 내기 전에 멈췄으면 「결과 확인 필요」도 함께 붙는다.
3. 「나를 기다리는 것」의 5번 묶음(나머지 알림)에 알림이 생긴다. 실행을 멈춘 알림은 바로 알리고, 계정이 하루 상한에 닿았다는 알림과 한도 근접 알림은 묶어 알린다.
4. 그 작업을 다시 맡기면(「이어서 맡기기」) 두 대기 사유가 떨어진다. 그 계정이 아직 멈춰 있으면 맡기기가 이유와 함께 거절된다.

## 과금 신호

Claude Code는 실행 중에 `rate_limit_event`로 5시간·7일 사용 비율과 추가 사용 상태를 준다(과금 표시 문서). 서버는 다음처럼 처리한다.

| 신호 | 처리 |
|---|---|
| 추가 사용 중(`isUsingOverage`·`overageInUse`가 참, `rateLimitType: overage`이고 허용, `errorCode: credits_required`), 또는 실행기 오류 문구 「draw from your extra usage」·「out of extra usage」 | 그 실행과 그 계정의 다른 실행을 멈춘다. 작업에 `billing_stopped`, 계정에 「추가 과금 멈춤」. 사람이 공급자 쪽을 확인한 뒤 계정 화면의 「추가 과금 멈춤 풀기」를 누르기 전까지 그 계정으로 맡기지 않는다 |
| 공급자 한도 도달(`status: rejected`) | 그 실행과 그 계정의 다른 실행을 멈춘다. 작업에 `waiting_limit_reset`, 계정은 「공급자 사용 한도」로 초기화 시각(`resetsAt`, 없으면 5시간 뒤)까지 맡기지 않는다 |
| 한 창이 90% 이상, 또는 `allowed_warning` | 실행은 계속한다. 계정마다 하루 한 번 묶어 알린다 |
| 그 밖 | 실행에 「구독 한도」와 사용 비율을 남긴다 |

오류 문구는 실행기가 오류를 싣는 자리(결과의 오류)에서만 찾는다. AI가 쓴 답에 같은 문구가 있어도 신호로 보지 않는다. 비용 환산값은 과금 신호로 쓰지 않는다. 신호가 오지 않은 구독 실행은 과금 위치가 「알 수 없음, 확인 불가」로 남는다. API 키 계정의 실행은 「API 과금」이다.

## 인증과 설정 격리

연결 프로그램은 실행기를 띄울 때 계정이 정한 방식 하나만 남긴다(협업 계약 「실행할 때 넘기는 것」 인증, DEC-0095 5항).

1. Claude Code가 로그인 방식을 고르는 순서에 드는 환경 변수(`CLAUDE_CODE_USE_BEDROCK`·`CLAUDE_CODE_USE_VERTEX`·`CLAUDE_CODE_USE_FOUNDRY`·`ANTHROPIC_AUTH_TOKEN`·`ANTHROPIC_API_KEY`·`CLAUDE_CODE_OAUTH_TOKEN`·`ANTHROPIC_PROFILE`) 가운데 고른 방식이 아닌 것을 실행기 환경에서 뺀다. 구독 계정인데 셸에 `ANTHROPIC_API_KEY`가 있으면 그것을 빼므로 키로 과금되지 않는다. 뺀 변수 이름이 실행 기록의 「시작 전 준비 검사」 「계정」 줄에 보인다. 값은 어디에도 남기지 않는다.
2. API 키 계정인데 그 창에 `ANTHROPIC_API_KEY`가 없으면 실행기를 띄우지 않고 준비 검사의 「계정」 미달로 끝낸다.
3. 실행기가 첫 줄(`system`·`init`)에 알리는 `apiKeySource`로 실제 방식을 확인해 끝 보고에 싣는다. 고른 방식과 다르면 실행에 실제 방식을 남기고 바로 알린다.
4. **설정 격리(`CLAUDE_CONFIG_DIR`)는 API 키 계정에만 한다.** 계정마다 zm-baton 설정 폴더의 `executors\<계정 번호>\claude`를 실행 전용 설정 폴더로 넘긴다. 소유자의 개인 지침·스킬·플러그인이 들어오지 않고 세션 기록도 따로 쌓인다. zm-baton은 그 폴더 안의 파일을 열지 않는다.
5. **구독 계정은 격리하지 않는다.** 2026-10-14 Claude Code 2.1.296으로 빈 임시 폴더를 `CLAUDE_CONFIG_DIR`로 주고 `claude auth status`를 보니 `loggedIn: false`였다. 구독 로그인은 설정 폴더에 있어서, 폴더를 바꾸면 로그인이 보이지 않는다. 로그인 파일을 복사하는 것은 금지(AGENTS.md 6절 1항)이고, 실행 전용 폴더에 다시 로그인하게 하면 소유자의 기존 로그인과 같은 저장소를 쓰는지 확인하지 못해 그 로그인을 깨뜨릴 위험이 있다. 대신 `--restricted`가 사용자·프로젝트 설정 파일(권한·훅 설정)을 읽지 않게 하고, `--strict-mcp-config`가 소유자의 MCP 서버를 띄우지 않게 한다(이전 판부터).

## 완료 확인

- 「AI 계정」 화면에 「이 PC의 Claude Code 로그인」이 보이고, 맡긴 일이 끝나면 오늘 사용량과 최근 7일이 늘어난다.
- 실행 기록에 계정·인증 방식·상한·사용량·과금 위치가 보인다.
- 낮은 하루 상한(예: 0.05달러)을 준 계정으로 맡기면 실행이 「오류」로 끝나고, 경고 띠에 「계정의 하루 상한에 닿아 멈췄다」, 작업에 「한도 리셋 대기」, 「나를 기다리는 것」 5번 묶음에 알림이 생긴다. 같은 계정으로 다시 맡기면 이유와 함께 거절된다.

## 실패하면

| 증상 | 원인과 대응 |
|---|---|
| 맡기기가 「… 하루 상한에 닿았다」로 거절된다 | 그 계정의 오늘 사용량이 하루 상한에 닿았다. 계정 화면에서 상한을 올리거나 다른 계정을 고른다. 다음 날 0시(서울)에 다시 센다 |
| 「비정상 소비로 보고 멈췄다」 | 최근 60분에 하루 상한의 절반을 넘게 썼다. 무엇이 썼는지 계정의 최근 실행을 보고, 60분 뒤에 다시 맡기거나 상한을 올린다 |
| 「추가 과금 신호를 받아 멈춘 AI 계정이다」 | 공급자 쪽의 추가 사용 설정과 사용 내역을 확인한다. 괜찮으면 계정 화면의 「추가 과금 멈춤 풀기」를 누른 뒤 이어서 맡긴다 |
| 「공급자의 사용 한도에 닿은 AI 계정이다」 | 표시된 초기화 시각 뒤에 맡기거나 다른 계정을 고른다 |
| 실행이 바로 「오류」, 준비 검사 「계정」 미달 | API 키 계정인데 그 PC에서 `zm-baton agent`를 띄운 창에 `ANTHROPIC_API_KEY`가 없다. 2단계 4번처럼 넣고 다시 띄운다 |

## 이 판이 하지 않는 것

- 자동 계정 전환과 재개(FN-0502, 2단계). 멈추면 사람이 다른 계정을 골라 이어서 맡긴다
- 금고와 실행 주입(핵심 모듈 5, 2단계). 키는 그 PC의 환경 변수에만 있다
- 「추가 과금 때 계속」 조직 설정과 개인 구독의 동의(DEC-0083). 지금은 늘 멈추고 묻는다
- 실행 중 사용량 표시. Claude Code가 결과에만 비용을 실어서, 실행이 끝나야 사용량이 보인다
- 첫 화면에서 사용량 알림을 따로 그리기. 5번 묶음 화면은 다른 작업에서 만든다

## 정리

- 계정을 그만 쓰려면 계정 화면의 「비활성화하기」. 기록은 남는다.
- API 키 계정의 실행 전용 설정 폴더는 zm-baton 설정 폴더의 `executors\`에 있다. 그 계정을 더 쓰지 않으면 지워도 된다. 지우면 그 계정으로 이어서 맡긴 실행은 새 세션으로 시작한다.
- `V9`는 되돌리는 마이그레이션이 없다. 이 판을 통째로 떼려면 [handoff.md](handoff.md)의 「정리」처럼 데이터베이스 볼륨까지 지우고 옛 판으로 다시 띄운다.
