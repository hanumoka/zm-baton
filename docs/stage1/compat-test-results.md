### 통과 기준별 결과

| 기준 | 결과 | 근거 |
|---|---|---|
| 1. 동시 청구는 하나만 성공 | 통과(서버) | 실행 시도 20개에 대해 매번 8개 스레드가 동시에 청구했고, 매번 하나만 성공하고 일곱은 거절됐다. 세대 번호는 1이었다 |
| 2. 옛 세대 보고는 기록만, 상태 불변 | 통과(서버) | 실행 A가 끝난 뒤 실행 B가 세대 2를 받았다. A가 세대 1로 「성공 종료」를 보내자 사건은 저장되고 A에 「늦은 보고 있음」이 붙었다. A의 종료 이유와 B의 상태는 바뀌지 않았다 |
| 3. 같은 사건 번호는 한 번만 저장, 성공 응답 | 통과(서버) | 같은 묶음을 두 번 보내자 두 번째는 저장 0·중복 2로 성공했고, 행은 2개였다 |
| 4. Claude Code 출력이 사건으로 저장 | 아직 | 연결 프로그램(`work/compat-agent`)에서 시험한다 |
| 5. 서버 빌드·시험, 연결 프로그램 빌드 | 서버 통과, 연결 프로그램 아직 | 위 표 |
| 6. 표식이 맞을 때만 실행기 종료 | 아직 | 연결 프로그램에서 시험한다 |

함께 확인한 것: 한 작업에 살아 있는 실행 시도가 있으면 새 실행 시도 만들기가 거절되고(부분 유일 인덱스), 그 실행이 끝나면 다시 만들 수 있다. 알 수 없는 활동 종류, 현재보다 큰 세대 번호, 모르는 `protocol_version`은 거절된다. HTTP로 다섯 API를 차례로 부르는 시험도 통과했다.
