# 1단계 설치·호환 시험 — Web·데스크톱 화면

**목적**: 먼저 시험할 화면 기술 후보(React + TypeScript, Electron)가 이 PC에서 서버와 연결 프로그램이 만든 실행 기록을 보여 줄 수 있는지 확인한다. 결과는 서버·연결 프로그램 시험([compat-test.md](compat-test.md))과 함께 기술 스택 최종 확정을 소유자에게 묻는 근거가 된다. 근거는 `zm-docs`의 DEC-0079 D8과 DEC-0087이다.
**대상 기기**: 소유자의 Windows 11 PC.

## 하는 것

가장 작게 이어 붙인다.

1. **서버 읽기 API 셋**(`apps/server`): 작업 목록, 한 작업의 실행 시도 목록, 한 실행 시도의 사건 목록(`after_seq` 뒤의 것만). 실행 시도의 상태 열은 내주지 않는다. 화면에 보이는 실행 상태는 사건에서 계산한다는 협업 계약 v1의 규칙을 지키기 위해서다.
2. **Web 화면**(`apps/web`, React + TypeScript, Vite)
   1. 작업 목록을 2초마다, 고른 실행 시도의 새 사건을 1초마다 묻는다.
   2. 실행 상태(시작 전·실행 중·끝남)를 사건에서 계산해 보여 준다.
   3. 사건 내용은 실행기 출력이므로 글자로만 보여 준다. HTML로 해석하지 않는다.
   4. 작업과 실행 시도를 만드는 입력란이 있다.
3. **서버가 화면을 함께 내준다**: `ZM_BATON_WEB_DIR`에 빌드한 화면 폴더를 주면 서버가 같은 주소에서 화면을 내준다. 화면과 API의 출처가 같아 CORS 설정이 필요 없다.
4. **데스크톱 껍데기**(`apps/desktop`, Electron)
   1. 서버가 내주는 화면을 창에 띄운다.
   2. 창에는 Node 기능을 주지 않는다(`contextIsolation`, `sandbox`, `nodeIntegration: false`).
   3. 서버 밖 주소로의 이동과 새 창은 막고, 콘텐츠 보안 정책을 붙이고, 권한 요청은 거부한다.
   4. Windows 실행 파일 폴더로 묶는다(`@electron/packager`).

## 통과 기준

1. Web 화면의 타입 검사·단위 시험·빌드와 데스크톱 껍데기의 컴파일·묶기가 이 PC에서 된다.
2. 서버가 빌드한 화면과 그 자원 파일을 내준다.
3. 연결 프로그램이 실제 Claude Code를 돌리는 동안, 데스크톱 창의 실행 상태가 시작 전 또는 실행 중에서 끝남으로 바뀌고 사건 수가 서버에 저장된 수와 같다.
4. 데스크톱 창 안의 페이지에서 Node 기능(`require`, `process`)이 보이지 않는다.
5. 묶은 실행 파일이 같은 화면을 연다.

## 하지 않는 것

인증과 로그인 화면, 작업 단계 바꾸기, 질문 답하기, 실시간 알림(WebSocket), TUI, 자동 업데이트·코드 서명·설치 프로그램, macOS·Linux 빌드, 접근성 점검, 화면 디자인. 이 시험 뒤 1단계 작업으로 한다.

## 기록할 것

- 도구 버전(Node, npm, React, TypeScript, Vite, Vitest, Electron, Chromium)
- 새 의존성의 라이선스
- 통과 기준별 결과와 실행한 명령
