# 1단계 설치·호환 시험 계획

**목적**: 먼저 시험할 기술 후보가 이 PC에서 협업 계약 v1의 핵심 흐름을 돌릴 수 있는지 확인한다. 결과로 기술 스택 최종 확정을 소유자에게 묻는다. 근거는 `zm-docs`의 DEC-0079 D6~D8과 DEC-0087이다.
**대상 기기**: 소유자의 Windows 11 PC. 중앙 서버 상시 운영(M1 Pro)은 이 시험에 넣지 않는다.

## 하는 것

가장 작게 이어 붙인다.

1. **PostgreSQL**: `deploy/compose`의 Docker Compose로 띄운다.
2. **서버**(`apps/server`, Kotlin + Spring Boot)
   1. 마이그레이션으로 `work_items`, `runs`, `run_events` 세 테이블만 만든다. 한 작업에 살아 있는 실행 시도를 하나로 막는 부분 유일 인덱스를 넣는다.
   2. API는 다섯이다. 작업 만들기, 실행 시도 만들기, 할 일 조회, 실행 권리 청구, 사건 받기. 연결 프로그램은 할 일 조회를 짧은 주기로 반복한다. WebSocket 깨우기 신호는 이 시험에 넣지 않는다.
   3. 청구는 조건부 갱신 한 번으로 하고, 성공하면 작업의 세대 번호를 1 올린다.
   4. 사건 받기는 같은 사건 번호를 한 번만 저장하고, 옛 세대 번호의 보고는 상태를 바꾸지 않는다.
3. **로컬 연결 프로그램**(`apps/agent`, Go)
   1. 할 일을 조회하고 청구한다.
   2. `claude -p --output-format stream-json --verbose --session-id <실행 시도마다 만든 UUID>`를 셸 없이 직접 띄우고 PID를 기록한다. 세션 번호가 종료 전 확인용 표식이다. 화면 없는 승인 요청은 거부(`--permission-prompts none`)하고, 허용 도구는 `--allowedTools`로 좁힌다. 작업 폴더는 임시 폴더 밖에 둔다(F02 1차 실험, 협업 계약 v1 「실행할 때 넘기는 것」·「프로세스 관리」).
   3. 출력 한 줄을 협업 계약 v1 「보고 한 건의 모양」의 사건 하나로 바꿔 서버에 보낸다. `kind`는 활동 일곱 가지 가운데 하나이거나 시작·종료를 뜻하는 `lifecycle`이다.
   4. 끝났다는 사건을 보내고 실행 시도를 끝낸다.

## 통과 기준

1. 같은 작업을 두 연결 프로그램이 동시에 청구하면 하나만 성공한다.
2. 옛 세대 번호로 온 보고는 사건으로 기록되고 그 실행 시도에 「늦은 보고 있음」 표시가 붙는다. 작업 상태는 바뀌지 않는다.
3. 같은 사건 번호를 다시 보내면 서버가 성공을 돌려주고, 사건은 한 번만 저장된다.
4. Claude Code 실행 출력이 사건으로 저장되고, 끝났다는 사건이 온다.
5. 이 PC에서 서버 빌드와 시험, 연결 프로그램 빌드가 된다.
6. 실행 중인 실행기를 끝낼 때, 기록한 PID의 명령줄에 그 실행 시도의 세션 번호가 있을 때만 끝낸다. 표식이 없거나 비어 있으면 끝내지 않는다.

## 하지 않는 것

인증, 권한, 위임, 요청 번호(`request_id`)로 같은 요청 거르기, 작업의 `version` 검사, WebSocket 깨우기 신호, 끝났다는 사건 없이 끊긴 실행의 판정과 재개, 화면(Web·TUI), 기억, 충돌 알림, Codex·Grok 어댑터, 임대 갱신(15초)과 기기 생존 판정(5분), 보내지 못한 사건의 디스크 보관, 순번 빈 곳 재요청, 외부 동작 기록. 이 시험 뒤 1단계 작업으로 한다. Web·데스크톱 후보(React + TypeScript, Electron, D8)는 이 시험에서 다루지 않고 따로 시험한다.

## 기록할 것

- 도구 버전(JDK, Gradle, Spring Boot, Go, PostgreSQL, Docker, Claude Code)
- 각 단계에 걸린 시간과 막힌 것
- 통과 기준별 결과와 실행한 명령
