# 문서 모순 후보 — 마스터가 문서·결정 사이의 어긋남을 찾아 알린다

1단계 필수 기능 「중앙 마스터」(FN-0401)의 최소판 가운데 남은 절반이다. 작업 충돌 알림(같은 파일을 고친 두 세션, [sessions.md](sessions.md))에 이어, 승인된 문서판과 채택된 결정이 다른 문서·결정과 어긋나 보이면 그 두 문장을 근거로 첫 화면에 알린다. 근거는 설계 허브 zm-docs의 협업 계약 v1 「충돌을 찾아 관계자에게 알린다 > 문서 모순 후보」·「알림 처리」, DEC-0086 1항, DEC-0095다.

- **대상**: 문서([documents.md](documents.md))와 여기서 만든 결정([work-and-decisions.md](work-and-decisions.md))을 쓰는 소유자 PC 한 대. 서버는 이 PC의 `127.0.0.1`에서만 받는다.
- **소유자**: 저장소 소유자. 마지막 확인 2026-10-14.
- **전제**: 기본 경로로 돌리려면 그 PC에서 `zm-baton login`을 했고 `zm-baton agent`가 떠 있어야 한다([handoff.md](handoff.md)). 마스터 실행은 저장소가 필요 없으므로 `zm-baton repo add`는 하지 않아도 된다.

마스터가 내는 것은 늘 **후보**다. 최상위 모델도 일부러 넣은 모순의 일부만 찾는다(DEC-0095 맥락). 알림은 일을 막지 않고, 사람이 읽고 판정한다.

## 언제 도는가

| 일어난 일 | 마스터 실행 | 이유 |
|---|---|---|
| 제품 안 문서의 판을 승인했다 | 그 판 하나를 대상으로 하나 | 계약 「문서 모순 후보」 1 |
| 여기서 만든 결정을 채택했다 | 그 결정을 대상으로 하나 | 같은 곳 |
| 다른 결정을 대체하는 결정을 채택했다 | 새 결정을 대상으로 하나. 대체된 결정은 비교하지 않는다 | 대체된 결정은 더 이상 유효하지 않다 |
| `zm-baton import zm-docs --apply`가 채택된 결정을 새로 들이거나 본문을 바꿨다 | 바뀐 결정이 1~3건이면 가져오기 한 번에 **하나로 묶어** 하나. 4건 이상이면 만들지 않고 「건너뜀」과 이유를 남긴다 | 평소 가져오기(새 결정 몇 건)는 잡고, 첫 가져오기처럼 수십 건이 바뀌면 비교 범위가 너무 커 후보 품질이 떨어지고 소유자 구독을 한꺼번에 쓰기 때문이다. 상한은 설정 `ZM_BATON_MASTER_IMPORT_LIMIT` |
| 결정을 기각했다, 제안을 고쳤다, 새 판을 썼다(승인 전) | 없음 | 정본이 바뀌지 않았다 |
| Git 문서의 판을 승인했다 | 「건너뜀」 | 본문이 Git에 있고 서버에는 없어 비교할 수 없다 |
| 가져오기 미리 보기(`--apply` 없음) | 없음 | 서버가 되돌리는 처리라 아무것도 바뀌지 않았다 |

승인·채택이 끝난 **뒤에** 따로 처리하므로, 마스터 쪽에 문제가 생겨도 승인·채택은 그대로 남는다.

## 무엇과 비교하는가

1. 대상의 프로젝트에 속한 문서(승인된 가장 새 판)와 채택된 결정, 그리고 대상과 이어진 문서·결정(문서의 「관련 결정」)이 후보 풀이다. 대상에 프로젝트가 없으면 조직의 모든 문서·결정이 풀이다.
2. PostgreSQL 전문 검색으로 대상 글의 자주 나오는 낱말(30개까지)과 겹치는 것을 고른다. 이어진 것이 먼저, 그다음 검색 순위다. 겹치는 낱말이 없는 것은 고르지 않는다. 1단계에는 벡터 검색이 없다.
3. 최대 5개(`ZM_BATON_MASTER_COMPARE_LIMIT`)다. 비교할 것이 하나도 없으면 「건너뜀」이다.
4. 마스터에게 주는 글의 길이는 대상 12,000자, 비교 자료 하나 6,000자까지다. 넘으면 앞부분만 주고 그렇다고 적는다.

PostgreSQL의 `simple` 설정은 한국어 어미를 떼지 못해서, 조사(`은`·`는`·`을`·`에서` 등)를 떼고 앞부분 일치로 찾는다. 한국어 검색 품질은 이 정도가 한계다.

## 어떻게 도는가 — 경로 둘

마스터 실행도 다른 실행과 같은 계약(청구·세대 번호·보고)을 따른다. 그래서 마스터 판단은 **소유자의 작업**이 된다. 작업 화면에 `모순 후보 찾기: 문서 「…」 판 N` 같은 작업이 생기고, 실행 기록에서 실행 상태·사용량·끝난 이유를 볼 수 있다. 1인 조직은 결과 검토 단계를 건너뛰므로 실행이 결과를 내면 그 작업은 완료로 넘어간다.

| | 기본: 이 PC의 연결 프로그램 | API 키가 있을 때: 서버 |
|---|---|---|
| 켜지는 조건 | 늘. API 경로가 꺼져 있거나 실패했을 때 | 서버의 환경 변수 `ZM_BATON_MASTER_API_KEY`(이름은 바꿀 수 있다)에 값이 있을 때만. 기본은 꺼짐 |
| 누가 돌리나 | 서버가 가장 최근에 맡긴 일을 청구한 기기(없으면 마지막으로 보인 기기)에 위임한다. 그 기기의 `zm-baton agent`가 가져간다 | 서버가 직접 청구한다(기기 없음) |
| 무엇으로 | 소유자 본인 구독의 Claude Code 로그인. AI 계정은 사람이 맡길 때와 같은 규칙으로 고른다(지금 쓸 수 있는 구독 로그인 계정) | API 키. 저가 모델(`claude-haiku-5-5`)이 후보를 찾고, 남은 후보가 있으면 강한 모델(`claude-opus-5-5`)이 한 번 더 확인한다 |
| 권한 | 비어 있는 전용 폴더(`zm-baton` 설정 폴더의 `master/<실행 번호>`)에서 읽기 도구(Read·Glob·Grep)만, `--restricted`·`--strict-mcp-config`로 돈다. 읽을 파일이 없다. 비교할 글은 모두 지시 안에 표준 입력으로 넘긴다. 끝나면 비어 있는 폴더를 지운다 | 도구 없음. 답의 모양을 JSON 스키마로 고정한다 |
| 답이 오는 길 | 실행기의 마지막 답을 끝 보고(`result`)에 실어 보낸다 | 같은 모양으로 서버가 스스로 보고한다 |
| 상한 | AI 계정의 상한(#32)과 마스터 상한 가운데 작은 쪽: 턴 5, 10분, 가격표 환산 2달러 | 요청마다 `max_tokens` 8,000. AI 계정을 정해 두면(`ZM_BATON_MASTER_API_ACCOUNT`) 그 계정의 하루 상한도 걸린다 |

연결 프로그램이 이 기능보다 오래된 판이면 마스터 실행을 가져가지 않는다(저장소가 없는 실행이라 「등록되지 않은 저장소」로 보고 건너뛴다). 연결 프로그램을 새 판으로 바꾼다.

## 몇 번까지 도는가

- 자동 실행은 **하루 5회**(`ZM_BATON_MASTER_DAILY_LIMIT`, 0이면 끈다)다. 하루는 사용량 상한과 같은 시간대(기본 `Asia/Seoul`)의 0시부터다. 「건너뜀」은 세지 않는다.
- 상한에 닿으면 그날의 나머지 승인·채택은 「건너뜀: 오늘 자동 모순 찾기 5회를 다 썼다」로 남는다.
- 시작값을 넉넉하지 않게 잡은 것은 이 실행이 소유자 구독(또는 API 크레딧)을 사람이 누르지 않아도 쓰기 때문이다. 실제로 써 보며 올리거나 내린다.

## 후보를 어떻게 거르는가

마스터는 후보마다 양쪽 자료의 문장을 그대로 옮겨 답한다. 서버가 다음을 확인하고 하나라도 어긋나면 그 후보를 버린다. 버린 수와 이유는 실행 결과(`master_checks.outcome`)에 남는다.

1. 두 쪽이 마스터에게 준 자료의 표시(S1, C1 …)를 가리키고, 서로 다른 기록이며, 한쪽은 이번에 바뀐 자료(S)다.
2. 옮긴 두 문장이 4자 이상 400자 이하이고, **마스터에게 준 그 글 안에 그대로 있다**. 줄 바꿈과 공백 수, Markdown의 굵게·코드 표시, 문장을 감싼 따옴표는 따지지 않는다.
3. 같은 두 문장이 두 번 나오면 하나만 남긴다. 한 실행에서 10개까지만 남긴다.

답이 정해진 JSON 모양이 아니면 그 실행은 실패로 남는다.

## 알림과 판정

| 무엇 | 어디 |
|---|---|
| 남은 후보 | 첫 화면 5번 묶음 「표본 검토와 나머지 알림」에 「모순 후보」로 놓인다. 알림은 묶어 알린다(계약 「알림과 집중 모드」 2) |
| 상세 | 어긋나 보이는 두 문장(각 문장 위에 그 문서판·결정으로 가는 링크), 마스터가 본 이유, 찾은 경로와 마스터 실행 기록 링크, 판정 단추 셋 |
| 판정 | 확인(「확인함」으로 남는다) / 모순 아님(이유를 적어야 보낸다) / 해결(기록을 고쳐 어긋남이 사라졌다). 판정하면 첫 화면에서 빠진다. 서버 API는 충돌과 같은 `POST /api/notices/{id}/status`다 |
| 문서·결정 화면 | 상세의 「할 수 있는 일」 아래에 「열린 모순 후보」(판정 전·확인함)와 그 기록으로 시작한 마지막 모순 찾기의 결과를 보인다. 판정 전 후보는 「나를 기다리는 것에서 판정」으로, 확인함은 「고쳤으니 해결로 남기기」로 처리한다 |

- **관계자**는 두 기록의 소유자다(문서는 소유자, 여기서 만든 결정은 주도자). 1단계는 소유자 한 명이라 첫 화면 항목도 소유자에게만 간다.
- **같은 근거**는 두 기록(판이 아니라 문서·결정)과 두 문장이 같은 것이다. 다시 나오면 새 알림을 만들지 않고 반복 수만 올린다. 「해결」로 판정한 것이 다시 나오면 다시 열려 첫 화면에 돌아온다. 「확인함」과 「모순 아님」은 판정한 그대로 둔다.
- 모든 단계는 감사 기록에 남는다: `master_check.requested`·`skipped`·`fallback`·`done`·`failed`, `notice.raised`·`reopened`, 사람의 `notice.acknowledged`·`not_a_conflict`·`resolved`.

## 실패하면

| 증상 | 무엇이 일어났나 | 대응 |
|---|---|---|
| 「연결 프로그램이 8시간 안에 가져가지 않았다」 | 위임 기한(8시간) 안에 `zm-baton agent`가 돌지 않았다. 실행은 취소로 끝나고 마스터 작업은 취소로 닫힌다 | 그 PC에서 `zm-baton agent`를 띄워 둔다. 다시 찾게 하려면 문서는 새 판을 승인한다(다시 찾기 단추는 아직 없다) |
| 「마스터 실행이 끝났지만 결과가 없다(취소)」 | 사람이 실행 기록에서 실행을 취소했거나 맡긴 일을 거뒀다 | 같다 |
| 「마스터의 답을 정해진 JSON 모양으로 읽지 못했다」 | 실행기가 JSON 대신 글로 답했다 | 그 실행의 「최근 활동」에서 답을 본다. 자주 일어나면 알린다 |
| 「끝 보고에 답이 없다」 | 연결 프로그램이 이 기능보다 오래된 판이다 | 연결 프로그램을 새 판으로 바꾼다 |
| 「마스터 실행을 맡길 AI 계정이 없다」로 건너뜀 | 구독 로그인 계정이 멈췄다(하루 상한·공급자 한도·추가 과금 신호·비활성) | AI 계정 화면에서 멈춘 이유를 본다([accounts.md](accounts.md)) |
| API 경로가 HTTP 402·429·529 등으로 실패 | 크레딧이 바닥났거나 API가 멈췄다 | 서버가 같은 작업을 이 PC의 연결 프로그램에 넘긴다(DEC-0095 2항). 실행 기록에 실패한 API 실행과 이어 맡긴 실행이 함께 보인다 |

## API 경로를 켜는 법과 비용

API 경로는 소유자가 키를 직접 넣을 때만 켜진다. zm-baton은 키 값을 받지 않고, 서버는 요청을 보낼 때 환경 변수에서 읽기만 한다. 저장·기록·내보내기에는 남지 않는다.

1. claude.ai 결제 화면에서 Console 조직을 연결하고 API 키를 만든다. 자동 충전은 끈다(DEC-0095 후속 조치).
2. 서버를 띄우는 환경에 `ZM_BATON_MASTER_API_KEY`로 키를 넣는다. 다른 이름을 쓰려면 `ZM_BATON_MASTER_API_KEY_ENV`에 그 **이름**을 준다.
   - 소스로 띄운 서버([run-locally.md](run-locally.md))는 그 PowerShell 창에서 변수를 정한 뒤 띄운다.
   - Docker로 설치한 서버(`deploy/compose/compose.yaml`)는 지금 이 변수를 컨테이너에 넘기지 않는다. 넘기려면 배포 설정을 고쳐야 하므로 이 PR에서는 바꾸지 않았다. 켜기로 하면 소유자가 그 줄을 정한다.
3. 켜졌는지는 `Invoke-RestMethod http://127.0.0.1:18081/api/settings/master`의 `api_path`가 `True`인지로 본다. 키 값은 이 응답에도 없다.
4. (선택) API 키 계정을 AI 계정 화면에 등록하고 그 번호를 `ZM_BATON_MASTER_API_ACCOUNT`에 주면, API 경로의 가격표 환산 비용이 그 계정의 하루 상한에 들어간다.

비용은 가격표 기준으로 실행 기록에 남는다(100만 토큰당 입력/출력: `claude-haiku-5-5` 0.10/0.50달러, `claude-opus-5-5` 4.00/20.00달러, `ZM_BATON_MASTER_API_PRICES`로 바꾼다). 한 번 실행은 비교 자료 5개를 다 쓰면 입력이 2만 토큰 남짓이라 저가 모델만 돌면 1센트 아래, 강한 모델 확인까지 가면 10센트 안팎이다. DEC-0095는 1인 조직의 월 사용량을 저가 0.35~3.2달러, 강한 모델 6.4~68달러로 추정했다. 하루 5회 상한이면 그 범위 안이다. 2026-10-14 진짜 Claude Code 2.1.299로 로컬 경로를 한 번 돌렸을 때(문서 하나와 결정 둘 비교) 1턴, 6초, 가격표 환산 0.21달러였다. 구독 로그인이라 청구되지 않는 환산값이다.

## 설정

모두 서버 설정이다. 화면에서는 바꾸지 않는다(사람 인증이 없어서다). 읽기는 `GET /api/settings/master`.

| 환경 변수 | 시작값 | 뜻 |
|---|---|---|
| `ZM_BATON_MASTER_DAILY_LIMIT` | 5 | 하루 자동 실행 수. 0이면 끈다 |
| `ZM_BATON_MASTER_COMPARE_LIMIT` | 5 | 한 번에 비교하는 문서·결정 수(1~20) |
| `ZM_BATON_MASTER_IMPORT_LIMIT` | 3 | 가져오기 한 번에 묶는 결정 수. 넘으면 만들지 않는다 |
| `ZM_BATON_MASTER_MAX_TURNS`, `_MAX_MINUTES`, `_MAX_BUDGET_USD` | 5, 10, 2.00 | 마스터 실행 하나의 상한. 계정 상한이 더 작으면 그것을 쓴다 |
| `ZM_BATON_MASTER_API_KEY_ENV` | `ZM_BATON_MASTER_API_KEY` | API 키를 읽을 환경 변수의 이름 |
| `ZM_BATON_MASTER_API_SCREEN_MODEL`, `_CONFIRM_MODEL` | `claude-haiku-5-5`, `claude-opus-5-5` | API 경로의 두 모델 |
| `ZM_BATON_MASTER_API_ACCOUNT` | 없음 | API 경로 비용을 셀 AI 계정 |

## 확인하는 방법

1. 같은 프로젝트에 승인된 문서나 채택된 결정이 있는 상태에서, 그것과 어긋나는 문장을 담은 문서판을 승인한다.
2. 작업 화면에 `모순 후보 찾기: …` 작업이 생기고, `zm-baton agent`가 가져가 실행한다(수 초).
3. 5초 안에 첫 화면 5번 묶음에 「모순 후보」가 놓이고, 그 문서 상세의 「열린 모순 후보」에도 보인다.
4. 「모순 아님」을 누르고 이유를 적어 보내면 첫 화면에서 빠지고, 문서 상세의 열린 후보 수가 줄어든다.

## 이 판이 하지 않는 것

- 다시 찾기 단추, 마스터가 찾은 후보를 사람이 고쳐 쓰기
- Git 문서 본문의 비교(서버에 본문이 없다), 벡터 검색, 팀원별 관계자 분리(1단계는 소유자 한 명)
- 공유 범위 관찰·Slack 전달·공지 묶기(계약 「1단계 밖으로 미룬 것」, 3단계)
- 다른 모델 연결(다른 공급자 API 키, 로컬 LLM, OpenRouter)은 조직 선택지(DEC-0095 3항)로 남아 있고 아직 없다
