# 문서 — 정본 위치와 문서판·승인 쓰기

1단계 필수 기능 「문서 정본 지정」(FN-0601)과 「문서판과 승인」(FN-0602)의 첫 판이다. 웹에 「문서」 화면이 생긴다. 문서마다 정본 위치를 하나로 정한다. 제품 안 문서는 zm-baton이 Markdown 본문과 판을 갖고, Git 문서는 저장소 파일이 정본이라 zm-baton은 경로와 커밋만 기록한다. 판마다 승인 상태(초안 / 승인됨)가 있고, 문서는 영향 받는 작업과 관련 결정에 이어진다. 근거는 권장 기준 G20.1(새 업무 문서는 제품 안, 기존 Git 문서는 Git 정본 유지, 문서마다 정본 위치 하나)·G46.5(제품 안 문서도 Markdown 원문)와 데이터 모델의 `documents`·`document_versions`·`approvals`다(설계 허브 zm-docs).

- **대상**: 둘째 묶음([work-and-decisions.md](work-and-decisions.md))을 설치한 소유자 PC 한 대. 서버는 이 PC의 `127.0.0.1`에서만 받는다.
- **소유자**: 저장소 소유자. 마지막 확인 2026-10-14.
- **전제**: `work/decisions-write`(여기서 만든 결정)와 `work/documents`가 함께 들어간 판에서 따른다. 문서의 「관련 결정」이 결정 쓰기에 기댄다.

## 정본 위치에 따라 다르게 동작한다

| | 제품 안 문서 | Git 문서 |
|---|---|---|
| 본문 | zm-baton이 판마다 Markdown으로 갖는다 | 저장소 파일에 있다. zm-baton은 갖지 않는다 |
| 새 판 | 「새 판 쓰기」로 본문을 고쳐 저장한다 | Git에서 고치고 커밋한 뒤 「새 커밋 기록」으로 그 커밋을 남긴다 |
| 화면의 본문 자리 | 고른 판의 본문을 그려 보인다 | 「읽기만 한다」와 저장소·경로·브랜치, 판의 커밋을 보인다 |
| 승인 | 판마다 승인한다 | 판(커밋)마다 승인한다 |
| 정본 위치 바꾸기 | 없음(아래 「이 판이 하지 않는 것」) | 없음 |

판은 1부터 쌓인다. 새 판은 늘 초안으로 시작하고, 승인자가 그 판을 한 번 승인한다. 새 판을 써도 앞 판의 승인은 그대로다. 그래서 「현재 판」(가장 새 판)과 「승인된 판」(승인된 판 가운데 가장 새 것)이 다를 수 있고, 화면 머리가 둘을 함께 보인다. 1단계 승인자는 소유자(`usr_owner`) 한 명이다. 승인자를 정하는 곳은 서버의 한 함수(`ApprovalPolicy.approverFor`)이고, 승인은 결정과 같은 승인 기록 표(`approvals`)에 남는다.

## 무엇이 어디에 뜨는가

| 무엇 | 어디 |
|---|---|
| 「문서」 화면: 승인 상태로 묶은 목록(승인 기다림 / 승인됨 / 판 없음), 목록 머리의 「새 문서」, 거르기 칩(프로젝트·정본 위치), 입력줄로 제목·Git 경로 찾기 | `http://127.0.0.1:18081/#documents`. 사이드바의 「결정」 아래. 좁은 폭에서는 아래 탭 줄의 「더 보기」 안 |
| 문서 상세: 정본·현재 판·승인된 판·프로젝트·소유자, 할 수 있는 일(새 판 쓰기 또는 새 커밋 기록, 판 승인하기, 문서 정보 고치기), 고른 판의 본문, 판 목록, 옆 칸의 영향 받는 작업·관련 결정·이력 | 같은 화면의 오른쪽(좁은 폭은 시트). 고른 문서와 판은 주소(`#documents?item=…&ver=…`)에 남는다 |

## 전제조건

- 둘째 묶음이 설치돼 돌고 있다(서버·웹이 Docker `zm-baton-dev`로 실행 중).
- PowerShell에서 `$repo`에 이 저장소 루트를 담는다.

## 단계

### 1. 서버와 웹을 새 판으로 다시 띄운다

```powershell
cd $repo
git pull --ff-only
docker compose -f deploy/compose/compose.yaml --profile app up -d --build
```

서버가 뜰 때 데이터베이스 구조 변경 `V6`(문서·문서판·문서와 작업 잇기·문서와 결정 잇기 표 추가, 승인 기록이 문서판도 받게 검사 넓힘, 지우는 것 없음)이 한 번 적용된다. 앞의 `V5`(결정 쓰기)가 아직이면 함께 적용된다.

### 2. 제품 안 문서를 써 본다

1. `http://127.0.0.1:18081/#documents`를 연다. 아직 문서가 없으면 「아직 등록한 문서가 없다」와 「새 문서 등록하기」가 보인다.
2. 「새 문서」를 누른다. 제목을 쓰고 정본 위치는 「제품 안」 그대로 둔다. 「첫 판 본문」에 Markdown을 쓰고 「미리보기」로 그려진 모양을 본다. 「영향 받는 작업」과 「관련 결정」에서 하나씩 잇고 「문서 등록하기」를 누른다.
3. 목록의 「승인 기다림」에 「판 1 초안」으로 들어간 것을 본다. 상세에서 「판 1 승인하기」를 누른다. 「승인됨」으로 옮겨 가고 판 목록에 승인한 사람과 시각이 남는다.
4. 「새 판 쓰기」를 누른다. 판 1의 본문에서 시작한다. 본문을 고치고 판 메모를 쓴 뒤 「판 2 저장」을 누른다. 머리의 현재 판이 「판 2 초안」, 승인된 판이 「판 1」이 된다. 판 목록의 「판 1 보기」로 옛 본문을 보고, 브라우저의 뒤로 가기로 돌아온다.

### 3. Git 문서를 등록해 본다

1. 「새 문서」에서 정본 위치를 「Git」으로 고른다. 저장소(예: `github.com/hanumoka/zm-docs`), 저장소 뿌리에서의 경로(예: `docs/governance/decisions/README.md`), 브랜치, 첫 판의 커밋을 쓴다. 커밋은 비워도 되고, 그러면 「판 없음」으로 등록된다.
2. 상세 머리에 「읽기만 한다」와 경로가 보인다. 본문 자리는 「본문은 Git 파일 …의 커밋 …에 있다」로 안내한다.
3. Git에서 그 파일을 고치고 커밋한 뒤, 상세의 「새 커밋 기록」에 그 커밋을 넣는다. 판이 하나 늘고 초안이 된다.

## 완료 확인

- 제품 안 문서 하나가 판 2까지 있고, 판 1이 승인됨, 판 2가 초안이다. 이력에 등록함·판 1 더함·판 1 승인함·판 2 더함이 남는다.
- Git 문서 하나가 커밋을 가리키는 판을 갖고, 화면이 본문을 고치는 단추를 내놓지 않는다.
- 이은 작업과 결정이 문서 상세의 옆 칸에 보이고, 누르면 그 화면에서 열린다.

## 실패하면

1. **「a Git document's body stays in Git」 또는 「본문은 Git 파일(…)이 정본이다」**: Git 문서에 본문을 보냈다. Git에서 고친 뒤 커밋을 기록한다.
2. **「git.path must be a path from the repository root」**: 경로가 `/`, `~`, 드라이브 문자(`C:`)로 시작하거나 `..`을 담았다. 저장소 뿌리에서 시작하는 경로를 쓴다. 이 PC의 절대 경로는 받지 않는다.
3. **「git.repo must not carry a user name or password」**: 저장소 주소에 `사용자:비밀번호@`가 들어 있다. 빼고 쓴다.
4. **「version N is the newest now」**: 그사이 다른 창에서 새 판이 생겼다. 화면을 다시 읽고 그 판에서 다시 쓴다.
5. **「the body is the same as version N」, 「the newest version already points at …」**: 바뀐 것이 없다.
6. **「이미 승인한 판이다」**: 그 판은 이미 승인됐다. 단추는 잠기고 이유가 옆에 보인다.
7. **화면 위에 「「문서」를 읽거나 바꾸지 못했다」가 뜬다**: 서버가 멈췄는지 `zm-baton status`로 본다.

## 정리

문서를 지우는 명령은 아직 없다. `V6`은 되돌리는 마이그레이션이 없다. 데이터베이스를 처음부터 다시 만드는 방법은 [work-and-decisions.md](work-and-decisions.md)의 「정리」와 같고, 그 전에 [backup-restore-update.md](backup-restore-update.md)대로 백업해 둔다. 내보내기(`zm-baton export`)에는 문서 표 넷이 함께 들어간다.

## 이 판이 하지 않는 것

- Git 문서의 본문을 가져오기. 경로와 커밋만 기록하고, 본문은 그 저장소에서 연다. `zm-baton import zm-docs`는 바꾸지 않았다
- 정본 위치를 옮기기(제품 안 ↔ Git). 정본 전환은 쓰기 제한·이력 대조·전환 확인 순서가 필요해(G20.3) 따로 만든다
- 제품에서 Git 문서를 고쳐 변경 제안·PR로 잇기(G20.2), 승인 철회, 판끼리 차이 보기
- 문서 확인·확인 만료·보관(FN-0603), 템플릿(FN-0605), 공유 범위별 열람 제한(1단계는 조직 하나)
- 문서판이 승인될 때 문서 모순 후보를 찾는 마스터 실행(협업 계약 「문서 모순 후보」). 승인을 기록하는 자리(`DocumentWriteService.approve`)가 그것이 붙을 자리다

## 알아 둘 점

- 「영향 받는 작업」은 사람이 이은 기록이다. 판이 바뀌었다고 작업에 알림이 가지는 않는다. 상세 옆 칸에서 다시 볼 작업을 확인한다.
- 본문은 한 판에 200,000자까지 받는다.
