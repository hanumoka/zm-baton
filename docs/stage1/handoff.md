# 작업을 AI에게 맡기기 — 1단계 셋째 묶음 쓰기

1단계 셋째 묶음의 첫 판이다. 웹의 작업 상세에서 「AI에게 맡기기」를 누르면, 이 PC의 로컬 연결 프로그램(`zm-baton agent`)이 그 작업을 Claude Code로 실행한다. 실행마다 저장소에 새 Git 작업 트리와 실행 전용 브랜치가 생기고, 결과가 그 브랜치에 남고, 작업이 결과 검토로 넘어온다. 1단계에서는 zm-baton이 결과를 합치지 않는다. 사람이 Git으로 직접 합치거나 버린다. 근거는 협업 계약 v1의 「위임」, 「실행 권리 청구」, 「실행할 때 넘기는 것」, 「실행마다 별도 작업 트리」, 「보고 한 건의 모양」(`protocol_version` 2)과 DEC-0098이다(설계 허브 zm-docs).

- **대상**: 첫째·둘째 묶음([sessions.md](sessions.md), [work-and-decisions.md](work-and-decisions.md))을 설치한 소유자 PC 한 대. 서버는 이 PC의 `127.0.0.1`에서만 받는다.
- **소유자**: 저장소 소유자. 마지막 확인 2026-10-14.
- **전제**: 이 묶음의 서버·연결 프로그램·웹이 함께 들어간 판에서 따른다. 실행 보고 형식이 `protocol_version` 2로 올라가므로 서버와 연결 프로그램을 같이 바꾼다. 옛 서버는 새 연결 프로그램의 보고를 거절한다.

## 무엇이 어디에 뜨는가

| 무엇 | 어디 |
|---|---|
| 「AI에게 맡기기」와 그 작업의 실행 기록 | 작업 상세(`http://127.0.0.1:18081/#work`)의 「다음 단계」 아래 |
| 이 PC에서 맡긴 일을 쓸 저장소 목록 | `zm-baton repo list`. 파일은 사용자 설정 폴더의 `zm-baton\repos.json` |
| 맡긴 일을 실행하는 연결 프로그램 | `zm-baton agent`. 띄운 창에 로그가 나온다 |
| 실행마다 만드는 작업 트리 | 기본은 저장소 폴더 옆의 `<저장소 폴더 이름>-zm-baton-runs\<실행 시도 번호>` |
| 실행 전용 브랜치 | `zm-baton/<실행 시도 번호>` |

서버는 저장소를 키(`git:<첫 커밋>`)·폴더 이름·자격 증명을 뺀 원격 주소로만 안다. 이 PC의 절대 경로는 `repos.json`에만 있고 서버로 가지 않는다.

## 전제조건

- 첫째 묶음의 `zm-baton login`을 마쳤다(`zm-baton status`가 `서버 응답: 정상`).
- Claude Code가 설치돼 있고 소유자가 직접 로그인해 둔 상태다. zm-baton은 로그인 정보를 읽거나 보내지 않는다. 맡긴 일은 **이 PC에 로그인한 그 계정**으로 돈다. 1단계에는 AI 계정을 따로 등록하는 기능이 없다.
- 맡길 저장소가 이 PC에 Git 체크아웃으로 있고 커밋이 하나 이상 있다. 저장소와 작업 트리 폴더는 임시 폴더(`TMP`·`TEMP`) 밖에 있어야 한다.
- PowerShell에서 `$repo`에 zm-baton 저장소 루트를 담는다.

## 단계

### 1. 서버와 웹을 새 판으로 다시 띄운다

```powershell
cd $repo
git pull --ff-only
docker compose -f deploy/compose/compose.yaml --profile app up -d --build
```

서버가 뜰 때 데이터베이스 구조 변경 `V4`가 한 번 적용된다. 표 둘(`device_repositories`, `delegations`)과 `runs`의 칸 다섯을 더하고, `run_events`의 종류 검사에 `git_changes`를 넣는다. 지우는 것은 없고 이미 있던 기록은 그대로다.

### 2. `zm-baton` 명령을 새 판으로 바꾼다

첫째 묶음 안내서 3단계의 첫 네 줄과 같다. 실행 중인 Claude Code 세션의 훅이 잠깐 실패할 수 있으니 세션을 닫은 뒤 바꾸는 것이 안전하다.

```powershell
cd $repo/apps/agent
docker run --rm -v "${PWD}:/src" -w /src -e GOOS=windows -e GOARCH=amd64 golang:1.27 go build -o bin/zm-baton.exe ./cmd/zm-baton
Copy-Item bin/zm-baton.exe "$env:LOCALAPPDATA/zm-baton/bin/"
```

### 3. 맡길 저장소를 등록한다(저장소마다 한 번)

```powershell
zm-baton repo add 'C:/work/my-repo'
```

- 서버에 저장소를 알리고, 이 PC의 `repos.json`에 경로를 적는다. 출력에 작업 폴더와 작업 트리 폴더가 나온다.
- 작업 트리 폴더를 바꾸려면 `--worktrees '<폴더>'`를 준다. 저장소 안의 폴더는 거부한다.
- 같은 저장소를 다른 폴더로 다시 등록하면 새 폴더로 바뀐다.
- 등록한 것을 보려면 `zm-baton repo list`, 빼려면 `zm-baton repo remove '<폴더 또는 git:키>'`. 빼도 이미 만든 작업 트리와 브랜치는 그대로다.

### 4. 연결 프로그램을 띄운다

창 하나를 차지하므로 따로 연 PowerShell 창에서 띄운다.

```powershell
zm-baton agent
```

- 2초마다 서버에 이 PC 몫의 맡긴 일을 묻는다. 등록한 저장소의 일만 가져간다. 다른 저장소의 일이 기다리면 한 번만 경고한다.
- `Ctrl+C`로 멈춘다. 실행 중이면 그 실행기를 멈추고 「취소됨」으로 보고한다.
- 하나만 실행하고 끝내려면 `zm-baton agent --once`. 실행 시간 상한은 `--run-timeout`(기본 30분), Claude Code 실행 파일은 `--claude`(기본 PATH의 `claude`)로 바꾼다.

### 5. 웹에서 맡긴다

1. 「작업」 화면에서 맡길 작업을 고른다. **여기서 만든 작업이고 「수행 준비」 단계**여야 한다.
2. 상세의 「AI에게 맡기기」를 누른다.
3. 저장소(등록한 PC)를 고르고, 기준 브랜치를 쓴다. 비우면 그 저장소의 지금 커밋에서 시작한다.
4. AI가 쓸 도구를 고른다.
   - **읽기만**(Read·Glob·Grep, 처음 값): 파일을 바꾸지 못한다. 조사·검토만 시킬 때 고른다.
   - **파일 고치기**(위에 Edit·Write를 더함): 그 실행의 작업 트리 안에서만 파일을 고친다.
   - 어느 쪽이든 명령 실행(Bash·PowerShell)은 허용하지 않는다.
5. 「Claude Code에 맡기기」를 누른다. 작업의 실행 담당이 AI(매니저)로 바뀌고 「실행 기록」에 「청구 대기」가 생긴다.
6. 연결 프로그램이 가져가면 「작업 중」과 최근 활동이 보이고, 작업은 「수행」으로 넘어간다.
7. 끝나면 결과 검토 단계를 쓰는 설정이면 「결과 검토」로, 쓰지 않는 설정이면(1인 조직의 처음 값) 「완료」로 넘어간다. 실행 기록에 실행 브랜치와 바뀐 파일이 보인다.

맡길 수 없으면 단추가 잠기고 서버가 준 이유가 옆에 보인다. 아직 가져가지 않은 일은 「맡긴 일 거두기」로 거둘 수 있다.

### 6. 결과 브랜치를 확인하고 합친다

zm-baton은 실행이 끝난 뒤 커밋하지 않고 작업 트리도 지우지 않는다. Claude Code가 커밋하지 않았다면 바뀐 파일은 작업 트리에 **커밋되지 않은 채** 남아 있다.

```powershell
cd 'C:/work/my-repo'
git worktree list                                  # 실행마다 만든 작업 트리와 브랜치
cd 'C:/work/my-repo-zm-baton-runs/<실행 시도 번호>'
git status                                         # 바뀐 파일 확인
git diff                                           # 내용 확인
git add <파일> ; git commit -m "<무엇을 했나>"     # 받아들일 변경을 그 브랜치에 커밋
cd 'C:/work/my-repo'
git switch <기준 브랜치>
git merge zm-baton/<실행 시도 번호>                # 합친다
```

- 실행 기록의 「원래 브랜치에서도 바뀜」 표시는 그 파일이 실행을 시작한 뒤 기준 브랜치에서도 바뀌었다는 뜻이다. 합칠 때 충돌할 수 있다. Git이 충돌 없이 합칠 수 있어도 표시한다.
- 「원래 폴더에도 고치는 중」은 원래 체크아웃에 그 파일의 커밋하지 않은 변경이 있다는 뜻이다. zm-baton 밖에서 연 세션이 같은 파일을 고치고 있을 수 있다.
- 합친 뒤 작업이 「결과 검토」에 있으면 「완료로 옮기기」로 끝낸다.

버리려면 작업 트리와 브랜치를 Git으로 지운다. 지우기 전에 다른 실행이 그 작업 트리를 쓰고 있지 않은지 본다.

```powershell
cd 'C:/work/my-repo'
git worktree remove 'C:/work/my-repo-zm-baton-runs/<실행 시도 번호>'   # 커밋하지 않은 변경이 있으면 거부한다. 버릴 것이 확실할 때만 --force
git branch -D zm-baton/<실행 시도 번호>
```

## 완료 확인

- 웹의 실행 기록이 「완료」이고, 실행 브랜치 이름과 바뀐 파일이 보인다.
- 작업이 「결과 검토」(또는 결과 검토를 쓰지 않으면 「완료」)에 있고, 이력에 「수행 준비 → 수행 (AI 실행이 옮김)」과 「수행 → 결과 검토 (AI 실행이 옮김)」이 있다.
- `git worktree list`에 그 실행의 작업 트리가 있고, 원래 체크아웃은 그대로다.

## 실패하면

| 증상 | 원인과 대응 |
|---|---|
| 「AI에게 맡기기」가 잠기고 「정본이 Git 파일…」 | zm-docs에서 가져온 작업이다. 실행하면 단계가 바뀌는데 그 복사본은 가져오기만 바꾼다. 「새 작업」으로 만들어 맡긴다 |
| 「… 단계다. 수행 준비로 옮긴 뒤에 맡긴다」 | 초안·계획 검토 단계다. 수행 준비로 옮긴다 |
| 「이어서 맡기기는 아직 없다」 | 수행·결과 검토 단계의 작업을 다시 실행하는 기능(재개)은 다음 판이다. 「다시 계획하기」로 수행 준비까지 돌린 뒤 맡긴다 |
| 저장소 칸에 「등록한 저장소가 없다」 | 3단계 `zm-baton repo add`를 한다 |
| 「청구 대기」에서 넘어가지 않는다 | 그 PC에서 `zm-baton agent`가 떠 있는지 본다. 연결 프로그램 창에 `not registered on this device` 경고가 있으면 그 저장소를 그 PC에서 `repo add`한다. 맡긴 지 8시간이 지나면 위임이 끝나 가져가지 않는다. 「맡긴 일 거두기」 뒤 다시 맡긴다 |
| 실행이 바로 「오류」로 끝나고 작업이 「수행 준비」에 남는다 | 실행기를 띄우기 전에 실패했다. 연결 프로그램 창의 `could not prepare the run` 줄에 이유가 있다. 기준 브랜치가 없거나, 저장소·작업 트리 폴더가 임시 폴더 안이거나, 같은 이름의 작업 트리 폴더가 이미 있을 때다. 고친 뒤 다시 맡긴다 |
| 실행이 「오류」나 「취소됨」으로 끝나고 작업에 「결과 확인 필요」 | 실행기가 결과를 내기 전에 끝났다(시간 상한, `Ctrl+C`, 실행기 비정상 종료). 작업 트리에 반쯤 고친 파일이 있을 수 있다. 6단계처럼 작업 트리를 확인한 뒤, 받아들이면 「결과 검토로 옮기기」나 「완료로 옮기기」, 다시 시키려면 「다시 계획하기」로 수행 준비로 돌려 다시 맡긴다 |
| 실행 기록에 「작업 중」이 계속되는데 연결 프로그램을 껐다 | 1단계에는 끊긴 실행을 서버가 알아채는 판정이 아직 없다. 그 실행 시도는 서버에서 끝나지 않은 채 남는다. 다음 판에서 고친다 |
| 바뀐 파일이 0개 | 「읽기만」으로 맡겼거나 Claude Code가 아무것도 바꾸지 않았다. 실행 기록의 「AI에게 넘긴 지시」와 최근 활동을 본다 |

## 이 판이 하지 않는 것

다음 판에서 한다.

- 실행 중 개입·취소·재개, 응답 없음 판정 강화(임대 갱신·기기 생존), 시작 전 준비 검사
- AI 사용량 상한, AI 계정 등록과 계정별 설정 폴더(`CLAUDE_CONFIG_DIR`)
- Codex를 zm-baton이 띄우기
- 결과 브랜치를 zm-baton이 합치거나 버리기, 작업 트리 지우기(계약 「실행마다 별도 작업 트리」 5번의 확인이 필요하다)
- `git_changes`의 겹침으로 충돌 알림 만들기(계약 「작업 충돌」 3·4·5번). 지금은 실행 기록에 표시만 한다

## 알아 둘 점

- **실행 지시**: 서버가 작업의 제목·작업 번호·프로젝트·수락 조건·다음 행동·참조 문서와, 작업 트리 안에서만 고치고 합치거나 push하지 않는다는 안내로 지시를 만든다. 실행 기록의 「AI에게 넘긴 지시」에서 그대로 볼 수 있다.
- **Claude Code를 제한 모드로 띄운다**: `--restricted`(Claude Code 2.1.296)로 띄운다. 그래서 이 PC의 사용자·프로젝트 설정 파일(권한 모드 `auto`, 허용 규칙)을 읽지 않고, 명령 실행 도구가 빠지고, 파일 도구는 작업 트리 안에만 머문다. 고른 도구(`--allowedTools`) 밖의 동작은 `--permission-prompts none`으로 거부되고 사용량 보고의 거부 목록에 남는다. 실행 시험(`zm-baton-agent`)은 이 옵션을 쓰지 않는다.
- **직접 연 세션으로 등록하지 않는다**: 실행기 환경에 `ZM_BATON_OFF=1`을 넣어, 소유자가 붙인 zm-baton 훅이 이 실행을 「직접 연 세션」으로 한 번 더 등록하지 않게 한다.
- **보고에서 빼는 경로**: Claude Code의 도구는 절대 경로를 보고한다. 연결 프로그램은 보내기 전에 그 실행의 작업 트리 경로를 지워 저장소 기준 경로로 바꾼다. 작업 트리 밖의 경로(예: 사용자 폴더)가 도구 결과에 섞이면 그대로 간다.
- **바뀐 파일 목록**: 실행 중 60초마다와 끝날 때 보낸다. 기준 커밋 대비 커밋한 것·커밋하지 않은 것·새 파일을 모두 센다. 원래 체크아웃은 잠금을 잡지 않고 읽기만 한다.
- **위임 기한**: 맡긴 뒤 8시간 안에 가져가지 않으면 그 위임으로는 실행하지 않는다.

## 정리

- 연결 프로그램은 `Ctrl+C`로 끈다.
- 저장소를 더 쓰지 않으면 `zm-baton repo remove '<폴더>'`. 작업 트리와 브랜치는 6단계의 Git 명령으로 지운다.
- `V4`는 되돌리는 마이그레이션이 없다. 셋째 묶음을 통째로 떼려면 둘째 묶음 안내서의 「정리」처럼 데이터베이스 볼륨까지 지우고 옛 판으로 다시 띄운다.
