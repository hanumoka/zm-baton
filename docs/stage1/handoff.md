# 작업을 AI에게 맡기기 — 1단계 셋째 묶음 쓰기

1단계 셋째 묶음의 첫 판·둘째 판·셋째 판이다. 웹의 작업 상세에서 「AI에게 맡기기」를 누르면, 이 PC의 로컬 연결 프로그램(`zm-baton agent`)이 그 작업을 Claude Code로 실행한다. 실행마다 저장소에 새 Git 작업 트리와 실행 전용 브랜치가 생기고, 결과가 그 브랜치에 남고, 작업이 결과 검토로 넘어온다. 둘째 판에서 실행 중에 멈추거나 짧은 지시를 보내고, 끊기거나 멈춘 실행·돌려보낸 결과를 이어서 맡기고, 실행기를 띄우기 전에 준비 검사를 하고, 연결 프로그램이 꺼진 실행을 서버가 「연결 끊김」으로 끝낸다. 셋째 판에서 실행이 고른 AI 계정으로 돌고, 쓴 양을 세고, 상한이나 과금 신호에 닿으면 멈춘다([accounts.md](accounts.md)). 1단계에서는 zm-baton이 결과를 합치지 않는다. 사람이 Git으로 직접 합치거나 버린다. 근거는 협업 계약 v1의 「위임」, 「실행 권리 청구」, 「실행할 때 넘기는 것」, 「실행마다 별도 작업 트리」, 「실행이 끊겼을 때」, 「프로세스 관리」, 「보고 한 건의 모양」(`protocol_version` 2)과 DEC-0098이다(설계 허브 zm-docs).

- **대상**: 첫째·둘째 묶음([sessions.md](sessions.md), [work-and-decisions.md](work-and-decisions.md))을 설치한 소유자 PC 한 대. 서버는 이 PC의 `127.0.0.1`에서만 받는다.
- **소유자**: 저장소 소유자. 마지막 확인 2026-10-14(셋째 판).
- **전제**: 이 묶음의 서버·연결 프로그램·웹이 함께 들어간 판에서 따른다. 서버와 연결 프로그램을 같이 바꾼다. 옛 서버는 새 연결 프로그램의 보고를 거절하고, 둘째 판의 서버는 임대를 갱신하지 않는 옛 연결 프로그램의 실행을 약 6분(임대 45초와 재연결 유예 5분) 뒤 「연결 끊김」으로 끝낸다.

## 무엇이 어디에 뜨는가

| 무엇 | 어디 |
|---|---|
| 「AI에게 맡기기」·「이어서 맡기기」와 그 작업의 실행 기록 | 작업 상세(`http://127.0.0.1:18081/#work`)의 「다음 단계」 아래 |
| 진행 중인 실행의 「실행 취소」와 「실행 중인 AI에게 지시」 | 실행 기록에서 그 실행의 칸 |
| 이 PC에서 맡긴 일을 쓸 저장소 목록 | `zm-baton repo list`. 파일은 사용자 설정 폴더의 `zm-baton\repos.json` |
| 맡긴 일을 실행하는 연결 프로그램 | `zm-baton agent`. 띄운 창에 로그가 나온다 |
| 실행마다 만드는 작업 트리 | 기본은 저장소 폴더 옆의 `<저장소 폴더 이름>-zm-baton-runs\<실행 시도 번호>` |
| 실행 전용 브랜치 | `zm-baton/<실행 시도 번호>` |
| 이 PC가 띄운 실행기의 기록(이어 쓰기 판단용) | 사용자 설정 폴더의 `zm-baton\runs\<실행 시도 번호>.json`. 서버로 가지 않는다 |
| AI 계정, 계정의 오늘 사용량과 상한 | 사이드바 아래(설정 자리) 「AI 계정」(`http://127.0.0.1:18081/#accounts`) |
| API 키 계정의 실행 전용 Claude Code 설정 폴더 | 사용자 설정 폴더의 `zm-baton\executors\<계정 번호>\claude`. zm-baton은 그 안을 열지 않는다 |

서버는 저장소를 키(`git:<첫 커밋>`)·폴더 이름·자격 증명을 뺀 원격 주소로만 안다. 이 PC의 절대 경로는 `repos.json`에만 있고 서버로 가지 않는다.

## 전제조건

- 첫째 묶음의 `zm-baton login`을 마쳤다(`zm-baton status`가 `서버 응답: 정상`).
- Claude Code 2.1.296 이상이 설치돼 있고 소유자가 직접 로그인해 둔 상태다. zm-baton은 로그인 정보를 읽거나 보내지 않는다. 셋째 판부터 맡긴 일은 **고른 AI 계정**으로 돈다. 처음부터 있는 계정 「이 PC의 Claude Code 로그인」은 이 PC에 로그인한 그 계정이다. 계정 등록, 계정마다의 사용량 상한, 과금 신호는 [accounts.md](accounts.md)에 있다.
- 맡길 저장소가 이 PC에 Git 체크아웃으로 있고 커밋이 하나 이상 있다. 저장소와 작업 트리 폴더는 임시 폴더(`TMP`·`TEMP`) 밖에 있어야 한다.
- PowerShell에서 `$repo`에 zm-baton 저장소 루트를 담는다.

## 단계

### 1. 서버와 웹을 새 판으로 다시 띄운다

```powershell
cd $repo
git pull --ff-only
docker compose -f deploy/compose/compose.yaml --profile app up -d --build
```

서버가 뜰 때 데이터베이스 구조 변경이 한 번 적용된다. 셋째 판의 `V9`는 [accounts.md](accounts.md) 1단계에 있다. `V4`는 표 둘(`device_repositories`, `delegations`)과 `runs`의 칸 다섯을 더하고 `run_events`의 종류 검사에 `git_changes`를 넣는다. `V7`은 `runs`에 이어 간 실행(`resumed_from_run_id`)과 이어 가는 이유(`continue_reason`) 칸을, 표 `run_inputs`(사람이 실행 중에 보낸 지시)를 더한다. 지우는 것은 없고 이미 있던 기록은 그대로다.

실행 중에 서버를 다시 띄워도 그 실행은 끊기지 않는다. 서버는 다시 뜬 때부터 재연결 유예(5분)를 새로 세고, 연결 프로그램은 서버가 돌아오면 임대를 다시 갱신한다.

### 2. `zm-baton` 명령을 새 판으로 바꾼다

첫째 묶음 안내서 3단계의 첫 네 줄과 같다. 실행 중인 Claude Code 세션의 훅이 잠깐 실패할 수 있으니 세션을 닫은 뒤 바꾸는 것이 안전하다. 떠 있는 `zm-baton agent`도 `Ctrl+C`로 끈 뒤 바꾼다.

```powershell
cd $repo/apps/agent
docker run --rm -v "${PWD}:/src" -w /src -e GOOS=windows -e GOARCH=amd64 golang:1.27 go build -o bin/zm-baton.exe ./cmd/zm-baton
Copy-Item bin/zm-baton.exe "$env:LOCALAPPDATA/zm-baton/bin/"
```

### 3. 맡길 저장소를 등록한다(저장소마다 한 번)

```powershell
zm-baton repo add 'C:/work/my-repo'
```

- 서버에 저장소를 알리고, 이 PC의 `repos.json`에 경로를 적는다. 출력에 작업 폴더와 작업 트리 폴더가 나온다.
- 작업 트리 폴더를 바꾸려면 `--worktrees '<폴더>'`를 준다. 저장소 안의 폴더는 거부한다.
- 같은 저장소를 다른 폴더로 다시 등록하면 새 폴더로 바뀐다.
- 등록한 것을 보려면 `zm-baton repo list`, 빼려면 `zm-baton repo remove '<폴더 또는 git:키>'`. 빼도 이미 만든 작업 트리와 브랜치는 그대로다.

### 4. 연결 프로그램을 띄운다

창 하나를 차지하므로 따로 연 PowerShell 창에서 띄운다.

```powershell
zm-baton agent
```

- 2초마다 서버에 이 PC 몫의 맡긴 일을 묻는다. 등록한 저장소의 일만 가져간다. 다른 저장소의 일이 기다리면 한 번만 경고한다.
- 일을 가져가면 끝날 때까지 5초마다 서버에 임대를 갱신한다. 갱신의 답으로 사람이 누른 「실행 취소」와 보낸 지시를 받는다.
- `Ctrl+C`로 멈춘다. 실행 중이면 그 실행기를 멈추고 「취소됨」으로 보고한다.
- 하나만 실행하고 끝내려면 `zm-baton agent --once`. 실행 시간 상한은 셋째 판부터 AI 계정의 「실행마다 시간」(처음 값 60분)이다. `--run-timeout`을 주면 그것이 더 짧을 때만 쓰고, 서버가 상한을 보내지 않으면 30분이다. Claude Code 실행 파일은 `--claude`(기본 PATH의 `claude`)로 바꾼다.
- API 키 계정으로 맡긴 일을 돌리려면 이 창에 `ANTHROPIC_API_KEY`를 둔다([accounts.md](accounts.md) 2단계). 구독 계정의 실행에서는 이 창의 `ANTHROPIC_API_KEY` 같은 다른 자격을 빼고 띄운다.

### 5. 웹에서 맡긴다

1. 「작업」 화면에서 맡길 작업을 고른다. **여기서 만든 작업이고 「수행 준비」 단계**여야 한다. 이미 AI가 돌린 작업은 8단계(이어서 맡기기)를 본다.
2. 상세의 「AI에게 맡기기」를 누른다.
3. 저장소(등록한 PC)를 고르고, 기준 브랜치를 쓴다. 비우면 그 저장소의 지금 커밋에서 시작한다.
4. AI 계정을 고른다. 처음 값은 이어 갈 실행의 계정이나 쓸 수 있는 첫 계정이다. 멈춘 계정은 잠긴 채 이유가 보이고, 칸 아래에 이 실행의 상한과 그 계정의 오늘 사용량이 보인다.
5. AI가 쓸 도구를 고른다.
   - **읽기만**(Read·Glob·Grep, 처음 값): 파일을 바꾸지 못한다. 조사·검토만 시킬 때 고른다.
   - **파일 고치기**(위에 Edit·Write를 더함): 그 실행의 작업 트리 안에서만 파일을 고친다.
   - 어느 쪽이든 명령 실행(Bash·PowerShell)은 허용하지 않는다.
6. 필요하면 「덧붙일 지시」를 쓴다. 지시 안에 「사람이 덧붙인 지시」로 들어간다.
7. 「Claude Code에 맡기기」를 누른다. 작업의 실행 담당이 AI(매니저)로 바뀌고 「실행 기록」에 「청구 대기」가 생긴다.
8. 연결 프로그램이 가져가면 준비 검사를 하고(아래 「시작 전 준비 검사」), 통과하면 「작업 중」과 최근 활동이 보이고, 작업은 「수행」으로 넘어간다.
9. 끝나면 결과 검토 단계를 쓰는 설정이면 「결과 검토」로, 쓰지 않는 설정이면(1인 조직의 처음 값) 「완료」로 넘어간다. 실행 기록에 실행 브랜치와 바뀐 파일, 계정·상한·사용량·과금 위치가 보인다.

맡길 수 없으면 단추가 잠기고 서버가 준 이유가 옆에 보인다. 아직 가져가지 않은 일은 「맡긴 일 거두기」로 거둘 수 있다.

### 6. 결과 브랜치를 확인하고 합친다

zm-baton은 실행이 끝난 뒤 커밋하지 않고 작업 트리도 지우지 않는다. Claude Code가 커밋하지 않았다면 바뀐 파일은 작업 트리에 **커밋되지 않은 채** 남아 있다. 대신 연결 프로그램이 끝날 때 그 내용을 스냅샷 커밋(`refs/zm-baton/snapshots/<실행 시도 번호>`)으로 고정하고, 서버가 그 결과를 위험 목록과 맞춰 사람에게 보낼지 정한다. 위험 목록에 걸린 결과는 합치기 전에 첫 화면에서 승인하거나 반려한다([human-review.md](human-review.md)).

```powershell
cd 'C:/work/my-repo'
git worktree list                                  # 실행마다 만든 작업 트리와 브랜치
cd 'C:/work/my-repo-zm-baton-runs/<실행 시도 번호>'
git status                                         # 바뀐 파일 확인
git diff                                           # 내용 확인
git add <파일> ; git commit -m "<무엇을 했나>"     # 받아들일 변경을 그 브랜치에 커밋
cd 'C:/work/my-repo'
git switch <기준 브랜치>
git merge zm-baton/<실행 시도 번호>                # 합친다
```

- 실행 기록의 「원래 브랜치에서도 바뀜」 표시는 그 파일이 실행을 시작한 뒤 기준 브랜치에서도 바뀌었다는 뜻이다. 합칠 때 충돌할 수 있다. Git이 충돌 없이 합칠 수 있어도 표시한다.
- 「원래 폴더에도 고치는 중」은 원래 체크아웃에 그 파일의 커밋하지 않은 변경이 있다는 뜻이다. zm-baton 밖에서 연 세션이 같은 파일을 고치고 있을 수 있다.
- 이어서 맡긴 실행이 이전 실행의 작업 트리를 이어 썼으면(실행 기록에 「이전 실행의 작업 트리와 세션을 이어 썼다」) 실행 브랜치는 이전 실행의 것이다. 그 브랜치 하나를 합친다.
- 합친 뒤 작업이 「결과 검토」에 있으면 「완료로 옮기기」로 끝낸다. 열린 위험 목록 검토가 있으면 이 단추가 잠긴다. 첫 화면에서 먼저 판정한다.

버리려면 작업 트리와 브랜치를 Git으로 지운다. 지우기 전에 다른 실행이 그 작업 트리를 쓰고 있지 않은지 본다.

```powershell
cd 'C:/work/my-repo'
git worktree remove 'C:/work/my-repo-zm-baton-runs/<실행 시도 번호>'   # 커밋하지 않은 변경이 있으면 거부한다. 버릴 것이 확실할 때만 --force
git branch -D zm-baton/<실행 시도 번호>
```

### 7. 실행 중에 지시를 보내거나 멈춘다

실행 기록에서 진행 중인 실행의 칸에 두 가지가 있다. 할 수 없으면 잠기고 서버가 준 이유가 옆에 보인다.

**지시 보내기**

1. 「실행 중인 AI에게 지시」 칸에 짧게 쓴다(2,000자까지). 예: 「테스트 파일은 건드리지 않는다」.
2. 「지시 보내기」를 누른다. 지시는 「연결 프로그램에 전달 대기」로 보인다.
3. 연결 프로그램이 다음 임대 갱신(5초 안)에 받아 Claude Code에 넣는다. Claude Code는 진행 중인 도구가 끝난 뒤 다음 턴에 그 지시를 받는다. 받으면 「실행기가 받음」으로 바뀐다. 상태는 다음 갱신 때 서버에 알려지므로 화면에 보이기까지 10초쯤 걸릴 수 있다.
4. 실행이 그 전에 끝나면 「전달하지 못함」이 된다. 그 지시는 8단계의 덧붙일 지시에 넣어 다시 보낸다.

Claude Code에는 「사람이 실행 중에 보낸 지시:」를 앞에 붙여 넣는다. 지시로 도구나 권한은 바뀌지 않는다. 연결 프로그램이 옛 판이거나 실행기가 아직 시작되지 않았으면 잠긴다.

**실행 취소**

1. 「실행 취소」를 누르고 「실행 멈추기」로 한 번 더 확인한다.
2. 실행이 「중단 요청됨」이 되고 「취소 요청함」 표시가 붙는다. 그 실행의 위임은 철회돼 더는 청구되지 않는다.
3. 연결 프로그램이 다음 임대 갱신에 알아채고, 띄울 때 붙잡아 둔 실행기 프로세스를 표식(세션 번호)을 확인한 뒤 멈춘다. Windows에서는 실행기가 띄운 하위 프로세스도 함께 멈춘다.
4. 실행은 「취소됨」으로 끝난다. 작업 트리와 브랜치는 그대로 남는다.
5. 실행기가 결과를 내기 전에 멈췄으면 작업에 「결과 확인 필요」가 붙고 작업은 「수행」에 남는다. 작업 트리를 확인한 뒤 8단계로 이어서 맡기거나, 6단계처럼 합치거나, 「다시 계획하기」로 돌린다. 실행기를 띄우기 전에 멈췄으면 작업은 그 단계 그대로이고 「결과 확인 필요」도 붙지 않는다.

작업 자체를 「취소하기」로 옮기려면 살아 있는 실행을 먼저 이렇게 멈춘다. 멈추기 전에는 「취소하기」가 잠긴다.

### 8. 이어서 맡긴다

AI가 돌린 작업이 「수행」에 있으면(실행이 끊겼거나, 취소했거나, 결과를 돌려보낸 뒤) 「AI에게 맡기기」 자리가 「이어서 맡기기」가 된다. 「결과 검토」에 있으면 「돌려보내고 이어서 맡기기」가 된다.

1. 단추를 누르면 이어 갈 실행과 그 실행의 저장소·도구가 먼저 골라져 있다. 기준 브랜치를 비우면 이전 실행과 같다.
2. 「덧붙일 지시」를 쓴다. 「돌려보내고 이어서 맡기기」이면 이 칸이 「돌려보내는 이유와 고칠 점」이 되고 비우면 보낼 수 없다. 그 이유로 작업이 「결과 검토 → 수행」으로 옮겨지고 이력에 남는다.
3. 보내면 새 실행 시도가 생기고, 이전 실행 시도와 이어 가는 이유(끊긴 실행을 잇는다 / 돌려보낸 결과를 고친다)가 기록된다. 작업의 「결과 확인 필요」와 「시작 전 준비 미달」은 이때 떨어진다.
4. AI에게 넘기는 지시에는 「이어서 하는 실행이다」, 이전 실행, 돌려보낸 이유(손으로 돌려보낸 뒤 이어서 맡기면 그 이유), 덧붙인 지시가 들어간다. 먼저 작업 트리를 살펴 이전 실행이 어디까지 했는지 확인하고 남은 것만 하라고 적힌다.
5. 연결 프로그램은 어느 작업 트리에서 시작할지 이렇게 고른다(협업 계약 v1 「실행마다 별도 작업 트리」 6번).
   1. 같은 PC이고 이 PC가 이전 실행기와 그 하위 프로세스가 끝난 것을 확인했으면(`runs\<실행 시도 번호>.json`에 기록) **이전 실행의 작업 트리와 같은 Claude Code 세션을 이어 쓴다**(`--resume`). Claude Code에 그 세션이 없으면 같은 작업 트리에서 새 세션으로 시작한다.
   2. 같은 PC이지만 끝난 것을 확인하지 못했으면(연결 프로그램이 도중에 꺼졌으면) **이전 실행 브랜치의 끝에서 새 작업 트리와 새 세션**으로 시작한다. 이전 실행이 커밋하지 않은 변경은 새 작업 트리에 없다. 이전 작업 트리는 지우지 않으니 필요하면 거기서 가져온다.
   3. 다른 PC이면 기준에서 새로 시작한다.
6. 어떻게 시작했는지는 실행 기록의 「이어서」 줄과 그 아래 문장(「이전 실행의 작업 트리와 세션을 이어 썼다」 등), 「시작 전 준비 검사」의 「이어 쓰기」 줄에 보인다. 연결 프로그램은 Claude Code에 넘기는 지시 끝에도 같은 사실과 이미 바뀐 파일 목록을 덧붙인다.

## 시작 전 준비 검사

연결 프로그램은 실행기를 띄우기 전에 다음을 차례로 본다. 하나라도 미달이면 실행기를 띄우지 않고 실행을 「오류」로 끝내고, 작업에 「시작 전 준비 미달」을 단다. 작업 단계는 그대로다. 실행 기록에 미달한 항목과 이유가 보이고, 「시작 전 준비 검사」를 펼치면 모든 항목이 보인다.

| 항목 | 보는 것 |
|---|---|
| 위임 범위 | 청구 응답에 이 저장소를 Claude Code에 맡긴 위임과 지시가 있고, 도구가 알려진 다섯 가지 안이다 |
| 실행기 | `claude --version`이 2.1.296 이상이다 |
| 계정 | 셋째 판부터. 계정의 인증 방식을 이 연결 프로그램이 알고, API 키 계정이면 이 창에 `ANTHROPIC_API_KEY`가 있다. 다른 방식의 자격 환경 변수 가운데 뺀 것의 이름을 적는다([accounts.md](accounts.md) 「인증과 설정 격리」) |
| 저장소 | 등록한 폴더가 임시 폴더 밖에 있고, 그 폴더의 첫 커밋이 등록한 저장소 키와 같다 |
| 작업 트리 폴더 | 만들 수 있고 임시 폴더 밖이다 |
| 디스크 | 작업 트리 폴더의 디스크에 512 MB 이상 남았다 |
| 기준 | 기준 브랜치가 이 저장소에 있다 |
| 작업 트리 | 같은 이름의 폴더와 브랜치가 없고 `git worktree add`가 된다 |
| 이어 쓰기 | 이어서 맡긴 실행이면 어느 작업 트리에서 시작하는지(위 8단계 5번) |

고친 뒤 다시 맡기면 된다. 수락 조건이 비어 있어도 막지 않는다. 지시에 「적혀 있지 않다. 제목과 다음 행동으로 판단한다」로 들어간다.

## 연결 프로그램이 꺼지거나 끊겼을 때

1. 연결 프로그램은 실행 중 5초마다 임대를 갱신한다. 임대는 45초 동안 유효하다.
2. 갱신이 45초 넘게 오지 않으면 실행 기록에 「연결 프로그램의 신호가 끊겼다」와 서버가 포기할 시각이 보인다. 그 PC에서 `zm-baton agent`가 떠 있는지 본다. 그 안에 연결이 돌아오면 아무 일도 없다.
3. 임대가 끝난 뒤 5분(재연결 유예) 안에 돌아오지 않으면 서버가 그 실행을 「연결 끊김」(`lost`)으로 끝내고, 작업에 「결과 확인 필요」를 단다. 이력에 「연결 프로그램의 신호가 끊겨 서버가 실행을 「연결 끊김」으로 끝냄」이 남는다.
4. 그 뒤 연결 프로그램이 돌아오면 서버가 그 실행을 더는 잡고 있지 않다고 답하므로, 연결 프로그램은 아직 돌던 실행기를 멈춘다. 늦게 온 보고는 기록만 되고 상태를 바꾸지 않는다.
5. 연결 프로그램이 강제로 끝났으면 Claude Code가 잠시 더 돌 수 있다. 작업 트리를 확인한 뒤 8단계로 이어서 맡긴다. 이때는 이전 실행기가 끝난 것을 확인하지 못했으므로 이전 브랜치 끝에서 새 작업 트리로 시작한다.

## 완료 확인

- 웹의 실행 기록이 「완료」이고, 실행 브랜치 이름과 바뀐 파일이 보인다.
- 작업이 「결과 검토」(또는 결과 검토를 쓰지 않으면 「완료」)에 있고, 이력에 「수행 준비 → 수행 (AI 실행이 옮김)」과 「수행 → 결과 검토 (AI 실행이 옮김)」이 있다.
- `git worktree list`에 그 실행의 작업 트리가 있고, 원래 체크아웃은 그대로다.
- 지시를 보냈으면 「사람이 보낸 지시」에 「실행기가 받음」이 보인다. 취소했으면 「취소됨」이고 작업 트리가 남아 있다.

## 이 판이 하지 않는 것

다음 판 이후에 한다.

- 실행기가 사람에게 묻는 질문 경로(zm-baton 질문 도구 `ask_question`, 승인 멈춤을 질문으로 바꾸기, 첫 화면 「멈춘 AI의 질문」). Claude Code는 화면 없이 돌 때 구조화된 질문을 내지 않으므로, 지금은 실행기가 물을 수 없을 때 가정을 마지막 답에 적게 한다
- 실행 중 작업을 「취소하기」로 옮기면 그 실행을 함께 멈추는 것(계약의 대기 사유 `cancelling`). 지금은 실행을 먼저 멈춘 뒤 작업을 취소한다
- 자동 계정 전환과 재개(FN-0502), 금고와 실행 주입(핵심 모듈 5). 셋째 판의 AI 계정·사용량 상한이 하지 않는 것은 [accounts.md](accounts.md)의 같은 절에 있다
- Codex를 zm-baton이 띄우기
- 결과 브랜치를 zm-baton이 합치거나 버리기, 작업 트리 지우기(계약 「실행마다 별도 작업 트리」 5번의 확인이 필요하다)
- `git_changes`의 겹침으로 충돌 알림 만들기(계약 「작업 충돌」 3·4·5번). 지금은 실행 기록에 표시만 한다
- WebSocket 깨우기 신호. 지금은 2초 폴링과 5초 임대 갱신이 대신한다

## 알아 둘 점

- **실행 지시**: 서버가 작업의 제목·작업 번호·프로젝트·수락 조건·다음 행동·참조 문서, 이어서 맡긴 실행이면 이어 가는 이유와 이전 실행, 사람이 덧붙인 지시, 그리고 에이전트 행동 규범으로 지시를 만든다. 실행 기록의 「AI에게 넘긴 지시」에서 그대로 볼 수 있다.
- **에이전트 행동 규범**: 모든 지시 끝에 일곱 줄이 붙는다. AI 에이전트임을 밝히고 최종 책임은 사람에게 있다, 이 작업 트리 안만 고친다, 합치거나 push하지 않는다, 거부된 동작을 다른 방법으로 돌아가지 않는다, 물을 수 없으면 가정을 적는다, 실행 중 사람의 지시를 먼저 따르고 멈추라면 멈춘다, 바꾼 것·확인한 것·확인하지 못한 것을 나눠 답한다. 원문은 서버의 `apps/server/src/main/resources/executor/agent-norms.txt` 하나다(FN-0406, 기준 G38.2).
- **Claude Code를 제한 모드로 띄운다**: `--restricted`와 `--strict-mcp-config`(Claude Code 2.1.296)로 띄운다. 그래서 이 PC의 사용자·프로젝트 설정 파일(권한 모드 `auto`, 허용 규칙)을 읽지 않고, 소유자가 붙인 MCP 서버도 띄우지 않고, 명령 실행 도구가 빠지고, 파일 도구는 작업 트리 안에만 머문다. 고른 도구(`--allowedTools`) 밖의 동작은 `--permission-prompts none`으로 거부되고 사용량 보고의 거부 목록에 남는다. 실행 시험(`zm-baton-agent`)도 둘째 판부터 같은 두 옵션으로 띄운다.
- **지시는 표준 입력으로 넣는다**: 맡긴 실행은 `--input-format stream-json --replay-user-messages`로 띄우고, 지시와 사람이 보낸 지시를 표준 입력에 사용자 메시지로 넣는다. Claude Code가 받은 메시지를 되돌려 보내면 「실행기가 받음」이다. 결과가 오면 입력을 닫아 Claude Code가 끝나게 한다.
- **직접 연 세션으로 등록하지 않는다**: 실행기 환경에 `ZM_BATON_OFF=1`을 넣어, 소유자가 붙인 zm-baton 훅이 이 실행을 「직접 연 세션」으로 한 번 더 등록하지 않게 한다.
- **보고에서 빼는 경로**: Claude Code의 도구는 절대 경로를 보고한다. 연결 프로그램은 보내기 전에 그 실행의 작업 트리 경로를 지워 저장소 기준 경로로 바꾼다. 작업 트리 밖의 경로(예: 사용자 폴더)가 도구 결과에 섞이면 그대로 간다. 준비 검사의 이유 문장에 경로가 섞이면 「자세한 이유는 이 PC의 연결 프로그램 창에 있다」로 바꿔 보낸다.
- **바뀐 파일 목록**: 실행 중 60초마다와 끝날 때 보낸다. 기준 커밋 대비 커밋한 것·커밋하지 않은 것·새 파일을 모두 센다. 원래 체크아웃은 잠금을 잡지 않고 읽기만 한다.
- **위임 기한**: 맡긴 뒤 8시간 안에 가져가지 않으면 그 위임으로는 실행하지 않는다.
- **계정과 상한**: 실행마다 고른 AI 계정의 인증 방식 하나만 남기고(다른 자격 환경 변수를 뺀다), 계정의 턴·비용 상한을 Claude Code의 `--max-turns`·`--max-budget-usd`로, 시간 상한을 연결 프로그램의 시간 재기로 지킨다. 결과의 사용량(가격표 환산 비용, 토큰, 턴, 시간)을 실행에 남기고 계정별·일별로 더한다. 자세한 것은 [accounts.md](accounts.md).
- **숫자**: 임대 45초, 갱신 5초(계약의 시작값은 15초), 재연결 유예 5분, 준비 검사의 디스크 기준 512 MB, Claude Code 최소 판 2.1.296. 계약이 시작값이라고 한 숫자이고 1단계에서 써 보며 바꿀 수 있다. 상한의 처음 값(실행마다 턴 200·비용 30달러·60분, 하루 200달러, 비정상 소비 60분에 하루 상한의 절반)은 작성자가 정한 시작값이다.

## 정리

- 연결 프로그램은 `Ctrl+C`로 끈다.
- 저장소를 더 쓰지 않으면 `zm-baton repo remove '<폴더>'`. 작업 트리와 브랜치는 6단계의 Git 명령으로 지운다.
- `runs\` 폴더의 실행기 기록은 이어서 맡길 때만 읽는다. 지워도 되며, 지우면 다음 이어서 맡기기는 이전 브랜치 끝에서 새 작업 트리로 시작한다.
- `V4`·`V7`·`V9`는 되돌리는 마이그레이션이 없다. 셋째 묶음을 통째로 떼려면 둘째 묶음 안내서의 「정리」처럼 데이터베이스 볼륨까지 지우고 옛 판으로 다시 띄운다.
