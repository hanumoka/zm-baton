# 서로 다른 사람에게 같은 알림 전달하기

**목적**: 충돌이나 모순에 관계된 모든 사람이 자기 첫 화면에서 알림을 확인하게 한다.
**대상·소유자**: 서버 관리자·조직 구성원 / hanumoka.
**마지막 검토**: 2026-10-18.
**상태**: 최종 확인 전의 격리 시험판, V16 마이그레이션 포함.

이전에는 알림 하나에 열린 첫 화면 항목이 하나뿐이었다. 서로 다른 두 사람의 세션이 같은 파일을 고치면 받는 사람 목록에는 둘 다 있지만 첫 화면에는 한 사람에게만 나타났다(H-47).

V16은 유일 조건을 알림과 받는 사람의 조합으로 바꾼다. 파일 충돌과 문서 모순은 각 사람에게 항목을 만들고, 반복 보고에는 같은 사람의 항목을 더 만들지 않는다. 사용량 알림도 같은 인덱스를 사용한다. 각 사람의 자료 열람 권한은 조회 때 계속 확인한다.

`work/preview-notice-reopen` 후속은 같은 공용 계정을 쓰는 두 사람의 사용량 알림이나 문서 주인이 바뀐 뒤 다시 나온 모순 알림의 수신자 목록에도 새 사람을 합친다. 첫 화면 항목만 만들고 판정할 수 있는 수신자 목록에는 빠뜨리던 독립 검토 N1을 고친다. 이전 수신자도 남기며 중복은 제거한다. 첫 화면은 근거 자료의 현재 열람 권한을 확인한다. 판정 API의 권한은 수신자 목록 또는 마스터 관리자 역할로 정하며, 근거 열람을 별도로 요구하지 않는다. 두 판정을 같게 할지는 고도화 목록에 남긴다. 반복할 때 근거가 마지막 자료로 바뀌어 이전 사람의 항목이 숨겨질 수 있는 제한도 남아 있다.

알림의 판정은 함께 공유한다. 한 사람이 「해결됨」 등으로 판정하면 그 알림의 열린 항목은 모두 닫힌다. 해결된 충돌이 다시 관찰되면 이번 발생의 수신자에게 항목을 만든다. 서버 시작 후 복구는 합쳐진 수신자 전원의 빠진 항목을 채우므로 두 시점의 대상에 차이가 있다. 개인별 읽음 상태를 추가한 것은 아니다.

## 기존 설치 업데이트

전제조건은 적용 전 DB 백업과 시험판 승인이다. 운영 DB에 먼저 적용하지 않는다.

1. 백업을 별도 PostgreSQL에 복원하고 이 판의 서버로 시작한다.
2. Flyway가 V16 인덱스를 적용하고, 서버의 시작 후 복구가 기존 열린 알림에서 빠진 수신자의 항목을 채운다. 기존 항목 ID와 기다리기 시작한 시각은 유지한다.
3. 서버를 다시 시작해도 각 사람의 열린 항목은 하나다. 판정이 끝난 알림은 다시 열지 않는다.
4. `./gradlew test --tests '*NoticeRecipientsTests' --tests '*SessionServiceTests' --tests '*MasterCheckTests'`로 두 사람의 전달·반복·판정·재발과 기존 항목 복구를 확인한다. 후속 시험에는 공용 계정의 두 번째 수신자 판정과 문서 소유자 변경 후 재발 판정이 포함된다.
5. 실패하면 운영 적용을 멈추고 원인을 수정한다. V16을 적용한 DB에 이전 서버를 연결하지 않는다. 이전 SQL의 `on conflict` 조건이 새 인덱스와 다르므로, 되돌릴 때는 적용 전 DB 백업과 이전 서버 판을 함께 사용한다.
