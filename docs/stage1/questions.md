# 질문과 재협의 — 작업에 질문을 남기고 답을 받아 이어 가기

1단계 필수 기능 FN-0210이다. 작업을 하다 판단이 필요하면 질문을 남긴다. 질문은 원문 책임자(작업 책임자, 이어진 문서의 소유자, 승인자)에게 가고, 답이 올 때까지 작업에 「질문 답 대기」가 붙는다. 받는 사람은 첫 화면 「나를 기다리는 것」의 2번 묶음에서 답한다. 답에는 그 때문에 바뀐 문서판·결정·승인의 번호를 이을 수 있다. AI 실행이 물은 것이면 답한 뒤 「이어서 맡기기」로 답을 다음 실행의 지시에 넣는다. 기한이 지나도 답이나 승인으로 치지 않고 다시 알린다. 근거는 협업 계약 v1의 「질문과 과금 신호」, 「작업 > 대기 사유」, 「실행 권리 청구」 1-2와 질문 경로 설계(설계 허브 zm-docs)다.

- **대상**: 셋째 묶음([handoff.md](handoff.md))과 사람 검토 고르기([human-review.md](human-review.md))를 설치한 소유자 PC 한 대. 서버는 이 PC의 `127.0.0.1`에서만 받는다.
- **소유자**: 저장소 소유자. 마지막 확인 2026-10-14.
- **전제**: 서버와 웹을 이 판으로 함께 바꾼다. 연결 프로그램은 바꿀 것이 없다.

## 무엇이 어디에 뜨는가

| 무엇 | 어디 |
|---|---|
| 작업의 질문 목록과 「질문 남기기」 | 작업 상세의 「질문」(「다음 단계」 아래, 「AI에게 맡기기」 위) |
| AI 실행이 물은 것을 질문으로 남기기 | 작업 상세 「실행 기록」에서 끝난 실행의 「질문으로 남기기」 |
| 나에게 온 질문과 답하기 | 첫 화면 2번 묶음 「멈춘 AI의 질문」. 막는 질문은 바로 알리고, 막지 않는 질문은 묶어 알린다 |
| 기한이 지난 질문 | 같은 2번 묶음에 「기한 지남: …」으로 다시 올라오고 바로 알린다 |
| 답이 다음 실행에 들어간 것 | 작업 상세 「질문」의 「같은 세션을 이어 답을 넣었다」·「새 세션의 지시에 답을 넣었다」, 실행 기록의 「이어서: 질문의 답이 왔다」 |

## 전제조건

- 질문을 남길 작업이 「완료」·「취소」가 아니고, 정본이 Git 파일인 복사본이 아니다. 그런 작업에서는 「질문 남기기」가 잠기고 이유가 보인다.

## 단계

### 1. 질문을 남긴다

1. 작업 상세의 「질문」에서 「질문 남기기」를 누른다.
2. 질문을 쓰고 종류를 고른다. 종류에 따라 받는 사람이 정해지고 폼 아래에 보인다.

| 종류 | 받는 사람 |
|---|---|
| 해석 | 원문 책임자: 그 작업에 이어진 문서의 소유자, 없으면 작업 책임자 |
| 실행 문제, 사실 확인 | 작업 책임자 |
| 정책 예외, 승인 요청 | 승인자(1단계는 소유자). AI에게는 보내지 않는다 |

3. 「답이 있어야 다음으로 간다」를 두면 막는 질문(바로 알림), 끄면 막지 않는 질문(묶어 알림)이다.
4. 「질문 보내기」를 누르면 작업에 「질문 답 대기」가 붙고, 받는 사람의 첫 화면 2번 묶음에 항목이 생긴다. 기한은 24시간 뒤다.

### 2. AI 실행이 물은 것을 질문으로 남긴다

Claude Code는 화면 없이 돌 때 구조화된 질문을 내지 않는다. 그래서 1단계에서는 사람이 실행 결과를 보고 질문으로 옮긴다.

1. 작업 상세 「실행 기록」에서 끝난 실행의 마지막 답(「AI에게 넘긴 지시」 위의 활동, 또는 연결 프로그램 창)을 읽는다. 행동 규범에 따라 AI는 물을 수 없으면 가정 목록을 답에 적는다.
2. 그 실행의 「질문으로 남기기」를 누른다. 가장 최근 실행이면 마지막 답이 칸에 미리 들어가 있다. AI가 물은 것만 남게 고친다.
3. 「질문으로 남기기」를 누른다. 질문은 그 실행에 묶이고, 묻는 쪽은 그 실행의 AI(매니저)로 남는다. 결과 검토에 있던 그 실행의 결과는 작업이 「수행」으로 돌아간다(실행이 묻느라 멈춘 것이므로).

### 3. 첫 화면에서 답한다

1. 「나를 기다리는 것」 2번 묶음에서 질문을 고른다. 상세에 질문, 종류, 막는지, 기한, 왜 나에게 왔는지, 작업, 전달 이력이 보인다.
2. 답을 쓴다. 답 때문에 요구·정책·계약 문서를 바꿔야 하면 「이 답 때문에 … 바꿔야 한다」를 둔다.
3. 그 답으로 생긴 기록이 있으면 「이어진 기록 번호」에 문서판(`dvr_…`)이나 문서(`doc_…`), 결정(`dcs_…`), 승인(`apv_…`)을 적는다. 없는 번호는 서버가 거절한다.
4. 「답 보내기」를 누른다. 항목이 목록에서 빠지고 목록 위에 결과 한 줄과 「작업 열기」가 남는다. 그 작업에 답을 기다리는 질문이 더 없으면 「질문 답 대기」가 떨어진다.

답이 하는 일:

| 질문 | 답한 뒤 상태 | 다음 |
|---|---|---|
| 사람이 남긴 질문 | 해결 | 없음 |
| AI 실행의 질문 | 답함, 다음 실행에 넣기 전 | 4단계 |
| 「문서를 바꿔야 한다」를 둔 답 | 답함, 문서 반영 대기 | 작업 상세 「질문」에서 바꾼 문서판 번호를 적고 「문서 반영 기록」. 그 뒤 위 두 줄처럼 간다 |

필요 없어진 질문은 상세의 「질문 거두기」로 닫는다.

### 4. 답을 넣어 이어서 맡긴다(AI 실행의 질문)

1. 작업 상세 「AI에게 맡기기」의 단추가 「답을 넣어 이어서 맡기기」가 되고, 폼에 「답이 온 질문 N개가 이 실행의 지시에 들어간다」가 보인다.
2. 맡기면 새 실행의 이어 가는 이유가 「질문의 답이 왔다」(`answer_arrived`)이고, 지시에 「이전 실행이 남긴 질문과 사람의 답」이 들어간다.
3. 새 실행의 실행기가 시작하면 질문이 「해결」이 된다. 같은 PC에서 이전 세션을 이어 썼으면 「같은 세션을 이어 답을 넣었다」, 아니면 「새 세션의 지시에 답을 넣었다」로 남는다.

## 기한이 지나면

1. 기한(처음 24시간)이 지나도 질문은 「답변 대기」 그대로다. 답이나 승인을 만들어 내지 않는다.
2. 서버가 1분마다 보고, 기한이 지난 질문은 첫 화면 항목을 「기한 지남: …」으로 새로 올리고 바로 알린다. 다시 알림 횟수가 행과 상세에 보인다.
3. 1단계에는 대리자·상위 책임자가 없어 같은 사람에게 다시 알린다. 전달 이력에 「기한 지남」이 남고 다음 기한은 그때부터 24시간 뒤다.

## 완료 확인

- 질문을 남기면 작업 상세의 대기 사유에 「질문 답 대기」, 첫 화면 2번 묶음에 항목이 있다.
- 답하면 항목이 빠지고, 작업 상세 「질문」에 답과 이어진 기록 번호가 보이고, 이력에 「질문에 답함 — …」이 있다.
- AI 실행의 질문은 이어서 맡긴 뒤 실행 기록에 「이어서: 질문의 답이 왔다」, 「AI에게 넘긴 지시」에 질문과 답이 있고, 질문이 「해결」이다.

## 실패하면

| 증상 | 원인과 대응 |
|---|---|
| 「질문 남기기」가 잠기고 「… 질문을 남기지 않는다」 | 완료·취소된 작업이다. 이어서 할 일이면 새 작업으로 만든다. 조직이 결과 검토를 건너뛰면 결과를 낸 작업이 바로 완료되므로, AI 실행의 질문을 남기려면 작업 화면의 「검토 단계 건너뜀」에서 결과 검토를 켜 둔다 |
| 「질문으로 남기기」가 안 보인다 | 실행이 아직 끝나지 않았거나, 작업이 질문을 받지 않는 상태다(위 줄) |
| 「the work item changed」로 거절 | 다른 화면에서 작업이 바뀌었다. 작업 상세를 다시 읽고 남긴다 |
| 답이 「… does not exist」로 거절 | 이어진 기록 번호가 없다. 번호를 고치거나 비운다 |
| 이어서 맡겼는데 질문이 「답함」에 머문다 | 새 실행의 실행기가 아직 시작하지 않았다. 연결 프로그램이 떠 있는지 본다 |
| 세션 토큰으로 질문·답을 보내려다 403 | 사람의 일이라 세션 토큰으로 할 수 없다(감사 기록 `person_action.refused`) |

## 이 판이 하지 않는 것

- 실행기가 실행 중에 직접 묻는 길(zm-baton 질문 도구 `ask_question`, MCP). 질문 경로 설계의 기본 방식이지만 실행기에 도구를 하나 더 붙여야 해 다음 판으로 미룬다
- 실행기의 승인 멈춤(`permission_denied`)을 질문으로 바꾸기, 시작 전 준비 검사에서 질문 만들기
- 결과 답의 글에서 질문을 저절로 꺼내기. 행동 규범과 질문 경로 설계에 그런 규칙이 없고, 행동 규범을 바꾸는 것은 정책 문서 변경이라 넣지 않았다
- 답이 오면 서버가 저절로 다음 실행을 띄우기. 지금은 사람이 「이어서 맡기기」를 누른다
- 실행 중 입력으로 답 넣기(`live_input`), AI가 다른 AI의 질문에 답하기(2단계), 대리자·상위 책임자에게 넘기기(팀원이 생긴 뒤)
- 문서 반영 전에 재개를 막는 조직 설정. 지금은 막지 않는다

## 알아 둘 점

- **질문 상태**: 답변 대기(`awaiting_answer`) → 답함(`answered`, AI 실행의 질문이 다음 실행을 기다림) 또는 문서 반영 대기(`awaiting_doc_change`) → 해결(`resolved`, 닫힌 이유: 답 `answered`·거둠 `withdrawn`·작업 취소 `work_cancelled`).
- **대기 사유**: 「질문 답 대기」(`waiting_answer`)는 서버가 붙이고 뗀다. 답을 기다리는 질문이 하나라도 있으면 붙어 있다. 작업을 취소하면 질문이 함께 닫힌다.
- **답하는 것은 사람만**: 질문·답·문서 반영·거두기 API는 사람의 일이라 세션 토큰을 거절한다.
- **숫자(작성자가 정한 시작값)**: 기한 24시간(조직 설정 `question_due_hours`, 화면에서는 바꾸지 않는다), 확인 주기 1분, 질문·답 4,000자, 선택지 10개.
- **기록**: 질문은 내보내기에 들어간다. 감사 기록에 `question.asked`·`question.answered`·`question.overdue`·`question.delivered` 등이 남는다.
