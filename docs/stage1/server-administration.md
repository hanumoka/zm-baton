# 서버 관리자와 최초 설정 — 시험판

**목적**: 빈 설치의 관리자 설정과 계정 정지 범위를 설명한다.
**대상**: 설치 관리자·조직 소유자·시험판 검토자.
**소유자·마지막 검토**: hanumoka · 2026-10-18.
**상태**: 최종 확인 전의 구현 제안. 기존 설치에 자동 배포하지 않는다.

## 처음 시작하기

전제조건은 독립 PostgreSQL DB, 서버와 웹 빌드, `ZM_BATON_AUTH=required`다.
연결 설정과 첫 비밀번호 코드는 [인증 절차](auth.md)를 따른다.

1. 빈 DB로 서버를 시작한다. 기본 조직과 소유자가 만들어진다. 외부 문서 저장소를 가져올 필요는 없다.
2. 서버 시작 기록의 일회용 코드로 웹에서 첫 비밀번호를 정한다.
3. 로그인한 관리자가 조직 이름과 본인 이름을 입력하고 「조직 설정 마치기」를 누른다.
4. 「나」에서 「서버 관리」를 열어 조직 이름·관리자·최초 설정 시각을 확인한다.
5. 「조직」에서 구성원을 등록하고 각자의 비밀번호 설정 코드를 발급한다.

최초 설정은 DB에서 한 번만 성공한다. 두 창이 동시에 제출하면 먼저 완료한 요청만 성공한다.
설정을 마치기 전에 실패하면 같은 화면에서 다시 제출한다. 재시작해도 완료 상태는 유지된다.
비밀번호 복구는 인증 절차의 `ZM_BATON_AUTH_SETUP`을 사용한다.

## 서버 관리 권한

서버 하나에 조직 하나, 서버 관리자 한 명을 두는 임시안이다.
서버 관리자는 조직의 소유자·운영자·마스터 관리자 역할과 별도로 저장한다.
첫 관리자는 기존 조직 소유자이며 기존 사용자·조직 ID와 자료를 유지한다.

관리자는 같은 조직의 활성 구성원 중 비밀번호 설정을 마친 사람에게 서버 관리를 넘길 수 있다.
확인란에 동의하고 이전하면 이전 관리자의 서버 관리 권한은 즉시 사라진다.
조직 소유권과 업무 역할, 승인 권한, 개인 자료의 열람 범위는 바뀌지 않는다.
현재 관리자와 조직 소유자는 비활성화할 수 없다. 관리자를 바꾸려면 먼저 권한을 이전한다.

`GET /api/server`, `POST /api/server/initialize`, `PUT /api/server/administrator`는
사람인 서버 관리자만 사용한다. 쓰기 요청에는 웹 로그인과 CSRF 토큰이 필요하다.
기기·AI 세션 토큰으로는 사용할 수 없다. local 모드는 관리 정보를 읽을 수 있으나 초기 설정·이전은 하지 못한다.
기존 local 설치를 자동으로 로그인 필수 모드로 바꾸지 않는다.

관리자 정보는 업무 내보내기에서 제외한다. DB 백업·복원은 관리자 정보를 함께 보존한다.
여러 관리자, 별도 복구 도구, 조직 소유권 이전은 이번 구현에 포함되지 않는다.

## 구성원 비활성화

비활성화는 다음 항목을 폐기한다.

- 웹 로그인과 미사용 비밀번호 설정 코드
- 기기 토큰과 승인 후 아직 수령하지 않은 기기 로그인
- 등록된 AI 세션과 그 세션의 대기·응답 전달

다시 활성화해도 예전 토큰은 돌아오지 않는다. 기기는 새로 승인한다.
기존 업무와 실행 결과·작업 폴더는 삭제하지 않는다.
연결 프로그램은 다음 실행 권리 갱신 요청에서 인증 거절을 받으면 정지를 요청한다.
Windows에서는 자기가 시작한 실행기와 자식 프로세스의 종료를 확인했다. Linux는 현재 실행기 본체만 중단하며,
macOS는 명령줄 확인 방법이 없어 정지를 거절한다. Unix의 자식 프로세스 처리는 H-16에 남아 있다.
구형 연결 프로그램에는 이 처리가 없으므로 이 서버와 함께 갱신한다.
네트워크가 끊긴 원격 실행기의 즉시 종료까지 보장하지 않는다. 서버는 기존 실행 권리 만료 절차로 결과를 알 수 없는 실행을 구분한다.

기기 승인·등록·토큰 발급은 구성원 행을 먼저 잠가 비활성화와 직렬화한다.
승인 직후 아직 CLI가 수령하지 않은 요청도 비활성화 때 거절되며 다시 활성화해도 돌아오지 않는다.
기존 비밀번호 해시는 유지한다. 재활성화 뒤 같은 비밀번호로 새 로그인하는 정책은 최종 확인 대상이다.

## 확인 절차

1. 서버: `./gradlew test --tests '*ServerAdministrationTests' --tests '*LoginAdministrationTests'`.
2. 연결 프로그램: `go test ./internal/agent ./internal/api`.
3. 웹: `npm test`, `npm run build`.
4. 빈 시험 DB와 로그인 필수 서버를 준비한다. Python Playwright와 Chromium을 설치한다.
5. `BATON_PREVIEW_URL`, `BATON_SETUP_TOKEN`, `BATON_EVIDENCE_DIR`를 설정하고 `python tests/browser/server_admin.py`를 실행한다.

브라우저 시험은 최초 설정·관리자 이전·이전 관리자의 접근 거절·현재 관리자 보호를 실제 HTTP로 확인한다.
1440px·390px 화면과 결과를 증거 폴더에 남긴다. 실패하면 프로세스 종료 코드는 0이 아니다.
그 폴더에는 시험 계정 비밀번호와 로그인 상태도 있으므로 Git에 넣지 않는다. 실제 운영 DB에 이 시험을 실행하지 않는다.
